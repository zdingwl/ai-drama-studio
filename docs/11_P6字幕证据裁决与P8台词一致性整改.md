# 1. 触发问题

真实 P8 人工验收发现开场对白被显示为：

```text
徐然 · 画外对白 · 黄阿姨
```

但完整 Episode 的烧录字幕 / OCR Evidence 已识别为：

```text
王阿姨
```

这里同时暴露两个不同问题：

1. 同一 canonical utterance 跨 Shot 的 J-cut / 声音先行显示，已经由 P8 overlap continuity UI 处理；
2. canonical 正文本身仍来自 ASR 错词“黄阿姨”，而同时间 OCR 字幕给出了“王阿姨”。

第二个问题不能在 P8 修。P8 的对白正文仍必须逐字来自 CURRENT P6 canonical Evidence。

---

# 2. 权威边界

保持：

```text
完整 Episode                         = Source Truth
完整连续音轨 ASR raw Evidence         = 实际听写证据
完整视频时间轴 OCR raw / canonical    = 实际画面文字证据
P6 canonical dialogue                = Source Evidence 层的正式对白正文
P7 / P8                              = canonical Evidence 消费者
```

本次允许的是 **P6 Source Evidence 内部的显式 evidence adjudication**，不是让 OCR、VLM、P7 或 P8 随意覆盖 ASR。

禁止：

- 在 P8 前端把“黄”硬替换成“王”；
- 在 P8 Provider 增加 dialogue rewrite 通道；
- 写“王阿姨”、本 Episode 时间戳或已知错词的专用词表；
- 只要 OCR 和 ASR 不同就采用 OCR；
- 用 P7/P8/VLM 生成文本修正 P6；
- 修改或删除 raw ASR Evidence；
- 不记录依据地静默改变 canonical text；
- 进入 P9。

# 4. 自动裁决条件

只有同时满足以下条件，OCR 才允许成为某条 canonical utterance 的正式正文来源：

1. OCR span 与 ASR utterance 在时间上真实重叠；
2. OCR confidence 达到高置信阈值；
3. 规范化后文本长度接近，且字符编辑距离属于“小范围近似冲突”，而不是语义重写；
4. OCR bbox 位于可合理视为字幕的画面区域；
5. 同一 utterance 不能出现两个互相冲突、同等级的 OCR candidate；若存在歧义则不自动替换；
6. exact match 只作为 corroboration，不产生“校正”；
7. 所有条件和阈值均为通用规则，不得引用真实样例文字。

首版保守阈值：

```text
OCR confidence >= 0.85
bbox center_y >= 0.55 * frame_height
normalized length >= 2
length difference <= 2
edit distance <= max(1, floor(max_length / 3))
```

如果有多个不同 eligible OCR 文本，P6 保留 ASR canonical text 并标记 conflict，不自动决定。

# 5. Typed read contract 与 provenance

数据库 raw Evidence 不需要删除或覆盖。

`SourceDialogueUtterance.text` 仍是下游唯一 canonical 正文，但 P6 read model 增加可审计字段：

```text
DialogueUtteranceRead
├─ text                    # 最终 canonical text
├─ text_source             # ASR | OCR_SUBTITLE_ADJUDICATED
├─ asr_text                # 原 canonical ASR 文本
├─ ocr_text                # 被采用的 OCR 文本，可空
├─ ocr_span_numbers[]      # 支持该裁决的 OCR canonical span 编号
├─ adjudication_policy     # ocr-subtitle-near-match-v1，可空
└─ adjudication_reason     # 可空
```

raw `AsrEvidenceSegment.provenance_json` 对参与裁决的 source segments 记录：

```text
canonical_text_source
canonical_asr_text
canonical_text
canonical_ocr_text
canonical_ocr_span_numbers
canonical_adjudication_policy
canonical_adjudication_edit_distance
canonical_adjudication_reason
```

因此可以随时证明：

```text
ASR 原文是什么
OCR 看到了什么
为什么 canonical 最终采用 OCR
```

这不是 silent rewrite。

# 9. 自动测试

至少覆盖：

- 高置信、同时间、字幕区域、近似 OCR 能修正 ASR canonical；
- raw ASR text 保持原样；
- provenance 明确记录裁决；
- exact OCR 只 corroborate，不产生 rewrite；
- 低置信 OCR 不覆盖；
- 非字幕区域 OCR 不覆盖；
- 时间不重叠 OCR 不覆盖；
- 明显大幅不同 OCR 不覆盖；
- 多个互相冲突 eligible candidate 不覆盖；
- P8 仍逐字复制新 P6 canonical，不拥有 rewrite 权限；
- migration 0015 正确使旧 P6/P7/P8 STALE；
- GET 仍只读。
