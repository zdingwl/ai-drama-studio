# 1. 阶段完成的统一标准

每个阶段统一区分：

```text
1. 代码完成
2. 自动测试完成
3. 人工可验收
4. 涉及真实 Provider 时：真实模型 / 真实素材验收
```

工程验收入口不等于最终普通用户主流程。

普通用户按业务结果工作；P5/P6/P7/P8 都属于“原片理解”业务阶段内部工程切片。

GET / 页面刷新必须只读；重任务只能显式 POST / Command 启动。

# 2. API Key 验收规则

硬规则：

```text
API Key 不得写入 DB
不得写入 Artifact
不得写入 ProviderJob
不得写入 provenance
不得写入日志
不得提交 Git
```

本项目当前以本地工作站方式运行，开发 / 验收界面允许读取和编辑本机运行时 API Key，但 UI 必须：

```text
默认 password 遮罩
→ 用户显式点击“显示”才回显明文
→ 保存到被 .gitignore 排除的 backend/.env
```

遮罩仅是展示层保护，不能把掩码字符保存成真实 Key。

# 6. P7 整集多模态理解 ✅

最终人工验收已完成，详细记录见 `docs/07_P7最终验收与ProviderReadiness.md`。

## 6.1 固定输入契约

```text
完整 immutable Episode
+
CURRENT Source Evidence
+
可选 CURRENT Shot Anchors
```

其中：

- 完整 Episode 是 Source Truth；
- Provider 必须接收完整 Episode；
- P6 canonical dialogue / OCR 是文字事实源；
- Shot Anchors 只是时间定位提示；
- semantic windows 不得冒充 Shot Boundary；
- 模型不得重新听写并覆盖 canonical dialogue。

## 6.2 正式契约

```text
source-video-understanding@1.1.0
p7-source-bible-v2
SOURCE_BIBLE schema 1.1
grounded-source-truth-v2
```

Grounding：

```text
FACT
INFERENCE
UNKNOWN
```

验收硬规则：

- FACT / INFERENCE 必须有 CURRENT Evidence 或完整 Episode video range；
- UNKNOWN 不能携带 support，也不能和确定性 Source Fact 同时发布；
- world_rules 只允许本作品内部 FACT；
- 道具 appearance 与 story_function 分离；
- hallucinated Evidence ID / 越界时间 / 无效人物引用 fail closed；
- Provider + Service publication 双层校验；
- P6 canonical Evidence 始终不可被 P7 覆盖。

## 6.3 SOURCE_BIBLE 用户结果

至少可读：

```text
素材基线
整体分析
时间化原作剧情
人物 / 关系
场景
关键道具
Story / 关键事件
Story Skeleton
Rhythm Skeleton
revision / provenance
```

Evidence 默认可折叠，但必须能按需反查 P6 canonical 正文。

人工编辑必须产生新 revision，并使旧 SOURCE_BIBLE / Story / Rhythm STALE；P6 Evidence 不变。

## 6.6 Provider / Runtime STALE

以下变化必须使对应 SOURCE_BIBLE / Story / Rhythm STALE：

- Project 模型切换；
- Model ID；
- Base URL；
- Doubao Video FPS；
- Professional Skill / Prompt / Schema / Grounding Contract 改变。

以下变化不应单独造成业务结果 STALE：

- API Key；
- Request Timeout。

配置变化本身不得自动执行模型。
