# 1. 阶段完成的统一标准

每个阶段统一区分：

```text
1. 代码完成
2. 自动测试完成
3. 人工可验收
4. 涉及真实 Provider 时：真实模型 / 真实素材验收
```

工程验收入口不等于最终普通用户主流程。

普通用户按业务结果工作；P5/P6/P7/P8/P9 都属于“原片理解”业务阶段内部工程切片。

GET / 页面刷新必须只读；重任务只能显式 POST / Command 启动。

---

# 2. API Key 验收规则

硬规则：

```text
API Key 不得写入 DB
不得写入 Artifact
不得写入 ProviderJob
不得写入 provenance
不得写入日志
不得提交 Git
```

本项目当前以本地工作站方式运行，开发 / 验收界面允许读取和编辑本机运行时 API Key，但 UI 必须默认 password 遮罩；只有用户显式点击“显示”才回显明文，并且本机值只能保存到被 `.gitignore` 排除的 `backend/.env`。

# 5. P6 Source Evidence ✅

真实执行必须是：

```text
完整 Episode 连续音轨 → ASR
完整 Episode 视频时间轴 → OCR
```

禁止每个 Reference Clip 分别 ASR 后拼接。

人工检查至少包括：

- 对白正文与真实语音一致；
- 起止时间合理；
- 跨 Shot 一句话仍是一条 canonical utterance；
- Shot projection 只做 1:N 时间投影，不复制 / 改写正文；
- OCR 与画面文字对应；
- raw ASR/OCR 保留；
- 自动 OCR subtitle near-match 裁决可追溯；
- 用户显式人工裁决产生新 revision；
- Source / canonical revision 变化后下游正确 STALE；
- P7/P8/VLM 无权静默覆盖 canonical Evidence。

当前基线：

```text
p6-source-evidence-v4
segment-preserving-dialogue-v4
adjacent-duplicate-microsegment-v1
ocr-subtitle-near-match-v1
human-dialogue-adjudication-v1
```

# 8. P9 Speaker / Character / Scene / Prop 最终归一 ▶ 下一阶段

P9 的人工验收规范必须在实现前先设计。

P9 硬输入至少包括：

```text
CURRENT SOURCE_VIDEO / 完整 Episode
CURRENT SOURCE_BIBLE
CURRENT SOURCE_SHOT_FACTS
CURRENT SHOT_ANCHORS
需要核对时读取 CURRENT canonical Source Evidence
```

P9 不能把 P8 provisional candidate 直接当最终 identity，必须利用跨 Shot / 全集上下文和必要 Evidence 做稳定归一。

至少要验收：

- Character identity 合并 / 拆分正确；
- Speaker ↔ Character attribution 有证据且允许 UNKNOWN；
- Scene 同一地点跨 Shot 可稳定归一，同名不同地点不误合并；
- Prop 同一关键道具跨 Shot 可稳定归一，相似外观不同道具不误合并；
- typed Artifact / revision / fingerprint / provenance / Artifact Graph 完整；
- 上游变化后正确 STALE；
- GET 只读；
- 外部 Provider 先持久化 ProviderJob；
- 人工确认 / 修改必须产生新 revision；
- 真实短剧人工验收通过。
