# AI Drama Studio V3 阶段人工验收规范

> 日期：2026-09-08  
> 目的：保证每一个开发阶段不仅“代码完成、自动测试通过”，还必须让项目使用者能够亲自在产品里验收该阶段的真实行为。

---

# 1. 阶段完成必须同时满足三层

以后每个 P 阶段统一区分：

```text
1. 代码完成
2. 自动测试完成
3. 人工可验收
```

任何阶段如果只有前两项，没有用户可以操作的验收入口或清晰的人工验收方法，不应视为完整收口。

真实模型相关阶段另外增加：

```text
4. 真实模型 / 真实素材验收
```

不能把 mock、单元测试或“代码已接入”写成真实模型验收通过。

---

# 2. 人工验收入口原则

人工验收必须满足：

- 用户可以从前端页面或明确的开发验收入口主动启动；
- GET / 页面刷新仍然只读，不能因为打开页面偷偷执行任务；
- 测试动作必须由显式 POST / Command 触发；
- 页面要展示普通用户能理解的结果，不要求用户阅读数据库、日志、fingerprint 或 ProviderJob 内部字段；
- 基础设施阶段允许使用本地 mock，但必须明确“不会调用真实模型、不产生费用”；
- mock 只能验证当前阶段的机制，禁止借验收工具提前开发后续阶段；
- 后续真实业务阶段优先直接使用真实输入素材进行人工验收。

---

# 3. P4 人工验收

P4 的业务能力是 Task / ProviderJob / Guardrail，本阶段没有 Shot Boundary、ASR、OCR、Step 3.7 Flash 或 MiniMax H3，因此人工验收使用本地模拟任务，不调用真实模型。

项目工作区新增：

```text
开发验收工具
→ P4 任务执行机制
```

提供四个测试入口：

## 3.1 测试正常完成

点击：

```text
测试正常完成
```

预期页面可以看到：

```text
排队中
→ 处理中
→ 进度持续变化
→ 已完成 100%
```

运行过程中应该出现“取消”按钮，可以人工测试 cooperative cancel。

正常验收任务内部还会运行一次本地 Provider mock。

该 mock 会在模拟 remote call 开始前用第二个数据库会话检查 ProviderJob 是否已经可见；如果 ProviderJob 没有先 commit，任务必须失败。

这用于人工入口配合自动测试共同验证：

```text
先持久化 ProviderJob
→ DB commit
→ 才允许 Provider 调用
```

不会产生任何真实模型费用。

## 3.2 测试失败 → 重试

点击：

```text
测试失败 → 重试
```

第一次执行预期：

```text
进度到 40%
→ 状态变成“失败”
→ 显示失败原因
→ 出现“重试”按钮
```

点击“重试”后预期：

```text
重新排队
→ 再次执行
→ attempt 增加
→ 最终完成 100%
```

用于人工验收有限重试和失败状态边界。

## 3.3 测试中断 → 继续

点击：

```text
测试中断 → 继续
```

第一次执行预期：

```text
进度到 55%
→ 保存 checkpoint
→ 状态变成“已中断”
→ 出现“继续”按钮
```

点击“继续”后预期：

```text
保留原检查点
→ 重新排队
→ 从已有进度继续
→ 最终完成 100%
```

用于人工验收 checkpoint / resume。

## 3.4 测试防重复提交

点击：

```text
测试防重复提交
```

该入口使用独立 `dedupe` 验收场景，任务名称固定显示：

```text
P4 验收：防重复提交
```

前端先读取测试前任务列表，然后用同一个 Idempotency-Key 并发发出两次完全相同的 `dedupe` Command，最后再次读取任务列表。

只有同时满足以下两个条件才允许显示“通过”：

```text
两次 POST 返回同一个 Task ID
+
本次测试前后任务总数只增加 1
```

预期页面明确显示：

```text
重复提交保护：通过。本次两次相同提交只新增了 1 个“防重复提交”任务。
```

如果新增任务数量不是 1，必须显示红色“未通过”，不能仅凭两个响应表面相同就显示成功。

这样即使此前已经运行过“测试正常完成”，也不会再把正常任务与防重复提交任务混成同一个名称。

---

# 4. P4 页面验收边界

普通任务卡仍然只展示：

```text
任务名称
状态
进度
失败原因
重试
继续
取消
```

不展示：

```text
ProviderJob
payload fingerprint
checkpoint JSON
API Key
Authorization
worker id
内部 provider / model 技术字段
```

P4 验收工具和 Task 区域必须独立于 ProjectExecutionPlan 展示；即使当前 Plan 尚未生成，也可以单独人工验收 P4。

---

# 5. 后续阶段要求

从 P5 开始，每个阶段在开发前就必须同时规划“用户怎么验收”。

例如 P5 视频技术预处理至少应允许用户：

```text
选择 / 使用已上传 Episode
→ 显式启动视频技术预处理
→ 查看镜头边界结果
→ 查看每个 Shot 的时间范围
→ 查看 thumbnail
→ 打开 / 播放 Reference Clip
→ 对明显错误边界进行后续阶段规定范围内的人工处理
```

P6 必须能够让用户用真实音视频检查 ASR / OCR / Source Dialogue 结果。

P7 进入真实整集理解模型后，必须增加真实 Episode 的模型验收，不能只靠 mock 或结构化输出单测。

后续所有阶段均按本规范执行。
