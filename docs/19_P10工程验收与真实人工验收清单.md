# 9. 真实 STALE / 新 revision 验收

这是 P10 最关键的真实状态传播验收。

## 9.1 安全创建一个上游新 revision

禁止为了验收而错误 MERGE/SPLIT 正确人物、场景或道具。

使用 P9 已有、已经真实验证过的 Speaker 人工裁决路径，对一个当前正确 Speaker 做**语义不变的 `CONFIRM`**：

```text
POST /api/v3/projects/{project_id}/source-resolution/SPEAKER/commands/adjudicate
```

要求：

- `expected_revision` 使用定稿前 CURRENT Speaker revision；
- `operation = CONFIRM`；
- 选择当前已经正确的 Speaker identity/reference；
- 不改变 display_name / Character link / utterance partition 的真实含义；
- reason 明确写成 P10 STALE 人工验收，例如“P10 Snapshot STALE 验收：确认当前正确 Speaker 归因，不改变 Source Truth”。

这一步允许生成新的 `SOURCE_SPEAKERS` revision，因为它是合法显式 P9 adjudication；旧 P9 revision 必须保留。

## 9.2 旧 Snapshot 必须自动 STALE

新 `SOURCE_SPEAKERS` 成为 CURRENT 后，**不要先重新定稿**，先刷新 P10。

预期：

```text
旧 SOURCE_VIDEO_SNAPSHOT = STALE
旧 Snapshot revision 仍可在历史中看到
当前不应存在仍冒充 CURRENT 的旧 Snapshot
```

验收记录：

```text
新 SOURCE_SPEAKERS revision = ______
[ ] 旧 Snapshot 自动变 STALE
[ ] 旧 Snapshot 内容仍可读/可追溯
[ ] 没有反向改写旧 Snapshot 或旧 P9 revision
```

## 9.3 显式重新定稿

此时再次点击“原片分析定稿”。

预期：

```text
新 Snapshot = CURRENT
revision = 旧 Snapshot revision + 1
旧 Snapshot = STALE
新 Snapshot --SUPERSEDES--> 旧 Snapshot
新 frozen SOURCE_SPEAKERS = 刚刚生成的 CURRENT Speaker revision
```

其余没有变化的 P5/P6/P7/P8/P9 artifact references 应继续保持原值。

验收记录：

```text
旧 Snapshot revision = ______
新 Snapshot revision = ______
[ ] 新 revision = 旧 revision + 1
[ ] 新 Snapshot CURRENT
[ ] 旧 Snapshot STALE 且保留
```
