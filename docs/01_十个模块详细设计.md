# 十个模块详细设计

> 这份文档是《00_短剧重做系统开发总纲》的下一层。
>
> 这里只细化每个模块的**输入、自动处理、人工确认、正式输出、完成条件和下游用途**。数据库字段、接口和任务编排继续放在《02_工作流V2技术实现规范.md》。

---

## 模块 1：创建项目

### 要解决什么

告诉系统：处理哪部短剧，要做成什么语言、什么地区的版本。

### 输入

- 项目名称；
- 源语言；
- 目标语言；
- 目标地区；
- 场景策略：AUTO / KEEP / LOCALIZE；
- 一个或多个 Episode 视频；
- Episode 名称和顺序。

### 自动处理

- 验证文件存在且可读取；
- FFprobe 获取时长、分辨率、帧率、音视频流；
- 保存 Episode 顺序；
- 记录原媒体版本；
- 判断项目规则修改会影响哪些后续数据。

### 需要人工确认

只有用户主动修改项目规则或 Episode 顺序时需要确认；保存配置本身不能自动启动后面的重任务。

### 正式输出

- ProjectSpec；
- EpisodeSource；
- 项目规则版本；
- 源媒体版本信息。

### 完成条件

- 至少有一个有效 Episode；
- 目标语言和目标地区已配置；
- 视频可读取、可解码；
- Episode 顺序明确。

### 下游用途

模块 2 开始对 Episode 做视频预处理和镜头拆分。

---

## 模块 2：拆分原片

### 要解决什么

把整集视频变成后面可以分析、参考和重新生成的镜头单位。

### 输入

- EpisodeSource；
- 原始音视频；
- 当前项目媒体版本。

### 自动处理

- 建立准确时间基准；
- 检测镜头边界；
- 保存每个 Shot 的开始/结束时间；
- 生成缩略图；
- 生成 Reference Clip；
- 保存必要的视频技术参数。

### 需要人工确认

只有镜头边界确实不确定、误切或漏切时，进入 Review Center 做 Shot Boundary 修正。

### 正式输出

- Shot；
- ShotRevision；
- Reference Clip；
- 源时间信息；
- 视频技术信息。

### 完成条件

- 所有 Shot 起止时间合法、有序；
- Reference Clip 可读取和解码；
- 当前 ShotRevision 对应当前源视频。

### 下游用途

模块 3 按 Shot 和上下文分析原片内容；模块 8、9 也会使用 Reference Clip 作为原镜头参考。

---

## 模块 3：看懂原片

### 要解决什么

不是只把视频切开，而是真正回答：**这一场和这个镜头里发生了什么？**

### 输入

- Shot；
- Reference Clip；
- 原片音轨；
- 前后镜头和 Episode 上下文。

### 自动处理

可由 ASR、OCR、Qwen3-VL、Tracking、Scene Timeline 等技术共同提供证据，最后整合为业务可用的镜头事实：

- 剧情摘要；
- 场景语义；
- 画面里有哪些人物；
- 人物动作；
- 表演和情绪；
- 人物站位和互动；
- 景别、构图、机位、运镜；
- 完整源对白；
- 每条对白在 Shot 中的投影位置；
- 画面文字；
- 道具；
- Reference Clip 对应关系。

### 对白必须怎么处理

一条完整对白可能跨多个 Shot。

正确结构是：

```text
1 条完整源对白
  ↓
保存一次完整文本和完整起止时间
  ↓
投影到 1 个或多个 Shot
```

不能因为一条对白跨 3 个 Shot，就复制成 3 条互相独立的业务对白。

### 需要人工确认

- 镜头边界问题回模块 2；
- 模型离线或 Worker 不可用属于运行环境问题，不进入人工内容审核；
- 单纯模型格式错误应有限自动重试。

### 正式输出

- Shot Facts；
- Scene Timeline；
- Source Dialogue Utterance；
- Shot Dialogue Projection；
- 人物轨迹/临时人物证据；
- 动作、表演、镜头、OCR、道具等证据。

### 完成条件

- Shot 事实可追溯到来源；
- 完整对白有稳定 ID；
- 跨 Shot 投影仍指向同一条完整对白；
- 这里只描述原片，不能混入 TargetCharacter、目标台词等下游数据。

### 下游用途

模块 4 使用这些证据把“看到的人/场景/道具”整理成正式业务资产。

---

## 模块 4：整理原片人物和场景

### 要解决什么

AI 在每个镜头里都可能看到“一个女人”“一个男人”。这一模块要把这些观察统一成正式人物，并确认镜头里到底是谁、谁在说话。

### 输入

- 模块 3 的人物轨迹和视觉证据；
- Character V10.1；
- Scene / Prop 证据；
- 完整源对白；
- Shot 事实。

### 自动处理

人物：

```text
Detection / Face / Track
→ 人物证据
→ Identity 归并
→ Final Character
```

场景和道具：

```text
Scene / Prop evidence
→ 归并和确认
→ Final Scene / Final Prop
```

并建立：

- Shot → Final Character；
- Shot → Final Scene；
- Shot → Final Prop；
- 完整 Dialogue → Speaker → Final Character / 画外音。

### 需要人工确认

当系统不能安全判断人物身份、说话人或资产绑定时，只创建**根问题**。

例如一个未确认人物影响 18 个 Shot、63 个对白投影，只让用户确认“这个人物是谁”一次，下游显示“被上游阻塞”，不能生成 63 个重复人工任务。

### 正式输出

- Final Character；
- Final Scene；
- Final Prop；
- Shot Asset Binding；
- Dialogue Speaker Binding。

### 完成条件

- 所有重要人物和说话人物都有正式身份，或明确标记为背景/画外/非角色；
- 同一完整对白的多个 Shot 投影不能出现不同说话人；
- Scene / Prop / Shot 关系有效；
- Character V10.1 的安全身份门槛不能为了减少人工任务而降低。

### 下游用途

模块 5 把已经确认的原片事实编译成 SourceDramaSnapshot。

## 模块 5：固化原片事实

### 要解决什么

前面有 ASR、OCR、VLM、人物轨迹、Scene 等很多内部结果。后面的目标版本不能再到处拼这些临时数据，需要一份唯一可信的正式原片资料。

### 输入

- Episode / Scene / Shot；
- Reference Clip；
- 完整源对白和 Shot 投影；
- Final Character / Scene / Prop；
- 人物和说话人绑定；
- 动作、表演、镜头和场景事实；
- 对应的数据版本。

### 自动处理

- 编译 SourceDramaSnapshot；
- 记录数据来源和版本；
- 只读校验快照是否完整；
- 判断是否存在阻塞性源事实问题。

### 需要人工确认

人工不直接编辑“快照里的临时字段”。如果发现问题，应回到模块 2、3、4 修改正式源事实，再重新形成当前快照。

### 正式输出

**SourceDramaSnapshot**：后续所有目标设计、翻译、时间轴和生成的唯一源事实输入。

### 完成条件

- Snapshot 对应当前上游版本；
- 必需人物、场景、说话人关系可用；
- 没有阻塞性的源事实 Review Case；
- 下游不需要绕过 Snapshot 去读零散 ASR/OCR/Fusion 临时结果。

### 下游用途

模块 6—10 都以当前 SourceDramaSnapshot 为原片事实基础。

---

## 模块 6：设计目标版本

### 要解决什么

把原片人物和场景变成目标地区版本。

### 输入

- SourceDramaSnapshot；
- 目标语言；
- 目标地区；
- 场景策略；
- Final Character；
- Final Scene。

### 自动处理

对每个需要出现的正式人物建立唯一 TargetCharacter：

- 目标姓名；
- 年龄范围；
- 外观；
- 发型；
- 服装；
- 地区风格；
- 人物参考图；
- TargetVoiceProfile。

对每个正式场景建立 SceneLocalizationMapping：

- KEEP：场景可保留；
- LOCALIZE：建立目标地区场景描述和参考；
- AUTO：系统最终仍要固化成明确决定，不能一直停留在 AUTO。

### 需要人工确认

- 目标人物创作方案冲突；
- 场景是否本土化无法安全决定；
- 目标参考明显不符合项目要求。

### 正式输出

- TargetCharacter；
- TargetVoiceProfile；
- SceneLocalizationMapping；
- Target Scene 描述/参考资产。

### 完成条件

- 每个必需 Final Character 都有唯一当前 TargetCharacter；
- 每个目标人物有声音方案；
- 每个场景有明确 KEEP / LOCALIZE 结果；
- 结果对应当前 SourceDramaSnapshot。

### 下游用途

模块 7 使用目标人物和声音生成本土化对白；模块 9 使用目标人物/场景参考生成画面。

---

## 模块 7：生成目标对白和声音

### 要解决什么

把原片对白真正变成目标地区可以说、可以听、可以对口型的最终对白。

### 输入

- SourceDramaSnapshot 中的完整源对白；
- 源说话人；
- TargetCharacter；
- TargetVoiceProfile；
- 目标语言和地区；
- 场景上下文。

### 自动处理

对每一条完整对白只生成一条目标对白：

```text
完整源对白
→ 翻译
→ 本土化润色
→ 最终目标台词
→ 绑定目标说话人
→ 选择 Voice
→ TTS
→ FFprobe 读取真实语音时长
→ 保留原 Shot 投影关系
```

### 需要人工确认

- 原文存在真正的语义歧义；
- 本土化有多种会改变剧情含义的选择；
- 上游人物未确认时，回模块 4 的人物根问题，不能重复制造对白问题。

TTS 服务离线属于运行环境问题，不属于人工内容问题。

### 正式输出

- TargetDialogue；
- Target Speaker；
- SpeechAsset；
- 真实 speech duration；
- Dialogue Projection links。

### 完成条件

- 每条完整源对白最多一个当前目标版本；
- 每条需要说话的目标对白有目标人物或明确画外音策略；
- Voice 已配置；
- TTS 文件可读取；
- 真实语音时长已保存；
- Shot 投影关系没有丢失。

### 下游用途

模块 8 使用**真实语音时长**重新计算镜头时间，不能先猜时长再做 TTS。

## 模块 8：重排时间并准备生成

### 要解决什么

中文、英语、西语等说同一句话需要的时间不同。不能把目标语言硬塞进原镜头时长，因此要重新安排镜头和 H3 实际生成片段。

### 输入

- 源 Shot 时间；
- 源动作和镜头事实；
- 目标语音真实时长；
- Shot Dialogue Projection；
- 反应镜和无对白区间；
- 目标人物/场景参考。

### 自动处理

1. 比较源对白时长和目标语音时长；
2. 为每条目标对白选择安全时间策略；
3. 生成 RemakeTimeline；
4. 生成 TargetDialoguePlacement；
5. 把目标镜头重新组织成 GenerationSegment；
6. 保存跨 Segment 的音频偏移；
7. 编译 H3 需要的生成条件。

时间策略可以包括：

- KEEP：保持；
- TRIM：安全缩短空白；
- CARRY_OVER_REACTION：对白延续到反应镜；
- EXTEND：延长镜头；
- HUMAN_REVIEW：确实需要人选择。

### GenerationSegment 规则

- Shot ≠ GenerationSegment；
- H3 目标生成窗口按当前约束控制在 4—15 秒；
- 小于 4 秒的目标内容可以生成至少 4 秒后精确裁切；
- 超过 15 秒需要拆成多个 GenerationSegment；
- 跨 Segment 对白必须从正确音频偏移继续，不能每段重新从句首播放。

### 需要人工确认

只有节奏策略真正无法安全决定时进入 DIALOGUE_TIMING Review Case。

### 正式输出

- RemakeTimeline；
- TargetDialoguePlacement；
- GenerationSegment；
- Segment Audio Offset；
- H3 Context / 生成条件；
- 预计生成段数和资源信息。

### 完成条件

- 所有目标音频已准备；
- 时间轴有序、无非法重叠；
- 所有需要生成的目标镜头被当前 GenerationSegment 覆盖；
- 跨段对白偏移正确；
- 没有阻塞性的 timing 问题。

### 下游用途

模块 9 按 GenerationSegment 调用 H3，而不是机械地按原 Shot 数量调用。

## 模块 9：H3 重拍与质检

### 要解决什么

按照目标人物、目标场景、目标语音和原片导演参考重新生成视频，并保证失败的生成结果不会直接进入成片。

### 输入

- GenerationSegment；
- H3 Context；
- TargetCharacter references；
- Target Scene references；
- 无源音频的 Reference Clip；
- 目标 TTS 音频；
- 上一个需要连续性的 Selected Output。

### 自动处理

每个 GenerationSegment：

```text
准备 H3 输入
→ 创建 GenerationAttempt
→ H3 生成
→ 下载输出
→ FFprobe / 完整解码 / 时长硬检查
→ Qwen3-VL 语义 QC
→ 不通过时更换 seed + 加入具体纠正提示
→ 有限自动重试
→ 通过后创建 GenerationSelection
```

检查内容至少包括：

- 文件能否完整解码；
- 时长是否符合目标；
- 目标人物是否正确；
- 是否泄漏原演员身份；
- 场景是否符合 KEEP / LOCALIZE；
- 动作和表演是否正确；
- 构图、机位和运镜是否偏离；
- 连续镜头人物和场景是否稳定。

### 需要人工确认

- 多次语义失败；
- 多个结构有效版本自动无法安全选择；
- 用户需要在有效候选中选版。

硬解码失败、文件损坏等不能被人工“忽略后继续”。

### 正式输出

- GenerationAttempt（每一次生成历史）；
- GenerationQualityCheck；
- GenerationSelection（当前可用版本指针）；
- Selected Output。

### 完成条件

每个必需 GenerationSegment 都有当前、结构有效、通过规则的 GenerationSelection。

### 下游用途

模块 10 **只读取 GenerationSelection**，不能拿“最新一个 SUCCEEDED Attempt”冒充正式镜头。

## 模块 10：后期和成片

### 要解决什么

把通过 H3 质检的镜头变成真正可以播放、下载和交付的完整目标语言短剧。

### 输入

- GenerationSelection；
- TargetDialogue SpeechAsset；
- RemakeTimeline；
- 目标说话人；
- 字幕数据；
- 可选的安全背景音。

### 自动处理

1. 根据目标时间轴放置最终目标对白；
2. 画外对白只保留目标音频，不做无意义口型；
3. 单一可见说话人做 LatentSync；
4. 多人镜头先定位目标说话人身份，再对目标人物区域做口型；
5. 生成目标时间轴字幕；
6. 如需要，安全分离和复用非对白背景；
7. 标准化视频、音频参数；
8. 按 RemakeTimeline 拼接整集；
9. 输出 MP4 + SRT；
10. 最后由用户观看、试听并接受或驳回。

### 背景音硬规则

```text
源原始音频
→ 分离非对白背景
→ 按 SourceDramaSnapshot 的源对白窗口再次硬抑制
→ 映射到目标时间
→ 在目标对白下保守混音
```

**禁止把原片原始音频直接混进目标成片。**

背景音 Worker 不可用时，可以安全降级成“目标对白-only”版本，不应阻塞整个 Episode 交付。

### 需要人工确认

- 多脸情况下目标说话人仍不确定；
- 最终观看/试听发现台词、节奏、画面、口型、音轨或字幕问题。

最终驳回应路由到真正负责的上游模块，而不是用一个通用“忽略问题”按钮。

### 正式输出

- PostProductionSegment；
- 最终目标音轨；
- Lip-sync result；
- UTF-8 SRT；
- EpisodeOutput；
- Final MP4；
- checksum / 版本；
- 人工验收记录。

### 完成条件

- 所有必需后期分段当前且成功；
- MP4 可完整解码并带正确音轨；
- SRT 使用目标时间轴；
- 无原语言对白泄漏；
- 用户实际观看和试听后明确接受当前 EpisodeOutput。

## 人物资产工作区补充（2026-09-04）

模块 4 的人工操作入口按“人物观察 → 原片人物资产 → 分镜绑定”组织：用户查看当前拉片的场景内人物及关联镜头，可把多个观察归并到已有原片人物，或命名创建新原片人物。同镜头不同观察禁止合并；重新分配观察可修正归并，不改变 AI 原始识别内容。

模块 6 以当前 SourceDramaSnapshot 的正式人物为入口创建独立 TargetCharacter。原人物姓名和目标姓名分别保存。用户填写目标姓名、外貌/发型/服装和生成描述，然后显式生成正面、左侧、背面、右侧四视图候选。当前实现复用本地 H3 Provider 生成 8 秒转身参考并抽取四个角度；模型角度准确性和人物一致性必须人工检查。技术成功不等于选版成功，只有人工采用的当前版本作为四视图参考供后续使用。

人物归并入口改为观察列表、代表画面定位核对、归并清单。没有可靠位置的观察显示待定位，由用户框选代表画面中的具体人物并核对局部裁剪后提交；代表画面的框不能推断成其他镜头的定位。
