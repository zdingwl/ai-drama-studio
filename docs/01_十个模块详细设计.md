# 十个模块详细设计

> 本文是《00_短剧重做系统开发总纲》的下一层。
>
> 这里只规定每个模块的：**输入、自动处理、正式输出、真正阻塞条件、用户可选纠错、完成条件、下游用途。**
>
> 数据库、接口、任务、Provider、revision、fingerprint 细节见 `02_工作流V2技术实现规范.md`。

## 0. 2026-09-07 当前统一原则

从本版本开始：

1. **默认全自动。** 内容不确定不再强制人工确认。
2. **低置信度自动决策并继续。** 记录 confidence / provenance / method，普通页面不展示。
3. **真正阻塞只来自技术/结构失败。** 例如文件损坏、模型 Runtime 失败、输出 schema 损坏、必需媒体不可解码。
4. **人工入口是可选纠错，不是流程门禁。**
5. **原片必须同时产出 Source Script 和 Source Directing Reference。**
6. **Qwen3.8-27B 是主视觉/剧情理解模型；D-ORCA 8B 是 Speaker Attribution 主模型。**
7. **ASR/OCR 保留源对白原文和时间证据；剧本模型不得改写 canonical source dialogue。**
8. **Character V10.1 保留跨镜身份门槛；证据不足宁可暂时分开，不错误合并。**
9. **SourceDramaSnapshot 仍是下游唯一正式源事实入口。**
10. **GET 只读；重推理必须显式命令。**

# 模块 1：创建项目

## 要解决什么

告诉系统：处理哪部短剧，要做成哪个国家/地区、什么语言的版本。

## 输入

- 项目名称；
- 源语言；
- 目标语言；
- 目标地区；
- 场景策略：AUTO / KEEP / LOCALIZE；
- 一个或多个 Episode 视频；
- Episode 名称和顺序。

固定字段使用下拉/枚举，不允许用户随意输入不规范值。

## 自动处理

- 验证文件存在、可读取；
- FFprobe 读取时长、分辨率、帧率、音视频流；
- 保存 Episode 顺序；
- 记录媒体版本；
- 计算项目规则 fingerprint；
- 判断规则变化会使哪些下游结果 STALE。

## 真正阻塞

- 文件不存在；
- 视频无法解码；
- 项目缺少目标语言/地区等必需配置。

## 用户可选纠错

- 调整 Episode 顺序；
- 修改项目规则；
- 替换错误视频。

## 正式输出

- ProjectSpec；
- EpisodeSource；
- 项目规则 revision；
- 源媒体版本信息。

## 完成条件

- 至少一个有效 Episode；
- Episode 顺序明确；
- 必需项目配置完整；
- 媒体可读取、可解码。

## 下游用途

模块 2 建立 Shot 和 Reference Clip。

# 模块 2：拆分原片

## 要解决什么

把整集视频转换成后续理解、参考和生成都能共用的时间锚点。

## 输入

- EpisodeSource；
- 原始视频；
- 当前媒体版本。

## 自动处理

- 建立准确 source timebase；
- 检测 Shot Boundary；
- 生成 Shot 起止时间；
- 生成缩略图；
- 生成 Reference Clip；
- 保存视频技术参数；
- 边界不确定时选择当前最佳边界并保存 detector evidence。

## 关键原则

Shot 是原片导演/剪辑单位，不等于后续 Target Shot，也不等于 GenerationSegment。

## 真正阻塞

- 时间范围非法；
- Shot 重叠/倒序导致结构无法使用；
- Reference Clip 无法读取或解码。

普通“边界可能差几帧”不阻塞。

## 用户可选纠错

用户发现误切/漏切时可以手动调整边界。修改后产生新 ShotRevision，并使依赖旧边界的下游结果 STALE。

## 正式输出

- Shot；
- ShotRevision；
- Reference Clip；
- Source Timebase；
- 视频技术信息。

## 完成条件

- 所有 Shot 时间合法、有序；
- Reference Clip 可用；
- ShotRevision 对应当前源视频。

## 下游用途

模块 3 按 Shot + 跨 Shot 上下文理解原片；模块 8/9 使用 Reference Clip 作为导演参考。

# 模块 3：完整理解原片

## 要解决什么

不是只分镜，而是真正回答：

> **这一场、这个镜头里发生了什么，谁在什么时候说了什么，人物怎么演，摄影机怎么拍。**

## 输入

- Shot；
- Reference Clip；
- 原片音轨；
- 前后 Shot；
- Episode 上下文；
- Source Language。

## 主模型分工

### Qwen3.8-27B：主视觉/剧情理解

负责：

- 可见人物；
- 动作；
- 表情；
- 姿态；
- 视线；
- 人物站位和互动；
- 场景；
- 道具；
- 画面事件；
- 景别；
- 机位；
- 构图；
- 运镜基础理解；
- 光线；
- 连续性；
- Shot narrative function；
- 跨镜事件；
- 整集剧情上下文。

### D-ORCA 8B：音视频对白理解

负责：

- WHEN：对白开始/结束的音视频证据；
- WHO：说话人归属；
- WHAT：对白内容的辅助证据；
- 音频和画面中说话行为的对齐。

D-ORCA 的主要职责是 Speaker Attribution，不能因为它也能转写就覆盖已有 canonical source dialogue。

### ASR / OCR：原文和时间证据

负责：

- 保存原始 ASR；
- 保存原始 OCR / 字幕；
- 对齐时间；
- 建立 SourceDialogueUtterance 候选；
- 与 D-ORCA 的 WHAT/WHEN 做校验。

原始 ASR/OCR 永不就地改写。

## 自动对白整合

正确业务结构：

```text
ASR / OCR / D-ORCA evidence
  ↓
Source Dialogue Reconcile
  ↓
1 条完整 SourceDialogueUtterance
  ↓
N 个 ShotDialogueProjection
```

一条对白跨多个 Shot：

- 完整文本只保存一次；
- 完整时间只保存一次；
- 每个 Shot 只保存自己覆盖区间；
- 所有投影共享同一个 dialogue_group_id。

### 对白文字选择顺序

1. 有可靠 ASR：ASR 是主要 canonical text 来源；
2. 稳定字幕/OCR 与 ASR 高度一致：可用于自动纠错低置信度识别；
3. ASR/OCR 冲突：使用时间、语言、上下文、D-ORCA WHAT evidence 自动选当前最佳；
4. 证据不足：保留当前最佳 source text + uncertainty metadata，不因为内容置信度低而阻塞；
5. 完全没有语音/字幕证据时不凭空制造对白。

## 自动 Speaker Attribution

优先级：

```text
D-ORCA audio-visual speaker evidence
  ↓
已有明确 SPEAKER relation
  ↓
Character V10.1 identity normalization
  ↓
现有 rule-based speaker resolver
  ↓
自动 best-effort / OFFSCREEN / UNKNOWN
```

规则式 resolver 只做 fallback，不能继续作为主要 Speaker 来源。

## Source Directing Reference 输出

模块 3 必须保留：

- visual_description；
- action；
- performance；
- expression；
- posture；
- gaze；
- interaction；
- blocking；
- shot_type；
- camera_angle；
- composition；
- camera_motion；
- lighting；
- prop interaction；
- continuity；
- source time；
- Reference Clip。

这些信息后面不一定全部显示给用户，但必须进入正式源事实或其可追溯引用。

## 真正阻塞

- Reference Clip 无法解码；
- 需要音频但媒体音轨损坏且没有可用 fallback；
- Qwen3.8 / D-ORCA 必需任务失败且无 fallback；
- 模型输出无法通过 schema/时间范围校验；
- 生成的 utterance/projection 结构自相矛盾。

## 用户可选纠错

用户可以修改：

- 画面描述；
- 动作/表情；
- 场景/道具；
- source dialogue；
- speaker；
- Shot 边界。

所有修改形成 revision，不覆盖原始模型 evidence。

## 正式输出

- Shot Facts；
- Scene Timeline；
- SourceDialogueUtterance；
- ShotDialogueProjection；
- Speaker Evidence；
- 人物视觉证据；
- Source Directing Facts。

## 完成条件

- 所有当前 Shot 有合法结构结果；
- canonical dialogue 有稳定 ID；
- 跨 Shot 对白保持 1:N；
- Speaker 有机器可消费结果或明确 OFFSCREEN/UNKNOWN；
- 不混入 Target-side 数据。

## 下游用途

模块 4 进行跨镜人物、场景、道具和 Speaker 的正式统一。

# 模块 4：自动统一原片人物、场景和道具

## 要解决什么

把每个 Shot 里的匿名视觉观察统一成后续可以稳定引用的正式源资产。

## 输入

- 模块 3 人物视觉证据；
- Character V10.1；
- D-ORCA Speaker Evidence；
- Scene / Prop evidence；
- SourceDialogueUtterance；
- Shot Facts。

## 人物自动处理

```text
Detection / Face / Track
  ↓
人物图库 / ReID / Face Evidence
  ↓
Character V10.1
  ↓
Final Character / provisional identity
```

规则：

- 同镜头明显不同人物不能错误合并；
- 强证据才跨镜合并；
- 证据不足时**宁可保留两个 provisional source identities，也不降低阈值强行合并**；
- provisional identity 也必须有稳定 source key，保证流程可以继续；
- 后续用户纠错可合并/拆分并触发下游失效。

## 场景和道具自动处理

```text
Scene evidence → Final Scene
Prop evidence  → Final Prop
```

同样允许自动 best-effort 归并；保留来源 evidence。

## Speaker Binding

完整 Dialogue 绑定 Speaker 时：

1. D-ORCA Speaker Evidence；
2. Character V10.1 视觉身份归一；
3. 已有正式 Speaker Override；
4. Rule-based fallback；
5. OFFSCREEN / UNKNOWN。

同一个完整 dialogue_group_id 的多个 Shot 投影不能得到互相矛盾的正式 Speaker。

## 真正阻塞

- 数据结构损坏，无法给 source identity 建稳定 key；
- 同一 utterance 出现无法调和的多个正式 speaker binding，且代码无法确定 current binding；
- 资产 revision 损坏或引用不存在。

“这个人到底像不像另一个人”本身不再强制人工阻塞。

## 用户可选纠错

- 合并/拆分人物；
- 改人物名称；
- 改 Scene/Prop；
- 改 Speaker；
- 补充漏掉的出镜人物；
- 框选错误人物位置。

## 正式输出

- Final Character；
- Final Scene；
- Final Prop；
- Shot Asset Binding；
- Dialogue Speaker Binding；
- resolution metadata / provenance。

## 完成条件

- 所有下游需要的人物有稳定 source identity；
- source dialogue 有机器可消费 Speaker 结果；
- Scene/Prop/Shot 关系结构有效；
- 不要求用户逐项确认。

## 下游用途

模块 5 编译 SourceDramaSnapshot。

---

# 模块 5：固化原片事实

## 要解决什么

把 ASR、OCR、Qwen3.8、D-ORCA、Tracking、Character、Scene、Prop 等内部结果收口成一份唯一正式源事实。

## 输入

- Episode / Scene / Shot；
- Reference Clip；
- SourceDialogueUtterance；
- ShotDialogueProjection；
- Final Character / Scene / Prop；
- Dialogue Speaker Binding；
- Source Directing Facts；
- 当前 revisions。

## 自动处理

- 编译 SourceDramaSnapshot；
- 计算 source fingerprint；
- 保存 provenance；
- 校验所有引用；
- 标识 warnings；
- 让依赖旧 fingerprint 的目标数据 STALE。

## SourceDramaSnapshot 必须同时支持

```text
Source Script 所需事实
+
Source Directing Reference 所需事实
```

不能只保留剧情文本，也不能只保留 Shot 技术字段。

## 真正阻塞

- Snapshot schema 无法通过；
- required source reference 缺失；
- 时间关系非法；
- current revision 互相矛盾；
- 媒体引用不可用。

低 confidence 不阻塞 Snapshot。

## 用户可选纠错

用户不直接编辑快照内部技术字段。发现错误时修改模块 2—4 的正式源事实，再重新编译。

## 正式输出

**SourceDramaSnapshot**。

## 完成条件

- 对应当前 source revisions；
- schema 合法；
- 下游不需要绕过 Snapshot 读取零散临时结果。

## 下游用途

模块 6—10 的唯一原片事实入口。

---

# 模块 6：还原原剧剧本 + 生成目标国家剧本

## 要解决什么

先把原片事实整理成真正可读的原剧剧本，再从剧情层生成目标国家版本。

## 输入

- SourceDramaSnapshot；
- Shot Facts；
- Episode Understanding；
- canonical SourceDialogueUtterance；
- 目标语言；
- 目标地区。

## Source Screenplay 自动处理

```text
SourceDramaSnapshot
  ↓
Episode Understanding
  ↓
Screenplay Reconstruction
  ↓
Source Screenplay
```

硬规则：

- Scene 顺序必须来自 source facts；
- 动作可以跨相邻 Shot 合并成可读剧本动作；
- canonical dialogue 每条恰好出现一次；
- 剧本模型不能生成/改写 source dialogue 正文；
- 剧本页面不堆景别/机位/Track ID 等技术字段；
- Directing Reference 继续在后台保留。

## Target Script 自动处理

```text
Source Screenplay
  + 目标语言/地区
  ↓
Country Adaptation
  ↓
Target Script
```

允许：

- 名字、社会关系表达、本地文化替换；
- 台词本土化；
- 场景本地化；
- 不影响剧情的生活细节改编。

不能无理由改变主线剧情和人物核心动机。

## 真正阻塞

- SourceDramaSnapshot 不可消费；
- screenplay model runtime 失败且无 fallback；
- 输出丢失 canonical dialogue 或引用未知 source facts；
- Target Script schema 损坏。

## 用户可选纠错

- 修改 Source Screenplay；
- 修改 Target Script；
- 重新生成目标国家版本。

## 正式输出

- Source Screenplay；
- Country Adaptation / Target Script；
- script revision / fingerprint。

## 完成条件

- Source Screenplay 可读且 grounded；
- canonical source dialogue exact-once；
- Target Script 对应当前 source script 和目标地区。

## 下游用途

模块 7 设计目标角色/场景/声音，模块 8 按目标剧本生成分镜和对白。

---

# 模块 7：设计目标人物、场景、道具和声音

## 要解决什么

把原片中的源资产转换成符合目标地区的新资产。

## 输入

- SourceDramaSnapshot；
- Target Script；
- 目标地区/语言；
- 场景策略。

## 自动处理

### TargetCharacter

每个需要出现的 source character 建立唯一当前 TargetCharacter：

- 目标姓名；
- 年龄范围；
- 外貌；
- 发型；
- 服装；
- 地区风格；
- 参考资产；
- VoiceProfile。

### Target Scene

- KEEP：保留场景结构；
- LOCALIZE：生成目标地区场景；
- AUTO：系统自动选择 KEEP/LOCALIZE 并固化为明确结果。

### Target Prop

关键剧情道具保持剧情功能，但可本地化外观/品牌/文字。

## 真正阻塞

- 必需目标资产生成失败且无 fallback；
- reference file 损坏；
- 目标人物/场景缺少稳定 current revision。

## 用户可选纠错

用户可以改人物设计、场景策略、参考图和声音，但不是必须逐个确认。

## 正式输出

- TargetCharacter；
- TargetVoiceProfile；
- SceneLocalizationMapping；
- Target Scene；
- Target Prop references。

## 完成条件

- 所有必需 source character 有目标替换；
- 所有目标场景有明确结果；
- 所有说话目标人物有 VoiceProfile；
- 结果对应当前 SourceDramaSnapshot / Target Script。

## 下游用途

模块 8 生成目标对白、TTS 和 Storyboard。

---

# 模块 8：生成目标对白、TTS、目标分镜和时间轴

## 要解决什么

目标语言说话时长不同，因此必须先拿到真实 TTS，再设计目标镜头和 GenerationSegment。

## 输入

- Target Script；
- Source Directing Reference；
- TargetCharacter / Scene / Prop；
- VoiceProfile；
- SourceDialogue links。

## 自动处理顺序

```text
Target Script dialogue
  ↓
TargetDialogue
  ↓
Target Speaker / Voice
  ↓
Qwen3-TTS
  ↓
真实 speech duration
  ↓
Target Storyboard
  ↓
RemakeTimeline
  ↓
GenerationSegment
```

绝不能先猜一个台词时长、把时间轴固定后才做 TTS。

## Target Storyboard 原则

目标分镜由：

```text
Target Script
+
Source Directing Reference
+
Target assets
+
真实 TTS duration
```

共同生成。

原片导演信息是 Reference，不是死模板。

允许：

- 一个 Source Shot 拆成多个 Target Shot；
- 多个 Source Shot 合并；
- 延长反应镜；
- 延长动作；
- 安全裁剪空白；
- 改变镜头持续时间；
- 为目标语言重新安排对白覆盖区间。

## 时间策略

系统自动选择：

- KEEP；
- TRIM；
- EXTEND；
- CARRY_OVER_REACTION；
- SPLIT_TARGET_SHOT；
- MERGE_TARGET_SHOT。

不再以 HUMAN_REVIEW 作为正常策略。

## GenerationSegment

- Target Shot ≠ GenerationSegment；
- GenerationSegment 按 H3 真正需要的生成窗口组织；
- 跨 Segment 对白保存 audio offset；
- 后一个 Segment 不能从句首重新播放。

## 真正阻塞

- 必需 TTS 文件失败/损坏；
- Timeline 非法重叠；
- GenerationSegment 无法覆盖目标时间；
- audio offset 非法；
- 目标资产引用损坏。

## 用户可选纠错

用户可修改 TargetDialogue、Storyboard、镜头时长、动作和镜头策略。

## 正式输出

- TargetDialogue；
- SpeechAsset；
- Target Storyboard；
- RemakeTimeline；
- TargetDialoguePlacement；
- GenerationSegment；
- H3 Context。

## 完成条件

- 所有目标对白有真实音频时长；
- Storyboard 覆盖目标剧本；
- Timeline 合法；
- 所有目标内容被 GenerationSegment 覆盖。

## 下游用途

模块 9 调用 H3。

---

# 模块 9：H3 重拍与自动质检

## 要解决什么

用目标人物、目标场景、目标音频和原片导演参考生成新视频，并自动把明显失败结果挡在成片之外。

## 输入

- GenerationSegment；
- H3 Context；
- TargetCharacter references；
- Target Scene/Prop references；
- visual-only Reference Clip；
- Target TTS；
- 前一个 Selected Output（需要连续性时）。

## 自动处理

```text
准备 H3 输入
→ GenerationAttempt
→ MiniMax H3
→ 下载输出
→ ffprobe
→ 完整 decode
→ 时长硬检查
→ 语义 QC
→ 失败：seed / correction prompt 有限重试
→ 自动选择最佳合格版本
→ GenerationSelection
```

QC 至少检查：

- 文件结构；
- 目标人物；
- 原演员身份泄漏；
- 目标场景；
- 动作；
- 表演；
- 构图；
- 机位；
- 运镜；
- 连续性；
- 目标时长。

## 真正阻塞

- 所有有限重试都产生损坏/不可消费文件；
- H3 runtime 不可用且无 fallback；
- required GenerationSegment 始终没有合法输出。

这类情况显示技术失败/可重试，不伪装成人工内容待确认。

## 用户可选纠错

用户可以：

- 选择另一个合格 Attempt；
- 修改分镜后重生成；
- 修改目标人物/场景后重生成。

## 正式输出

- GenerationAttempt；
- GenerationQualityCheck；
- GenerationSelection；
- Selected Output。

## 完成条件

每个 required GenerationSegment 都有 current、结构有效、通过规则的 GenerationSelection。

## 下游用途

模块 10 只读取 GenerationSelection。

# 模块 10：口型、音频、字幕、拼接和最终成片

## 要解决什么

把已经选中的目标镜头组装成真正可播放和交付的目标语言短剧。

## 输入

- GenerationSelection；
- TargetDialogue SpeechAsset；
- RemakeTimeline；
- Target Speaker；
- 字幕数据；
- 可选安全背景音。

## 自动处理

1. 按目标时间轴放置最终对白；
2. 画外对白跳过口型；
3. 单一可见说话人执行 LatentSync；
4. 多人镜头按 Target Speaker 身份定位目标人物 ROI，再做 LatentSync；
5. 生成 SRT；
6. 分离并安全复用非对白背景；
7. 标准化媒体参数；
8. 拼接整集；
9. ffprobe + 完整 decode；
10. 自动产出 EpisodeOutput。

## Speaker 原则

多人镜头必须有一个机器可消费的 Target Speaker 决定，但**不要求人工确认**。

如果 Speaker confidence 较低：

- 优先使用 D-ORCA/source speaker + target mapping；
- 使用人物可见性/嘴部活动作为辅助；
- 仍自动选当前最佳；
- 保留 correction metadata。

## 背景音硬规则

```text
源 raw audio
  ↓
分离非对白背景
  ↓
按 source dialogue windows 再次抑制源语言对白
  ↓
映射到目标时间
  ↓
保守混音
```

**禁止直接把原片 raw audio 混进目标成片。**

背景音处理失败可以安全降级成 Target Dialogue Only，不阻塞整个 Episode。

## 真正阻塞

- 必需 Selected Output 损坏；
- 必需目标音频损坏；
- 最终 MP4 无法完整解码；
- 时间轴结构无法组装。

## 用户可选纠错

最终成片默认自动产生即可交付预览。用户可以主动观看、驳回并定位问题：

- 台词问题 → 模块 6/8；
- 节奏/分镜问题 → 模块 8；
- 人物/场景/动作/运镜问题 → 模块 9；
- 口型/音轨/字幕问题 → 模块 10。

不要求用户必须逐集点击“接受”流程才能继续批处理。

## 正式输出

- PostProductionSegment；
- Lip-sync result；
- 最终目标音轨；
- UTF-8 SRT；
- EpisodeOutput；
- Final MP4；
- checksum / revision。

## 完成条件

- MP4 可完整解码；
- 音轨正确；
- SRT 使用目标时间轴；
- 无源语言对白泄漏；
- 当前输出 fingerprint 对应当前上游。
