# 剧本本土化长文本：模型上下文与输出保护

## 当前已接入范围

- 仅 `SCRIPT_LOCALIZATION` 新工作区使用；`REPLICA` 的五步生产链及原 P11/P12 完全不修改。
- 原有 `≤ 24,000` 字符的任务保留既有代码路径；`24,001～200,000` 字符自动进入独立的 `SCRIPT_LOCALIZATION_LONG_STAGE`。
- 当前单个文本项目文档超过 `200,000` 字符则显式拒绝模型任务，提示按集/章节拆分；**绝不截断源文件**。上传/存储限制与单次模型处理上限是两个概念。

## 真实限制不是“字符数”

模型 API 的约束是：`系统手册 + JSON Schema + 历史上下文 + 当前源分段 + 要求输出` 的总 token 数，此外还有提供商输出 token、超时、费率与成本限制。字符预算是保守的产品运行上限，**不是任意模型的 token 准确计数或上下文可用性保证**。不同供应商及本地 vLLM 的真实上下文配置可能不同。

## 保护措施

1. 用原文不可变字符偏移 `[start,end)` 分段，每次最多 4,000 字符，优先靠近场景/段落边界；所有分段拼接必须严格还原原剧本。
2. 每段独立真实 ProviderJob，调用前持久化；模型输出必须通过 Pydantic Schema。长文本每次请求指定 8,192 输出 token 上限，并检查 Ark `incomplete`、本地 `finish_reason=length` 和部分上下文超限响应；输出不完整则当前任务失败，不覆盖旧结果。
3. 每段成功后保存 `Task.checkpoint_json`（含分段来源 hash、结构化输出、ProviderJob ID），任务重试/重启后从已持久化的下一段继续；远程调用成功但进程在写 checkpoint 前故障可能重发该段请求，属于至少一次调用而非恰好一次计费保证。
4. 先按分段做结构理解，合并故事时保留每段完整 `chunk_analyses`；本土化方案逐段累计全剧专名和术语映射，发现同一项冲突则加入人工决策；目标剧本逐段生成，严格检查原文 span、hash、输出数量和非空，再按顺序合并并在一个事务中发布完整正式 Artifact。
5. 每段都重新核对任务的来源 Artifact、目标语言/地区和方案指纹；源文本或方案变更时拒绝继续发布，GET 不调用模型、不修改数据库。跨项目类型不可调用这条路径。
6. 当全剧映射本身过大，导致单次模型调用超过业务请求安全预算时，明确报错并要求拆分项目；不偷偷删掉人物映射或只送前半段。

## 验收边界

自动测试验证了分段原文覆盖、模拟模型完整分析→方案→目标剧本→导出、失败重试接续、来源版本失效及 Replica 类型隔离。**源文本覆盖完整不等于语义翻译零遗漏**：逐场剧情、专名、人物语气和输出质量仍需在真实模型与人工审核中确认；不同模型真实上下文额度、推理 token 消耗与吞吐需用部署环境验证。超过 20 万字的自动分卷合并、多项目全局 Registry、按真实 tokenizer 动态调整块长不属于此版验收范围。
