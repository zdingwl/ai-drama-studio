# AI Drama Studio V3 产品与系统详细规划

> 版本：V3.1 Skill Architecture Baseline  
> 日期：2026-09-08  
> 本文是当前最高优先级产品与系统规划。  
> Seko 3.0 公开架构研究见：`docs/03_Seko3.0_Skill架构逆向分析.md`。

---

# 1. V3 最终产品定位

V3 是一个 **AI 短剧生产工作台**。

用户只需要关心：

```text
我有什么素材
↓
我要做什么类型
↓
系统理解出了什么
↓
目标剧本 / 人物 / 场景 / 分镜是什么
↓
哪些地方需要修改
↓
生成到哪里
↓
最终成片
```

用户不需要理解：

```text
ASR
OCR
VLM
Tracking
ReID
Fingerprint
ProviderJob
GenerationSegment
内部模型名
```

V3 正式支持六类项目：

```text
REPLICA              复刻
REDRAW               重绘
TRANSLATION          翻译
NOVEL_TO_DRAMA       小说生成短剧
SCRIPT_TO_DRAMA      剧本生成短剧
SCRIPT_LOCALIZATION  剧本本土化
```

`project_type` 必须是真实后端字段。

---

# 2. V3 核心架构：Agent + Skill + Artifact + Tool

V3 不再把六类项目设计成六套写死的 stage graph。

正式架构：

```text
Project Type
↓
Root Project Skill
↓
Agent / Plan Compiler
↓
Project Execution Plan
↓
Professional Skills
↓
Tool / Provider Capabilities
↓
Typed Artifacts
↓
Artifact Graph
↓
下一步 Skill
```

同时存在不可绕过的系统硬约束：

```text
Workflow Guardrails
Task / ProviderJob
Revision / Fingerprint / STALE
GET Read-only
Schema Validation
Source / Target Separation
Generation QC / Selection
```

职责必须分开：

```text
Skill       = 怎么做对
Artifact    = 已经做出了什么
Agent       = 当前应该怎么规划
Tool        = 用什么执行
Guardrail   = 绝对不能违反什么
```

---

# 3. Skill 是 V3 的核心业务单元

Skill 不是一段 Prompt。

一个 Skill 必须可以描述：

- 适用场景；
- 不适用场景；
- 必需输入；
- 可读取的项目 Artifact；
- 需要的能力；
- 可以调用的子 Skill；
- 执行步骤；
- 关键判断规则；
- 什么情况需要询问用户；
- 什么情况可以自动决定；
- 输出 Artifact；
- 输出校验；
- 完成标准；
- 失败处理；
- 推荐下一 Skill。

建议结构：

```yaml
id:
name:
version:
category:
description:
when_to_use:
when_not_to_use:
required_inputs:
readable_artifacts:
required_capabilities:
subskills:
steps:
user_decision_policy:
auto_decision_policy:
output_contracts:
completion_criteria:
failure_policy:
next_recommended_skills:
```

人类可读方法论放 `SKILL.md`。

机器可执行部分放结构化 manifest，不依赖运行时解析 Markdown。

# 4. Skill 三层结构

## 4.1 项目 Root Skill

回答：

> 这一类项目整体应该怎么完成？

六个正式 Root Skill：

```text
skills/projects/replica/
skills/projects/redraw/
skills/projects/translation/
skills/projects/novel_to_drama/
skills/projects/script_to_drama/
skills/projects/script_localization/
```

Project 创建后绑定当前 Root Skill + Skill Version。

---

## 4.2 Professional Skill

回答：

> 某项专业工作怎么做对？

第一版建议至少包括：

```text
source-video-understanding
story-rhythm-analysis
shot-breakdown
character-resolution
scene-resolution
prop-resolution
speaker-attribution
script-analysis
novel-adaptation
script-localization
target-world-design
character-design
scene-design
prop-design
dialogue-localization
storyboard-directing
timing-adaptation
video-generation-qc
post-production
```

这些 Skill 可以被不同 Root Skill 复用。

---

## 4.3 Tool / Provider Playbook

回答：

> 具体模型 / 工具怎样被安全、正确地调用？

例如：

```text
Step 3.7 Flash
faster-whisper
RapidOCR
Speaker Provider
Identity Provider
Qwen3-TTS
MiniMax H3
LatentSync
FFmpeg
```

业务 Skill 只能依赖 capability，不绑定具体模型。

例如：

```text
required_capability = SOURCE_EPISODE_UNDERSTANDING
```

由 Provider Registry 决定生产环境实际使用哪个 Provider。

# 5. Agent 与 Project Execution Plan

Agent 不能变成每次请求都临时发挥的黑盒。

正确流程：

```text
Project Type
+
Root Skill Version
+
当前 Artifact 状态
+
用户配置
↓
Agent / Plan Compiler
↓
ProjectExecutionPlan
↓
PlanStep[]
```

生成出来的 Plan 必须：

- 持久化；
- 有 revision；
- 有 input_fingerprint；
- 记录使用的 Root Skill Version；
- 可以被重新编译；
- 不会因为页面刷新自动变化；
- 只有用户修改项目配置 / Artifact / Skill Version 后才重新生成新 Plan。

Agent 可以做专业判断，但 Guardrail 必须确定性执行。

例如 Agent 永远不能决定：

- GET 时启动付费模型；
- 跳过 ProviderJob；
- 把 STALE Artifact 当 CURRENT；
- 直接把 Track 当 Character；
- 让 H3 Attempt 未经过 Selection 就进入后期。

# 6. Artifact Graph：我们的“画布内核”

V3 学习 Seko 的“项目资产长期沉淀”，但第一版不先做复杂无限画布 UI。

后端先建立正式 `Artifact Graph`。

所有 Skill 读取 / 写入正式 Artifact。

例如：

```text
SourceVideoSnapshot
├─ contains → SourceCharacter
├─ contains → SourceScene
├─ contains → SourceProp
└─ contains → SourceShotFact

TargetCharacter ETHAN
├─ used_by → StoryboardShot 12
└─ used_by → StoryboardShot 18

TargetScene MANSION_LIVING_ROOM
├─ used_by → StoryboardShot 11
└─ used_by → StoryboardShot 12

TargetProp DNA_REPORT
└─ used_by → StoryboardShot 23
```

前端以后可以把 Artifact Graph 渲染成节点画布。

硬原则：

> **画布是正式 Artifact Graph 的视觉化，不是数据库真相。**

# 8. 六个 Root Skill 的业务定义

## 8.1 REPLICA — 复刻

用户目标：

> 把一部已经验证过好看的原短剧，换成目标地区的人物、语言和世界重新拍一遍。

默认锁定：

- 故事主线；
- Hook；
- 冲突顺序；
- 反转；
- 信息揭示顺序；
- 情绪起伏；
- Payoff / 爽点 / 痛点；
- Cliffhanger；
- 场景顺序；
- 镜头逻辑；
- 动作节奏；
- Shot Rhythm 基线。

允许本土化：

- 人物姓名 / 身份 / 外形；
- 场景文化环境；
- 道具外观；
- 货币 / 法律 / 公司 / 学校 / 社交习惯；
- 称呼和文化表达；
- 目标语言对白。

Root Skill 需要的核心 Professional Skills：

```text
source-video-understanding
story-rhythm-analysis
shot-breakdown
character/scene/prop/speaker-resolution
localization
target-world-design
dialogue-localization
storyboard-directing
timing-adaptation
video-generation-qc
post-production
```

---

## 8.2 REDRAW — 重绘

目标：保留原剧内容和大部分时间结构，重点更换视觉。

允许：

- 真人换演员；
- 地区 / 时代 / 服装改变；
- 写实 ↔ 风格化；
- 原语言保留或可选重新配音。

默认不重新编故事。

---

## 8.3 TRANSLATION — 翻译

目标：原画面尽量保持，仅重建目标语言版本。

核心能力：

```text
Source Dialogue
→ Speaker
→ Translation / Localization
→ Voice / TTS
→ Actual Duration
→ Timing
→ Lip Sync
→ Subtitle / Audio / Post
```

默认不做整段 H3 重拍，只在补帧 / 延长 / 修复画面时局部调用生成。

---

## 8.4 NOVEL_TO_DRAMA — 小说生成短剧

小说不能直接逐段转视频。

必须先：

```text
小说理解
→ 人物 / 世界观 / 事件
→ 可影视化改编
→ Episode Outline
→ Hook / 冲突 / 反转 / Cliffhanger
→ 短剧剧本
→ Target Bible
→ Storyboard
→ 生成
```

---

## 8.5 SCRIPT_TO_DRAMA — 剧本生成短剧

用户故事已存在。

系统主要负责：

- 标准化剧本；
- 补动作 / 可视化信息；
- 人物 / 场景 / 道具资产；
- 导演分镜；
- 时长；
- 可生成性；
- 视频生产。

---

## 8.6 SCRIPT_LOCALIZATION — 剧本本土化

默认输出是目标地区本土化剧本，不强制生成视频。

需要处理：

- 人名；
- 身份；
- 社会关系；
- 制度环境；
- 金额 / 单位；
- 节日 / 饮食 / 服装；
- 场景；
- 道具；
- 俚语；
- 情绪表达；
- 冲突成立条件；
- 文化梗；
- 对白自然度。

完成后可一键派生为 SCRIPT_TO_DRAMA 项目，并复用正式 Target Script Artifact。

# 9. 视频类项目的正确原片理解顺序

适用：REPLICA / REDRAW / TRANSLATION。

正式业务顺序：

```text
导入完整 Episode
↓
媒体检查 / Source Timebase
↓
Shot Boundary
这里只建立时间锚点 / Reference Clip
不等于逐镜语义拉片
↓
ASR + OCR
↓
整集理解
↓
Source Episode Bible
├─ 故事梗概
├─ 剧情时间线
├─ Story Beats
├─ 角色候选
├─ 人物关系
├─ 场景候选
├─ 关键道具
├─ 关键事件
├─ 世界背景
└─ 情绪变化
↓
Story Skeleton + Rhythm Skeleton
↓
带全局知识做逐镜精细拉片
↓
Speaker / Character / Scene / Prop 归一
↓
SourceVideoSnapshot
```

禁止回到：

```text
先让每个 Shot 猜整部故事
→ 最后把 Shot 拼成剧情
```

关键原则：

> **先知道整部戏讲什么、谁是谁、在哪发生、有什么关键东西，再研究导演一镜一镜怎么拍。**

# 10. Story Skeleton + Rhythm Skeleton

Replica 的权威约束必须新增两个正式 Artifact。

## StorySkeleton

至少包含：

- Hook；
- Conflict；
- Escalation；
- Reveal；
- Reversal；
- Emotional Peak；
- Payoff；
- Cliffhanger；
- Character Relationship Change；
- Beat 起止时间。

## RhythmSkeleton

至少包含：

- Shot 顺序；
- Shot 原始时长；
- Scene 节奏；
- Dialogue / Reaction 节奏；
- Cut Timing；
- 关键 Beat 的时间位置；
- 可允许偏移范围。

Replica Skill 下游必须默认遵守：

```text
故事不乱改
节奏不重做
文化和表达才本土化
```

---

# 11. Source Dialogue 权威规则

完整对白必须是独立业务对象：

```text
SourceDialogueUtterance
      ↓ 1:N
ShotDialogueProjection
```

一条对白跨多个镜头：

- 原文只保存一次；
- 完整时间只保存一次；
- Shot 只保存自己覆盖的投影区间。

canonical source dialogue 主要来自：

```text
ASR + OCR / Subtitle + reconciliation
```

视觉 / 故事模型不能随意改写正式源对白。

Speaker 需要独立音视频证据。

---

# 12. Character / Scene / Prop

## Character

禁止：

```text
Face == Character
Track == Character
```

必须使用多证据：

- Face；
- Body / Person ReID；
- Clothing / Hair / Body features；
- Track / Temporal continuity；
- Voice；
- Source Bible role context；
- neighboring-shot continuity。

## Scene

整集阶段建立全局 Scene Identity，Shot 绑定全局 Scene，不能每个镜头重新创造一个文本场景。

## Prop

只有剧情相关的重要道具升级成全局正式 Prop。

桌子、杯子、花瓶等普通背景物不应自动污染剧情资产库，除非它们在剧情中有作用。

# 13. 模型与 Provider 规划

模型必须通过 Provider 抽象。

## AgentReasoningProvider

用于：

- Skill 规划；
- 跨 Artifact 推理；
- 结构化专业判断；
- 计划建议。

当前优先候选：

```text
Step 3.7 Flash
```

原因：面向 Agent、长上下文、视觉理解、工具调用生态。

但业务合同不能写死模型名。

## SourceEpisodeUnderstandingProvider

负责整集故事 / 世界 / 角色 / 事件理解。

当前 Step 3.7 Flash 作为重点候选之一，必须通过真实 Episode A/B 验收后才能成为生产默认。

## SourceShotUnderstandingProvider

负责逐镜导演事实。

候选：

```text
Step 3.7 Flash
Qwen3.8 系列
其他经真实镜头验收的 VLM
```

## Dialogue / OCR / Speaker / Identity

继续使用独立专业 Provider，不能把一个多模态大模型当作所有事实的唯一来源。

## TTS

当前规划：Qwen3-TTS Provider。

## Video Generation

固定业务抽象：

```text
VideoGenerationProvider
→ MiniMaxH3Provider
→ Local Runtime
```

## Lip Sync

规划：LatentSync Provider 或后续更强可替换实现。

---

# 14. Target Dialogue 与时长

顺序固定：

```text
Source Dialogue
→ Translation
→ Localization
→ Final Target Dialogue
→ Target Speaker / Voice
→ TTS
→ Actual Speech Duration
→ Timing Plan
```

Replica 优先级：

1. 保持语义 / 情绪 / 人物关系；
2. 目标语言自然；
3. 优先压缩 / 改写对白适配原节奏；
4. 微调停顿 / 表演；
5. 只做最小镜头时长调整；
6. 大幅改动 Story / Rhythm 最后才允许，并进入用户决策。

允许策略：

```text
KEEP
TRIM
EXTEND
CARRY_OVER_REACTION
REWRITE_SHORTER
SPLIT_SHOT
MERGE_SHOT
USER_DECISION
```

禁止全局不自然语速或整体慢放硬解决语言差异。

---

# 15. Source Shot / Storyboard Shot / GenerationSegment

三者必须分开。

```text
Source Shot
= 原片真实剪辑单位

TargetStoryboardShot
= 目标版本导演设计单位

GenerationSegment
= 真正送入生成模型的推理窗口
```

禁止：

```text
Source Shot == TargetStoryboardShot == GenerationSegment
```

一个 GenerationSegment 可以覆盖多个最终剪辑 Shot。

最终剪辑仍可恢复源节奏。

---

# 16. H3 生成、QC 与 Selection

```text
Target Storyboard
↓
Timing Plan
↓
GenerationSegment
↓
MiniMax H3
↓
GenerationAttempt
↓
Technical QC
↓
Semantic QC
↓
PASS / RETRY / USER_DECISION
↓
GenerationSelection
↓
Post
```

只有 GenerationSelection 可以进入后期。

QC 至少检查：

- 可完整 decode；
- 时长；
- Target Character 一致性；
- 原演员泄漏；
- Target Scene；
- 动作是否完成；
- 构图 / 运镜；
- 连续性；
- 明显生成崩坏。

Retry 必须有限次数，并带具体 correction。

# 17. Task / ProviderJob / 状态

重任务必须持久化 Task。

外部付费 Provider 必须：

```text
先持久化 ProviderJob
↓
再发远程请求
```

禁止保存 API Key 到 DB / Artifact / 日志 / Git。

内部三维状态继续使用：

```text
Validity:
NOT_BUILT | CURRENT | STALE

Readiness:
READY | BLOCKED_DEPENDENCY | WAITING_RUNTIME | BLOCKED_TECHNICAL | NEEDS_USER_DECISION

Execution:
IDLE | QUEUED | PROCESSING | SUCCEEDED | FAILED | INTERRUPTED
```

只有：

```text
CURRENT + READY
```

才能被下游消费。

---

# 18. Revision / Fingerprint / STALE

从第一天就必须正确处理重算。

关键正式 Artifact 至少保存：

```text
revision
input_fingerprint
skill_id
skill_version
created_at
supersedes
```

上游变化：

```text
旧结果保留
↓
current pointer 失效
↓
下游 STALE
↓
重新编译 Plan
↓
用户显式启动需要的重任务
```

页面刷新绝不能自动重算。

# 23. 自动模式与专业模式

两种模式消费同一正式数据。

## 自动模式

```text
Agent 根据 Root Skill 自动推进建议
→ 用户只处理真正需要选择的地方
```

## 专业模式

用户可以进入：

- 剧本；
- 人物；
- 场景；
- 道具；
- Story / Rhythm；
- 分镜；
- 生成版本。

进行局部编辑和重生成。

不能做两套互不兼容的数据结构。

# 24. Episode 批处理

多集默认串行：

```text
EP01
→ 当前重阶段完成
→ EP02
→ EP03
```

不默认并行跑多个重模型。

原因：GPU / VRAM、Provider 限流、稳定性、人物和世界信息跨集复用。

# 25. 第一版明确不做

- 微服务；
- Kubernetes；
- 多租户权限；
- Skill 市场；
- 用户上传任意可执行 Skill；
- 无限画布编辑器；
- raw Prompt 编辑器；
- 六条完整业务同时开发；
- 页面自动启动 Agent；
- 无限重试。

先把 Root Skill + Artifact Graph + Replica 纵向链做正确。

# 28. 完成定义

任何能力都必须分别说明：

```text

2. 自动测试是否通过
3. CI 是否通过

6. 输出结构是否正确

```

不能用其中一层替代另一层。

# 29. V3 成功标准

系统层：

- Project Type 真正驱动 Root Skill；
- Skill 不是 Prompt；
- Agent 规划会物化为正式 Plan；
- Artifact Graph 是项目长期上下文；
- Source / Target / Production 边界清晰；
- 视频类先整集理解再逐镜；
- Story / Rhythm 能约束 Replica；
- TTS 真实时长驱动 Timing；
- H3 Attempt / QC / Selection 分离；
- GET 无副作用；
- 外部调用先 ProviderJob；
- 上游变化正确 STALE。

用户层：

- 选择项目类型后系统知道该怎么做；
- 用户不需要理解内部模型；
- 中间结果可读、可改；
- 人物 / 场景 / 道具 / 分镜可以长期复用；
- 发现错误只改相关部分；
- 能稳定得到最终输出。

旗舰 Replica 的最终目标：

> **给一部原短剧，系统真正理解故事、人物、场景、道具和导演节奏，再自动生成一部符合目标地区人物、语言和文化环境，同时尽可能继承原作故事、动作、表演、镜头逻辑和节奏的新短剧。**
