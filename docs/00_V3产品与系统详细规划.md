# AI Drama Studio V3 产品与系统详细规划

> 版本：V3.0 Planning Baseline  
> 日期：2026-09-08  
> 本文是仓库清空重建后的最高优先级产品与系统规划。

---

# 1. 为什么重建

旧仓库长期围绕“单一短剧重做链”演进，已经积累了大量历史版本、兼容层、页面、状态和模型链。继续在旧结构上增加“复刻、重绘、翻译、小说生成短剧、剧本生成短剧、剧本本土化”六种项目，会导致：

- 前端虽然有六种入口，后端实际仍是一条旧流程；
- 不同输入类型被强行塞进视频拉片模型；
- 页面越来越多，但用户看不到最直接的业务结果；
- 历史中间数据、业务正式数据和目标生成数据边界混乱；
- 每增加一种项目类型都要绕过大量旧兼容代码；
- 很难判断哪些能力是真正完成、哪些只是代码入口存在。

因此 V3 选择从产品模型重新设计，而不是继续对旧仓库做补丁。

---

# 2. V3 产品目标

V3 要成为一个统一的 AI 短剧生产工作台。

用户不需要理解模型、ASR、OCR、VLM、Tracking、ReID、Fingerprint、Provider Job 等内部技术细节。用户只需要回答：

1. 我现在有什么素材？
2. 我想做哪一类短剧任务？
3. 我要生成哪个语言、地区、风格的版本？
4. 系统已经理解出了什么？
5. 哪些内容需要我改？
6. 目标剧本、人物、场景、分镜是什么？
7. 视频生成到哪里了？
8. 最终成片在哪里？

V3 正式支持六类项目：

```text
REPLICA              复刻
REDRAW               重绘
TRANSLATION          翻译
NOVEL_TO_DRAMA       小说生成短剧
SCRIPT_TO_DRAMA      剧本生成短剧
SCRIPT_LOCALIZATION  剧本本土化
```

`project_type` 是整个后端工作流的第一层路由条件，不是前端标签。

# 3. 六类项目的业务定义

## 3.1 复刻 REPLICA

### 用户目标

给系统一部已经完成的短剧，系统先完整理解原剧，再重做一个面向目标语言和目标地区的新版本。

### 应保留

- 核心剧情；
- 冲突与反转；
- 镜头切换关系；
- 动作和表演关系；
- 构图和运镜意图；
- 关键情绪节奏；
- 关键道具在剧情中的功能。

### 应允许替换/本土化

- 人物身份与外形；
- 服装；
- 场景；
- 关键道具外观；
- 文化环境；
- 画面文字；
- 台词表达；
- Voice；
- 因语言时长差异导致的镜头时长。

### 正式输出

目标地区版本完整短剧成片。

---

## 3.2 重绘 REDRAW

### 用户目标

保留原剧的剧情、剪辑、对白时序和表演结构，重点重做视觉。

典型用途：

- 真人换演员；
- 场景整体换地区；
- 写实转特定视觉风格；
- 服装、时代、身份重设；
- 原语言不变，只重做画面。

### 默认规则

- 原对白语义默认保留；
- 原音轨可配置 `KEEP_SOURCE_AUDIO` 或 `REGENERATE_AUDIO`；
- 参考视频送入生成模型前移除源音轨；
- 如果选择保留源音频，在后期阶段重新挂回正式目标时间线；
- 若用户同时改变目标语言，则自动升级为“重绘 + 目标语音重建”路径。

### 正式输出

视觉重绘后的完整短剧成片。

---

## 3.3 翻译 TRANSLATION

### 用户目标

尽可能保持原始画面不变，只把短剧做成新的目标语言版本。

### 核心处理

- 源对白识别；
- Speaker 识别；
- 翻译；
- 本地化表达；
- Voice；
- TTS；
- 真实语音时长；
- 镜头延长/裁剪/反应镜头承接；
- Lip Sync；
- 字幕；
- 安全音轨重建。

### 关键原则

不能把不同语言硬塞进原视频固定时长。

允许：

```text
KEEP
TRIM
EXTEND
CARRY_OVER_REACTION
REWRITE_SHORTER
HUMAN_REVIEW
```

翻译类型默认不调用 H3 重绘整段视频。只有确实需要补帧、延长镜头或修复口型画面时，才调用局部生成能力。

### 正式输出

保留原视觉为主的目标语言成片。

---

## 3.4 小说生成短剧 NOVEL_TO_DRAMA

### 用户目标

输入小说、网文、故事文本，自动改编成可拍摄/可生成的短剧。

### 核心流程

```text
小说
→ 文本清洗与章节切分
→ 故事理解
→ 人物/关系/世界观
→ 冲突/钩子/反转提炼
→ 短剧改编方案
→ Episode Outline
→ 正式短剧剧本
→ Target Bible
→ Storyboard
→ Voice/TTS
→ GenerationSegment
→ H3
→ QC
→ Post
→ 成片
```

### 重点

小说不能直接逐段转视频，必须先完成短剧化改编：

- 强化开场钩子；
- 压缩背景说明；
- 提升对话密度；
- 把心理活动改造成可见行为；
- 把章节结构转换为 Episode 节奏；
- 明确每集结尾悬念。

### 正式输出

短剧剧本 + 完整生成成片。

---

## 3.5 剧本生成短剧 SCRIPT_TO_DRAMA

### 用户目标

用户已经有剧本，系统不重新发明故事，而是把剧本整理成可生成的短剧生产方案并生成成片。

### 核心流程

```text
剧本
→ 结构解析
→ Scene / Character / Dialogue 标准化
→ 剧本合法性检查
→ Target Bible
→ Shot Storyboard
→ 目标人物/场景/道具
→ Voice/TTS
→ Timing Plan
→ GenerationSegment
→ H3
→ QC
→ Post
→ 成片
```

### 重点

系统只能在用户允许的范围内优化：

- 不足的动作描述；
- 缺失的镜头规划；
- 不适合视频生成的场景切分；
- 对白时长；
- 连续性；
- 可生成性。

### 正式输出

标准化剧本、分镜和完整短剧成片。

---

## 3.6 剧本本土化 SCRIPT_LOCALIZATION

### 用户目标

输入一份已有剧本，把它改造成目标地区真正能成立的版本，而不是逐句翻译。

### 要处理的内容

- 人名；
- 人物身份；
- 家庭/社会关系；
- 公司、学校、医院、法律等制度环境；
- 金额、单位、地址；
- 节日、饮食、服装；
- 场景；
- 道具；
- 俚语；
- 情绪表达；
- 冲突成立条件；
- 笑点与文化梗；
- 对白自然度。

### 默认正式输出

目标地区本土化剧本。

### 可扩展行为

用户可以把本土化完成的剧本一键转为 `SCRIPT_TO_DRAMA` 生产任务，不需要重新解析剧本。

# 4. 六类项目不是六套完全独立代码

V3 的核心设计是：

```text
不同输入
→ 不同 Source Pipeline
→ 统一 Target Production Pipeline
```

不是复制六套系统。

# 5. V3 三层正式数据边界

## 5.1 Source Facts

描述“用户原始素材真实是什么”。

根据输入类型不同分为：

### SourceVideoSnapshot

用于：

- 复刻；
- 重绘；
- 翻译。

至少包含：

- Episode；
- Shot Anchor；
- Source Script；
- Source Dialogue；
- Speaker；
- Source Character；
- Source Scene；
- Source Prop；
- Source Directing Facts；
- Reference Clip；
- Source fingerprint。

### SourceTextSnapshot

用于：

- 小说；
- 剧本；
- 待本土化剧本。

至少包含：

- 原始文档；
- 章节/场次；
- Character；
- Relationship；
- Dialogue；
- Event；
- World facts；
- source revision/fingerprint。

Source Facts 不能包含目标人物、目标台词和生成结果。

---

## 5.2 Target Bible

描述“我们准备做成什么样”。

所有最终生成视频的项目最终都要进入这一层。

至少包含：

- Target World；
- Target Script；
- Target Character；
- Target Character Appearance；
- Target Scene；
- Target Prop；
- Target Voice；
- Visual Style；
- Localization Decisions；
- continuity rules。

这是一套完整世界，不允许人物、场景、道具各自本土化后互相不匹配。

---

## 5.3 Production Plan

描述“具体怎么生成”。

至少包含：

- TargetStoryboardShot；
- target action/performance；
- source reference clip（视频来源项目可选）；
- TargetDialogue；
- TTS asset；
- actual speech duration；
- TimingPlan；
- GenerationSegment；
- H3 prompt/context；
- GenerationAttempt；
- QC result；
- GenerationSelection；
- PostProductionPlan；
- Final Output。

# 6. 视频类项目原片理解的正确顺序

这是 V3 必须保持的核心逻辑。

```text
导入完整 Episode
↓
媒体检查 / Source Timebase
↓
Shot Boundary
这里只找切镜和建立 Reference Clip
不等于逐镜语义拉片
↓
ASR + OCR
保留对白和画面文字时间证据
↓
整集音视频理解
↓
Source Bible
├─ 故事梗概
├─ 剧情时间线
├─ Story Beats
├─ 角色候选
├─ 角色关系
├─ 场景候选
├─ 关键道具
├─ 关键事件
├─ 世界背景
└─ 情绪变化
↓
带 Source Bible 做逐镜精细分析
↓
逐镜得到
├─ 当前可见人物
├─ 动作
├─ 表情
├─ 姿态
├─ 视线
├─ 互动
├─ Blocking
├─ 场景/道具可见事实
├─ 景别
├─ 机位
├─ 构图
├─ 运镜
├─ 光线
├─ 剧情作用
└─ 连续性
↓
Speaker / Character / Scene / Prop 归一
↓
SourceVideoSnapshot
```

关键思想：

> 先知道整部戏讲什么、谁是谁、在哪发生、有什么关键东西，再研究导演一镜一镜怎么拍。

# 7. 模型职责规划

模型必须通过 Provider 抽象接入，业务对象不能绑定某个具体模型名。

## 7.1 SourceEpisodeUnderstandingProvider

职责：完整 Episode 音视频理解，形成 Source Bible。

默认优先选择中国大陆可稳定访问、支持长视频和音视频联合理解的 Provider。

当前规划默认：

```text
Volcano / Doubao Seed 2.0 系列
```

但数据库和业务字段只记录 provider/model profile，不能把类名写死为 Doubao。

---

## 7.2 SourceShotUnderstandingProvider

职责：带 Source Bible 做逐镜视觉和导演事实分析。

规划默认：

```text
Qwen3.8 系列本地运行
```

它不能拥有 canonical source dialogue。

---

## 7.3 SourceDialogueEvidenceProvider

职责：

- ASR；
- OCR/Subtitles；
- 时间证据。

规划默认：

```text
faster-whisper
RapidOCR
```

---

## 7.4 SpeakerAttributionProvider

职责：识别谁在什么时候说话。

不能用自己的 transcript 覆盖 canonical dialogue。

---

## 7.5 IdentityProvider

职责：把不同镜头里的视觉人物归一成稳定 Source Character。

必须使用多证据，不允许简单“人脸 = 人物”。

---

## 7.6 LocalizationProvider

职责：

- 翻译；
- 文化本土化；
- Script adaptation；
- Target World planning。

必须输出结构化决策，不只返回一段自然语言。

---

## 7.7 Voice/TTS Provider

默认：

```text
Qwen3-TTS
```

TTS 完成后必须以真实音频时长驱动 Timing Plan。

---

## 7.8 VideoGenerationProvider

业务层固定抽象：

```text
VideoGenerationProvider
└─ MiniMaxH3Provider
   └─ Local H3 Runtime
```

最终生成默认使用本地 MiniMax H3。

业务 Service 不能直接依赖具体推理服务实现。

---

## 7.9 LipSyncProvider

规划默认：

```text
LatentSync
```

多人镜头必须先确定目标说话人，再做目标 ROI 口型。

# 9. Source Shot、Storyboard Shot、GenerationSegment 必须分开

## Source Shot

原片真实剪辑单元。

## TargetStoryboardShot

目标版本导演设计单元。

它可以：

- 对应一个 Source Shot；
- 合并多个 Source Shot；
- 拆分一个 Source Shot；
- 对小说/剧本项目完全没有 Source Shot。

## GenerationSegment

真正送入 H3 的生成窗口。

它是推理单元，不是导演业务单元。

禁止：

```text
Source Shot == Target Storyboard Shot == GenerationSegment
```

# 10. 多语言时长规划

完整链路必须固定：

```text
Source Dialogue
→ Translation
→ Localization
→ Final Target Dialogue
→ Target Speaker / Voice
→ TTS
→ Actual Speech Duration
→ Timing Plan
→ GenerationSegment
```

禁止在 TTS 前猜最终时长并强制语音适配。

Timing 策略：

```text
KEEP
TRIM
EXTEND
CARRY_OVER_REACTION
REWRITE_SHORTER
SPLIT_SHOT
MERGE_SHOT
USER_DECISION
```

优先级：

1. 自然对白；
2. 保持剧情节奏；
3. 使用反应镜头承接；
4. 合理延长/裁剪镜头；
5. 必要时改写更短；
6. 最后才要求用户决定。

禁止使用明显不自然的全局语音加速或视频慢放作为主要方案。

---

# 11. H3 生成规划

每个 GenerationSegment 至少包含：

- target duration；
- TargetCharacter refs；
- TargetScene ref；
- TargetProp refs；
- Target dialogue/audio condition；
- action/performance description；
- camera/framing/motion；
- continuity context；
- source reference video（复刻/重绘可选）；
- negative constraints；
- generation fingerprint。

Reference Video 只能作为：

- 动作；
- 表演；
- 构图；
- 运镜；
- 节奏参考。

源语言音轨在送 H3 前必须移除。

---

# 12. GenerationAttempt / QC / Selection

技术成功不等于可用。

```text
GenerationAttempt
→ ffprobe
→ full decode
→ duration gate
→ semantic QC
→ PASS / RETRY / NEEDS_USER_DECISION
→ GenerationSelection
```

QC 至少检查：

- 视频可解码；
- 时长；
- TargetCharacter 一致性；
- 原演员身份泄漏；
- TargetScene；
- 动作是否完成；
- 构图/运镜；
- 前后镜头连续性；
- 口型前置条件；
- 明显生成崩坏。

只有 `GenerationSelection` 是后期正式输入。

Retry 必须：

- 有最大次数；
- 改 seed；
- 带上具体 QC correction；
- 禁止无限循环。

# 13. 音频与口型规划

## 13.1 Translation / Replica

源对白音轨不能直接混进目标语言成片。

目标音频至少来自：

```text
Target TTS
+
安全背景/Music/SFX
```

如需要复用源背景：

```text
Source Audio
→ speech/music/sfx separation
→ source dialogue window suppression
→ target timing remap
→ conservative mix
```

## 13.2 Redraw

如果用户明确选择 `KEEP_SOURCE_AUDIO`，可以在生成画面完成后把源音频按正式时间线重新挂回成片。

这属于项目业务配置，不应和 Replica 的目标语言音频规则混为一谈。

## 13.3 Lip Sync

- OFFSCREEN：不修改嘴；
- 单一明确说话人：整段/ROI Lip Sync；
- 多人：先确定目标 Speaker，再定位 ROI；
- 无法确认目标人脸：进入 NEEDS_USER_DECISION 或保守跳过，不允许改错人的嘴。

# 16. revision / fingerprint / stale

V3 从第一天就要正确处理重算，不允许后期再补。

任何关键正式数据都保存：

```text
revision
input_fingerprint
created_at
supersedes
```

上游变化时：

```text
旧结果保留历史
→ current pointer 失效
→ 下游标记 STALE
→ 页面显示“需要重新生成”
→ 用户显式启动重任务
```

禁止页面刷新自动重算。

---

# 17. 状态模型

内部统一三维状态：

## Validity

```text
NOT_BUILT
CURRENT
STALE
```

## Readiness

```text
READY
BLOCKED_DEPENDENCY
WAITING_RUNTIME
BLOCKED_TECHNICAL
NEEDS_USER_DECISION
```

## Execution

```text
IDLE
QUEUED
PROCESSING
SUCCEEDED
FAILED
INTERRUPTED
```

只有：

```text
Validity = CURRENT
Readiness = READY
```

才能被下游正式消费。

用户页面只显示简单业务文案，例如：

```text
未开始
处理中
已完成
需要重新生成
模型未启动
需要你确认
失败
```

不直接把内部状态枚举堆给用户。

# 18. 自动化与人工确认原则

V3 默认自动处理。

普通低置信度：

```text
保存 confidence/provenance
→ 选择当前最佳结果继续
```

真正需要用户决定的情况：

- 两个主要人物发生结构性身份冲突；
- 目标 Speaker 无法安全定位且会导致改错嘴；
- 本土化有多个完全不同剧情方向，需要创作选择；
- H3 多次重试仍无法得到可用镜头；
- 原素材损坏；
- 必需结构无法自动修复。

不需要为每个低置信度检测建立 Review 页面。

# 23. API 设计原则

## Query


## Command

所有重任务必须显式命令。

```text
POST /api/projects

POST /api/projects/{id}/commands/build-target
POST /api/projects/{id}/commands/build-storyboard

```

写操作要支持：

- Idempotency-Key；
- expected revision；

# 25. Episode 批处理原则

用户一次可以导入多集。

默认处理：

```text
EP01
→ 完成当前阶段
→ EP02
→ EP03
```

即批量是“按顺序排队”，不是默认并行跑多个重模型。

原因：

- GPU/VRAM；
- 外部 Provider 限流；
- 容易定位错误；
- 上一集人物/世界信息可以辅助下一集；
- 避免磁盘和模型竞争。

以后可以在明确资源调度器存在后再增加可控并行。

# 28. V3 第一版不做的事情

为了避免再次失控，以下内容第一阶段不做：

- 多租户/企业权限系统；
- 微服务拆分；
- Kubernetes；
- 模型市场；
- 节点式可视化工作流编辑器；

# 29. 开发优先顺序

虽然产品有六类项目，但开发必须按共享能力纵向完成。

## Phase 0：仓库重建基线

- 清空旧 main；
- 留规划；
- 建新项目骨架；
- 建 CI；
- 建数据库迁移；
- 建 Project/project_type；
- 建统一 WorkflowStageState；
- 建 Task/ProviderJob。

## Phase 1：项目系统

- 六种项目创建；
- 各类型输入规则；
- 项目列表；
- 工作区动态阶段；
- SourceAsset；
- 上传与排序。

## Phase 2：视频原片理解

优先实现旗舰“复刻”需要的 Source Pipeline：

```text
Media
→ Shot Boundary
→ ASR/OCR
→ Episode Understanding
→ Source Bible
→ Per-Shot Understanding
→ Speaker/Identity normalization
→ SourceVideoSnapshot
```

先把“看懂原片”真正做对。

## Phase 3：复刻端到端 MVP

```text
SourceVideoSnapshot
→ Target Bible
→ Target Script
→ Target Assets
→ TTS
→ Replica Storyboard
→ TimingPlan
→ H3
→ QC/Selection
→ Post
→ Output
```

先用一个真实 Episode 跑通。

## Phase 4：翻译

复用视频输入、Dialogue、Speaker、TTS、Timing、Lip Sync、Post。

不需要完整 Target Asset/H3 重拍链。

## Phase 5：重绘

复用 SourceVideoSnapshot + Storyboard + H3 + QC。

增加视觉方案和 audio_policy。

## Phase 6：剧本生成短剧

实现 SourceTextSnapshot + Script normalization，然后接入共享 Target/Storyboard/H3 链。

## Phase 7：小说生成短剧

增加 Novel Adaptation 层，再接到 Script Pipeline。

## Phase 8：剧本本土化

实现强本地化 Adaptation Plan 和 Target Script 导出，并支持转 SCRIPT_TO_DRAMA。

## Phase 9：生产级稳定

- 真实多集；
- 中断恢复；
- 任务排队；
- 磁盘/VRAM 管理；
- 性能；
- 失败诊断；
- 用户最终看听验收。

# 30. 每个阶段的验收定义

不能再笼统说“完成”。

必须分开：

```text
1. 数据模型/API 已实现
2. 自动测试通过
3. 前端真实交互通过
4. 模型 Runtime 真正运行
5. 真实素材跑通
6. 输出结构正确
7. 用户看/听质量通过
```

例如：

“Qwen Provider 类已写完”只能算第 1 层。

“pytest 通过”只能算第 2 层。

必须用真实 Episode 跑完才能说模型链真实验收。

# 32. V3 成功标准

V3 不是“页面多”和“模型多”。

真正成功标准是：

### 用户层

- 能明确选择自己要做的项目类型；
- 每一步都能看懂结果；
- 不需要理解内部 AI 技术；
- 发现错误能直接改；
- 不需要重复处理无关步骤；
- 能稳定拿到最终输出。

### 系统层

- 六类项目由真实后端工作流驱动；
- Source/Target/Generation 数据边界清晰；
- 视频类先整集理解再逐镜；
- 真实 TTS 时长驱动时间线；
- H3 输入输出可追踪；
- Attempt/QC/Selection 分离；
- GET 无副作用；
- 任务可恢复；
- 上游变化可正确 STALE；
- 历史代码不再拖累新架构。

### 质量层

复刻项目最终要达到：

> 给一部原短剧，系统能理解它，再自动生成一部人物、语言、文化环境符合目标地区，同时动作、表演、镜头逻辑和剧情节奏尽可能继承原作的新短剧。

这就是 V3 的旗舰能力。
