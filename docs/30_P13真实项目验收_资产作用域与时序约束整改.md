# P13 真实项目验收：资产作用域与时序约束整改

> 日期：2026-09-11  
> 状态：**P13 真实 Provider / 真实项目验收整改；高于 docs/28、docs/29 中与资产 continuity composition、wardrobe baseline、time-of-day baseline 冲突的旧口径。**  
> 验收证据：真实 REPLICA 项目已经完成 P13 Provider 调用、候选审核与正式 `TARGET_ASSETS` 发布；但本轮人工内容质量验收发现合同级问题，因此 **P13 尚未 PASS**。  
> 范围：只修 P13 Target Assets；不修改 P11/P12 已验收 Artifact，不准入 P14+。

---

## 1. 真实验收结论

本轮真实项目已经证明以下工程链路能够执行：

```text
CURRENT TARGET_BIBLE
→ real ProviderJob
→ Target Assets candidate
→ USER EXPLICIT ACCEPT
→ CURRENT TARGET_ASSETS
```

这证明真实 Provider / review gate / formal publication 路径可运行，但**不等于 P13 内容质量通过**。

人工核对正式资产后发现三个阻断问题：

1. 服务端在 Provider 中文审核门禁之后，把 P11 `TARGET_BIBLE.continuity_rules` 及 entity continuity rules 再次合并进每个 P13 asset packet，导致大量英文 Story Beat / shot order / cliffhanger / relationship / timing preservation rules 重复出现在人物、场景、道具的“连续性与生成约束”中；
2. Character `wardrobe_baseline` 出现按具体场景列出多套服装的逐场景换装设计，越过 P13 base identity 职责；
3. Scene `time_of_day_baseline` 根据剧情顺序自行推断“深夜 / 次日上午”等故事时间变化，而这些时间事实没有由 P13 唯一硬输入 CURRENT TARGET_BIBLE 明确给出。

因此本轮正式 rev 1 虽然由用户显式 ACCEPT 发布成功，但**不能作为 P13 最终人工验收 PASS 基线**。必须按本文新合同显式 regenerate 并重新人工审核。

## 2. 正式合同升级

本次不改变 typed schema 结构和 Target entity binding，因此：

```text
P13_SCHEMA_VERSION          = 1.0
P13_ENTITY_BINDING_CONTRACT = target-bible-entity-binding-v1
P13_REVIEW_CONTRACT         = human-target-asset-approval-v1
```

运行与内容合同升级为：

```text
P13_PROMPT_VERSION        = p13-replica-target-assets-v3
P13_TARGET_ASSET_CONTRACT = replica-target-visual-identity-v2
review_language_contract  = zh-cn-human-review-asset-local-visual-v2
```

`target_asset_id` 仍由 `project + asset_type + target_entity_id + entity_binding_contract` 稳定生成，因此本次升级不得制造第二套 Target identity。

## 3. continuity 的正式作用域

### 3.1 Target Bible continuity 仍是上游 truth，但不复制进 asset packet

P11 Target Bible 的：

```text
global continuity_rules
character.continuity_rules
scene.continuity_rules
prop.continuity_rules
preservation locks
story / beat / shot / timing rules
```

继续是正式上游语义边界，P13 Provider 不得违反。

但 P13 `Target*Asset.continuity_constraints[]` 的职责改为严格的：

```text
asset-local visual continuity only
```

例如：

```text
Character：脸型、发际线、主发型、身材比例、基础服装身份
Scene：空间拓扑、固定地标、材质、主光照身份
Prop：形态、尺寸、材质、颜色、标志性细节
```

服务端**不得**再把 Target Bible 的全局故事 / 镜头 /对白 / 节奏 preservation rules 确定性复制到每个 asset packet。

理由：

- 上游规则仍可通过 `target_bible_artifact_id` 和 Artifact Graph 追溯，不需要冗余复制；
- 故事锁、镜头顺序、Cliffhanger、人物关系不是单个视觉资产的 continuity；
- 重复复制会制造英文审核墙、数据膨胀和后续 Generation prompt 污染；
- Target Assets 应保持可被具体人物 / 场景 / 道具稳定引用的视觉身份，而不是另一个 Target Bible 副本。

---

## 4. Character wardrobe baseline 边界

`wardrobe_baseline` 只定义人物的**基础服装身份与风格边界**。

允许：

```text
基础轮廓
常用色系
材质倾向
正式度
饰品基线
跨镜不可随机漂移的识别特征
```

禁止 P13 自行生成：

```text
场景 1 穿 A
场景 2 穿 B
闪回穿 C
卧室穿 D
逐 Shot 换装表
```

除非 CURRENT TARGET_BIBLE 自身已经明确给出一项经过 P11 确认的服装 variation，否则 P13 不得根据剧情、Source 画面或 Target Script 猜测逐场景服装。

后续若生产确实需要 Scene / Shot wardrobe variation，应由后续正式 production contract 通过 base asset + explicit variation overlay 表达，不在 P13 偷偷实现。

---

## 5. Scene time-of-day baseline 边界

`time_of_day_baseline` 是**场景视觉基线**，不是剧情时间轴。

P13 可以描述：

```text
空间长期稳定的自然采光方向
人工照明类型
常态色温
不依赖剧情推断的环境光基线
```

P13 不得仅凭 Scene 顺序、闪回、情绪或常识推断：

```text
深夜
次日上午
数小时后
第二天清晨
```

如果 CURRENT TARGET_BIBLE 没有明确给出故事时段，则应使用不制造新剧情事实的表达，例如：

```text
该空间身份以暖柔室内光为稳定基线；具体 Shot 的昼夜与临时灯光变化由后续 Storyboard / Shot context 决定。
```

P13 不读取 TARGET_SCRIPT，也不能借 `time_of_day_baseline` 绕过这一硬输入边界。

## 6. 中文审核语言门禁扩展

`docs/29` 的中文审核规则继续有效，并增加：

- Provider 新生成的 asset-local continuity / generation guidance / negative constraints 必须中文优先；
- 服务端 composition 后不得再注入未经中文审核的英文 review-facing 规则；
- 专有名词 `Lila Xu / Austin / HEB / iPhone / $19.99` 可保留目标地区原文；
- Story Beat / shot order / dialogue / cliffhanger 等上游英文 preservation rules 不应出现在 P13 asset review packet 中。

## 7. 旧候选与旧正式资产处理

### 7.1 未审核候选

所有升级前仍为：

```text
NEEDS_REVIEW
```

的 P13 candidate 不能继续按旧合同接受：

```text
pre-v3 NEEDS_REVIEW
→ SUPERSEDED
```

迁移只处理待审核候选，不删除历史。

### 7.2 已确认正式资产

已 ACCEPTED 并发布的正式 `TARGET_ASSETS`：

- 不自动删除；
- 不在数据库迁移中静默改写 content；
- 不伪造新的用户确认；
- 仍保留 provenance / revision / Artifact Graph 历史。

但真实人工验收已经证明旧 `replica-target-visual-identity-v1` 内容不满足最终 P13 质量合同，因此它**不是 P13 PASS 基线**。

用户必须显式：

```text
重新生成候选
→ v3 Provider / visual-identity-v2
→ 人工审核
→ ACCEPT
→ 新 CURRENT TARGET_ASSETS revision
```

新 revision 应保持相同 Target entity 的稳定 `target_asset_id`，并只对视觉 packet 实际变化的 asset 增加 `target_asset_revision`。

9. pre-v3 `NEEDS_REVIEW` candidate 在迁移后为 `SUPERSEDED`；
10. ACCEPTED / REJECTED / SUPERSEDED 历史和正式 TARGET_ASSETS 不被迁移篡改；
11. GET 继续只读；
12. 没有创建任何 P14+ Artifact。
