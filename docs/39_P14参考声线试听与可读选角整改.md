# P14 参考声线试听与可读选角整改

> 日期：2026-09-12  
> 状态：P14 产品交互整改；本文对参考声线选择 UX 的规定优先于 `docs/33`、`docs/34` 中较早的目录/选择描述。  
> 本整改不改变阶段验收状态：`TTS = PLANNED / TIMING = PLANNED / P14 PASS = NO`。

## 1. 问题

当前默认 IndexTTS-2.5 工程声线目录来自上游官方 demo Reference Audio，文件以 `voice_01.wav`、`voice_02.wav` 等编号区分。上游没有为这些编号提供可作为产品事实使用的可信性别、年龄或音色风格元数据。

因此把普通产品 UI 做成：

```text
IndexTTS 示例声线 01
IndexTTS 示例声线 02
IndexTTS 示例声线 03
...
```

然后要求用户直接下拉选择，不具备可验收的可用性。

## 2. 禁止猜测声线属性

AI Drama Studio 不得根据文件编号、文件名、波形、音高、主观听感或人物剧情需求，自动给这些官方 demo Reference Audio 贴上“男声 / 女声 / 青年 / 老年 / 温柔 / 成熟”等未经来源确认的标签。

没有可信元数据时，正式展示固定为：

```text
官方未提供可信的性别、年龄或风格标签
```

用户通过真实试听做选择，而不是依赖系统猜测。

未来生产 Voice Catalog 可以增加人工维护的 `gender / age_range / style / locale / language / use_case` 等检索信息，但这些信息必须来自有权管理该参考声线的明确来源或人工标注流程，不能由本阶段静默推断。

## 3. 正式选择交互

P14 声线绑定改为：

```text
Target Character / unresolved utterance
→ 打开声线库
→ 每张声线卡片直接播放真实 Reference Audio
→ 用户试听
→ 显式“选用这个声线”
→ Target Voice Binding
```

普通用户不再面对无法理解的纯编号下拉框。

每个角色必须同时展示：

- 当前是否已选声线；
- 已选声线名称；
- 已选声线真实 Reference Audio 播放器；
- 更换声线入口；
- 声线库中每个候选的试听播放器；
- 有可信元数据时展示元数据，没有时明确显示“未提供”，不得补猜。

## 4. Reference Audio 试听 API

公共 Voice Catalog 继续不暴露底层 `reference_audio_url`。每个 public voice option 新增受控：

```text
preview_url
```

对应只读接口：

```text
GET /api/v3/projects/{project_id}/target-audio/voices/{voice_key}/preview
```

服务端用当前正式 Voice Catalog 解析 `voice_key`，读取对应 Reference Audio，再以 audio response 代理给浏览器。浏览器不知道原始 Reference URL。

该试听 GET：

- 不创建 Task；
- 不创建 ProviderJob；
- 不创建 Candidate；
- 不发布 Artifact；
- 不修改 voice binding；
- 不要求 IndexTTS 推理运行时 READY；
- 只负责读取已配置 Reference Audio 供人试听。

Reference Audio 的读取大小限制、content type 检查和失败关闭继续复用 P14 Provider 的现有媒体边界。

## 5. 默认官方 demo 的定位

上游官方 demo Reference Audio 继续只用于：

```text
工程联调
真实本地 TTS 链路验证
P14 人工预览
```

它们不是本项目正式生产声线资产，也不因为能试听就获得虚构的版权、人物身份、性别、年龄或风格元数据。

正式 P14 PASS 前，生产使用的目标声线仍应替换为具有明确使用授权的 Reference Audio，并由用户实际听审生成结果。

## 6. 历史残留清理

旧 OpenAI built-in voice catalog 模块属于 P14 Provider 决策前的历史工程残留，不再属于当前 IndexTTS-2.5 单 Provider 基线，应从当前代码路径与测试中删除，避免旧 `alloy / coral / marin` 等语义重新污染 P14。

## 7. 当前状态

本整改只提升声线选择可理解性和试听能力，不等于生成质量通过。

继续保持：

```text
P13 = PASS
TARGET_ASSETS = AVAILABLE
IndexTTS-2.5 runtime = engineering READY on validated local machine only
TTS = PLANNED
TIMING = PLANNED
P14 PASS = NO
```

仍需真实目标配音生成、真实 WAV、ffprobe、逐句听审、正式 TARGET_AUDIO、TIMING_PLAN 与全部 overflow 处理，并由用户明确 `P14 PASS` 后才允许升级能力状态。
