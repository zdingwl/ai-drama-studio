# 历史文档说明

> 本文用于防止旧规划、旧阶段名和旧验收记录继续干扰当前 Workflow V2 开发。

## 1. 当前正式文档

以后判断产品方向和开发规则，优先级固定为：

```text
1. docs/00_短剧重做系统开发总纲.md
2. docs/01_十个模块详细设计.md
3. docs/02_工作流V2技术实现规范.md
4. docs/03_当前项目状态与验收.md
5. 当前实际代码和测试
```

根目录：

- `README.md`：项目入口，只做简要介绍和文档导航；
- `AGENTS.md`：给开发代理/开发者的当前硬规则；
- `SKILL.md`：项目技能入口和规则索引。

`README.md / AGENTS.md / SKILL.md` 保留英文文件名，是因为这些名称属于仓库和开发工具的通用约定；文件内容使用中文，正式业务文档统一使用中文文件名。

## 2. 历史文档是什么

仓库中仍保留大量早期文档，例如：

- 旧 Character V4 / V9 / V10 方案；
- 旧 Breakdown / Fusion / G1 / G2 方案；
- 旧 Feature / P0 / P1 / P2 阶段设计；
- 历史性能测试和验收报告；
- Runtime 安装和诊断记录；
- 旧页面/接口设计草案。

这些文件仍然有价值，主要用于：

- 回归旧算法；
- 排查历史问题；
- 了解某段代码为什么这样实现；
- 保留测试和性能记录；
- 兼容旧数据。

但它们**不是当前产品流程真相**。

## 3. 历史文档不能覆盖的当前规则

无论旧文档写过什么，以下规则以当前正式文档为准：

- 产品主线是 10 个业务模块；
- 普通用户顶层页面只有 Project / Review Center / Output；
- SourceDramaSnapshot 是目标版本和生成流程唯一原片事实入口；
- 完整对白与 Shot 投影是 1:N，不能把跨 Shot 投影当成多条业务对白；
- LocalSubject / Track / Face 不等于 Final Character；
- 人物始终替换，场景按 KEEP / LOCALIZE / AUTO 决策；
- TTS 真实时长驱动 RemakeTimeline；
- Shot != GenerationSegment；
- GenerationAttempt != 可用镜头；
- 只有 GenerationSelection 能进入后期；
- 多脸口型必须先定位目标说话人；
- raw source audio 不得直接混入目标成片；
- 页面读取不能偷偷启动重任务；
- GET 不能写业务数据；
- 上游变化后旧下游结果必须失效为 STALE / SUPERSEDED；
- Runtime 离线不能伪装成人工内容问题。

## 4. 旧文档处理原则

不做一次性“大扫除式全删”，避免删掉仍被代码、脚本或回归测试引用的资料。

处理顺序：

1. 当前正式架构文档已经被新中文文档完整替代的，可以删除；
2. 历史算法方案暂保留；
3. 安装、Runtime、故障诊断、验收脚本说明暂保留；
4. 后续修改具体模块时，如果确认某份旧文档已经完全无引用、无回归价值，再删除；
5. 不为了“文件名统一”批量重命名历史文档，避免破坏仓库内已有链接和脚本引用。

## 5. 当前已被新文档替代的旧正式文档

## 6. 开发时怎么判断一份旧文档还能不能用

先问：

1. 它描述的是当前 10 个模块中的哪一个？
2. 它和 `00/01/02` 是否冲突？
3. 它是当前规则，还是历史实现记录？
4. 当前代码是否仍然引用它描述的数据结构/算法？
5. 删除后会不会影响安装、脚本、测试、回归或故障排查？

如果和当前正式文档冲突：

> 以当前正式文档为准，旧文档只做历史参考。

如果确认完全被替代且没有引用价值：

> 删除，而不是继续让它和新规则并存。
