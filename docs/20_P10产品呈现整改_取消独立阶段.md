# P10 产品呈现整改：取消独立阶段

> 日期：2026-09-10  
> 状态：产品呈现整改决定，优先级高于 `docs/18~19` 中“独立 P10 面板”的旧 UI 描述。  
> 背景：第一次真实页面验收时，`SOURCE_VIDEO_SNAPSHOT rev1` 已成功生成，但用户明确反馈“这个阶段的目的和输出看不懂”，并确认“不需要单独弄一个阶段，直接显示结果即可”。

---

# 1. 结论

`SourceVideoSnapshot` **保留为内部正式 Source 数据边界，但取消作为用户可见独立阶段。**

正式区分：

```text
P10 / source-video-snapshot
= Internal Engineering Slice / Professional Skill
= freeze / validate / publish
= 后续 Target 消费 Source 的版本边界

用户产品阶段
= 原片理解
= 直接展示 P5~P9 已得到的可读结果
```

普通用户不应看到一个新的：

```text
P10
SourceVideoSnapshot
Frozen Inputs
Artifact revision
fingerprint
provenance
DETERMINISTIC_FREEZE
```

大面板。

这些概念属于工程诊断和数据治理，不是用户业务结果。

---

# 2. 用户真正应该看到什么

原片理解结果继续直接展示现有正式内容：

```text
素材基线
整体剧情 / 故事背景 / 叙事结构
时间化剧情
Story / Rhythm
人物与人物关系
正式说话人归因
场景
关键道具
逐镜精细拉片
canonical 对白 / OCR（需要时查看）
```

P10 不复制这些结果再做一份“Snapshot 统计页”。

P10 只负责在这些结果背后回答：

```text
当前这一整套原片理解结果是否已经形成一个可供下游使用的正式版本？
```

---

# 3. 新的产品交互

在原片理解结果末尾只保留一个轻量状态条，不作为独立卡片阶段。

状态文案：

```text
NOT_BUILT
→ 当前原片分析结果尚未确认

CURRENT
→ 当前原片分析结果已确认

STALE
→ 原片分析结果已有更新，请重新确认
```

允许的主操作：

```text
确认当前原片分析结果
重新确认当前结果
```

操作仍对应显式：

```text
POST /api/v3/projects/{project_id}/commands/source-video-snapshot
```

页面打开 / 刷新继续只读，不能自动发布 Snapshot。

---

# 4. 技术信息的呈现规则

普通产品模式不展示：

- `SOURCE_VIDEO_SNAPSHOT` 名称；
- P10 编号；
- 11 个 frozen artifacts 清单；
- artifact id / revision；
- fingerprint；
- provenance；
- provider_jobs；
- Artifact Graph relations。

这些信息仍必须保留在：

- 后端 typed schema / domain；
- API；
- Artifact Graph；
- 自动测试；
- 开发 / 排障模式；
- 人工工程验收记录。

也就是说：**隐藏技术信息，不删除技术能力。**

---

# 5. Snapshot 后端契约保持不变

本次产品呈现整改不修改以下已完成能力：

```text
source-video-snapshot@1.0.0
p10-source-video-snapshot-v1
SOURCE_VIDEO_SNAPSHOT schema 1.0
frozen-accepted-source-facts-v1
DETERMINISTIC_FREEZE
```

继续冻结 11 个 CURRENT Source Artifact：

```text
SOURCE_VIDEO
SHOT_ANCHORS
SOURCE_DIALOGUE
SOURCE_BIBLE
STORY_SKELETON
RHYTHM_SKELETON
SOURCE_SHOT_FACTS
SOURCE_CHARACTERS
SOURCE_SPEAKERS
SOURCE_SCENES
SOURCE_PROPS
```

继续保持：

- `SOURCE_SPEAKERS` 独立；
- P5 时间只读；
- P6 canonical dialogue / OCR 只读；
- 不调用任何新模型；
- 不创建 ProviderJob；
- fingerprint / provenance / revision / CURRENT / STALE；
- 11 类上游任一新 revision 都使旧 Snapshot STALE；
- 相同 Source chain 显式 POST 幂等；
- GET 只读；
- Target / Production 不得反向写入 Source。

# 6. UI 整改要求

必须完成：

1. 从 `App.vue` 移除独立 `P10SourceVideoSnapshotPanel`；
2. 删除或停用该独立大面板实现与对应旧 UI 测试；
3. 新增轻量的“原片结果确认状态”组件；
4. 状态组件只能显示用户可理解的状态与确认动作；
5. 不重复显示 Episode / Shot / Dialogue / OCR / Character / Speaker / Scene / Prop 数量；
6. 不重复显示 P7/P8/P9 内容；
7. 不在主界面显示 frozen artifact / fingerprint / provenance；
8. CURRENT 时明确“当前原片分析结果已确认”；
9. STALE 时明确“结果已有更新，请重新确认”；
10. 点击确认才执行 POST，加载 / 刷新只做 GET。

# 7. 人工验收口径修正

第一次真实页面已经证明：

```text
SOURCE_VIDEO_SNAPSHOT rev1 = CURRENT
Episode = 1
Shots = 28
Dialogue = 54
OCR = 73
Characters = 3
Speakers = 3
Scenes = 3
Props = 4
ProviderJobs = 0
```

这些结果可以作为**后端冻结成功的真实证据**。

但旧独立 P10 面板本身被用户明确判定为产品表达不合格，因此：

```text
旧 P10 大面板 UI = REJECTED
内部 Snapshot 机制 = 保留
产品 UI = 必须整改后重新验收
```

整改后真实验收重点不再是“能否读懂 Snapshot 技术字段”，而是：

- 原片理解结果是否直接可读；
- 是否没有新增一个让用户困惑的 P10 阶段；
- 用户能否理解“当前结果已确认 / 有更新需重新确认”；
- 确认动作是否保持显式、幂等、可追溯；
- 上游变化后状态是否正确变为需重新确认。

---

# 8. Capability 状态

本次 UI 整改不等于 P10 最终人工验收完成。

在新产品呈现通过真实人工验收前仍保持：

```text
SOURCE_SNAPSHOT = PLANNED
Target / Production / Generation = PLANNED
```

不得因为内部 rev1 已生成就提前进入 Target。
