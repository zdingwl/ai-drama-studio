# P10 产品呈现整改：取消独立阶段

> 日期：2026-09-10  
> 状态：产品呈现整改决定并已实现。  
> 优先级：凡 `docs/01`、`docs/02`、`docs/04`、`docs/18`、`docs/19` 中仍把 P10 描述成普通用户独立大面板、要求用户读取 Snapshot 技术字段或在 CURRENT 状态反复“重新定稿”的旧 UI 描述，均由本文件替代。后端 P10 数据契约不变。  
> 背景：第一次真实页面验收时，`SOURCE_VIDEO_SNAPSHOT rev1` 已成功生成，但用户明确反馈“这个阶段的目的和输出看不懂”，并确认“不需要单独弄一个阶段，直接显示结果即可”。

---

# 1. 结论

`SourceVideoSnapshot` **保留为内部正式 Source 数据边界，但取消作为用户可见独立阶段。**

正式区分：

```text
P10 / source-video-snapshot
= Internal Engineering Slice / Professional Skill
= freeze / validate / publish
= 后续 Target 消费 Source 的版本边界

用户产品阶段
= 原片理解
= 直接展示 P5~P9 已得到的可读结果
```

普通用户不应看到一个新的：

```text
P10
SourceVideoSnapshot
Frozen Inputs
Artifact revision
fingerprint
provenance
DETERMINISTIC_FREEZE
```

大面板。

这些概念属于工程诊断和数据治理，不是用户业务结果。

---

# 2. 用户真正应该看到什么

原片理解结果继续直接展示现有正式内容：

```text
素材基线
整体剧情 / 故事背景 / 叙事结构
时间化剧情
Story / Rhythm
人物与人物关系
正式说话人归因
场景
关键道具
逐镜精细拉片
canonical 对白 / OCR（需要时查看）
```

P10 不复制这些结果再做一份“Snapshot 统计页”。

P10 只负责在这些结果背后回答：

```text
当前这一整套原片理解结果是否已经形成一个可供下游使用的正式版本？
```

---

# 3. 新的产品交互

在原片理解结果末尾只保留一个轻量状态条，不作为独立卡片阶段。

状态规则：

```text
NOT_BUILT
→ 当前原片分析结果尚未确认
→ 显示「确认当前原片分析结果」

CURRENT
→ 当前原片分析结果已确认
→ 纯状态提示，不显示额外确认/重新确认按钮

STALE
→ 原片分析结果已有更新，请重新确认
→ 显示「重新确认当前结果」
```

NOT_BUILT / STALE 的确认动作仍对应显式：

```text
POST /api/v3/projects/{project_id}/commands/source-video-snapshot
```

页面打开 / 刷新继续只读，不能自动发布 Snapshot。CURRENT 状态下不要求用户做重复无意义操作；相同 Source chain 的幂等能力继续由 API / 自动测试保障。

# 4. 技术信息的呈现规则

普通产品模式不展示：

- `SOURCE_VIDEO_SNAPSHOT` 名称；
- P10 编号；
- 11 个 frozen artifacts 清单；
- artifact id / revision；
- fingerprint；
- provenance；
- provider_jobs；
- Artifact Graph relations。

这些信息仍必须保留在：

- 后端 typed schema / domain；
- API；
- Artifact Graph；
- 自动测试；
- 开发 / 排障模式；
- 人工工程验收记录。

也就是说：**隐藏技术信息，不删除技术能力。**

本次产品呈现整改不修改以下已完成能力：

```text
SOURCE_VIDEO_SNAPSHOT schema 1.0
frozen-accepted-source-facts-v1
```

```text

SOURCE_BIBLE
STORY_SKELETON
RHYTHM_SKELETON
SOURCE_SHOT_FACTS
SOURCE_CHARACTERS
SOURCE_SPEAKERS
SOURCE_SCENES
```

继续保持：

- `SOURCE_SPEAKERS` 独立；
- P5 时间只读；

- Target / Production 不得反向写入 Source。

# 8. 修正后的真实人工验收重点

不再要求用户阅读 Snapshot 技术字段，也不要求在 CURRENT 状态点击无意义的“重新定稿”。

下一次真实页面验收只需要确认：

- 页面不再出现独立 P10 / SourceVideoSnapshot 大面板；
- 原有剧情、人物、场景、道具、对白、分镜等结果直接可见；
- 当前已有 rev1 时，仅出现轻量“当前原片分析结果已确认”状态；
- CURRENT 状态没有额外确认按钮；
- 若上游 Source 结果产生新 revision，状态变为“原片分析结果已有更新，请重新确认”；
- STALE 时只有用户显式点击重新确认才发布新 Snapshot；
- 重新确认后状态恢复“已确认”，技术上的旧 rev / 新 rev / SUPERSEDES / provenance 由工程接口和自动测试核验。

这是 Product Stage 与 Internal Engineering Slice 分离的正式口径。
