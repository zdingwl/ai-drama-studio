# P14 声线分类筛选与选角效率整改

> 日期：2026-09-12  
> 状态：P14 Voice Catalog 产品交互整改；本文补充 `docs/40_P14可编辑VoiceCatalog元数据与人工命名整改.md`。  
> 本整改不改变阶段验收状态：`TTS = PLANNED / TIMING = PLANNED / P14 PASS = NO`。

## 1. 问题

当 Voice Catalog 从十几条扩展到几十、上百条后，仅有“可读名称 + 试听”仍不足以快速选角。用户需要先缩小候选范围，再试听，而不是每次滚动完整声线库。

分类筛选必须基于已有可信元数据，不得为了方便筛选自动推断性别、年龄或风格。

## 2. 正式分类维度

P14 声线库新增统一分类筛选：

```text
关键词
性别
年龄感
风格标签
语言 / 地区
人工标注状态
```

其中：

- 性别、年龄感、风格来自 `indextts_voice_metadata` 的人工标注；
- 语言 / 地区来自 Voice Catalog 已有 `locale`；
- 标注状态分为 `全部 / 已人工标注 / 未标注 / 需重新标注`；
- 关键词搜索覆盖可读名称、原始目录名、voice_key、风格、备注、locale 与目录标签；
- 多个分类条件采用 AND 组合，即同时满足才显示。

## 3. 禁止自动分类猜测

以下行为继续禁止：

```text
根据音高猜性别
根据角色性别反推声线性别
根据文件编号猜年龄
用模型静默生成“温柔 / 霸总 / 少女”等标签
```

未标注声线必须保留为未标注；Reference Audio 变化导致人工标签失效时必须进入“需重新标注”。

## 4. 同一筛选作用于两个场景

分类筛选不是只用于声线库管理，而是同时作用于：

```text
声线库管理卡片
角色 / 未绑定对白的声线选择卡片
```

例如用户选择：

```text
女声 + 青年 + 温柔 + 已人工标注
```

则声线库和所有角色选角弹层都只展示同一批匹配候选。

已经绑定给角色的声线不因为后续筛选条件变化而自动解除；筛选只改变候选展示，不修改正式 binding。

## 5. 产品交互

筛选区固定显示：

```text
分类筛选
搜索 [名称 / voice_key / 风格 / 备注]
性别 [全部 / 女 / 男 / 中性 / 未标注]
年龄感 [全部 / 儿童 / 青少年 / 青年 / 成年 / 成熟 / 老年 / 未标注]
风格 [根据人工 style_tags 动态生成]
语言 / 地区 [根据目录 locale 动态生成]
标注状态 [全部 / 已标注 / 未标注 / 需重新标注]
清空筛选
结果数 X / 总数 Y
```

没有匹配结果时必须明确提示调整筛选或先补人工标签，不能显示空白区域。

## 6. 工程边界

本整改不新增数据库字段，也不修改 TTS Provider 合同。分类完全消费 `docs/40` 已建立的 Voice Catalog 元数据。

新增前端纯函数：

```text
collectVoiceFilterOptions
filterVoices
```

并用单元测试覆盖：

- 性别 + 年龄 + 风格组合筛选；
- 名称 / voice_key / 备注搜索；
- 已标注 / 未标注 / stale 分类；
- style / locale 动态分类项收集。

## 7. 当前状态

该整改只提升大规模声线库的检索和选角效率，不代表声音质量验收通过。

继续保持：

```text
P13 = PASS
TARGET_ASSETS = AVAILABLE
TTS = PLANNED
TIMING = PLANNED
P14 PASS = NO
```
