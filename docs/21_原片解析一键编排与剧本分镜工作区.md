# 原片解析一键编排与剧本 / 分镜工作区

> 日期：2026-09-10  
> 状态：产品流程整改设计基线。  
> 优先级：高于此前把 P5~P10 暴露为普通用户独立操作的 UI 描述。  

---

# 1. 产品结论

视频类项目（REPLICA / REDRAW / TRANSLATION）的普通用户流程统一收口为：

```text
上传完整原片
↓
解析原片（一次显式操作）
↓
原片剧本 + 分镜 + 人物 / 场景 / 道具
↓
直接进入后续修改
```

P5 / P6 / P7 / P8 / P9 / P10 继续存在，但全部属于内部工程切片，不再作为普通用户逐项点击的业务阶段。

复杂度属于系统，不属于用户。

---

# 2. 一次“解析原片”内部执行图

```text
完整 SOURCE_VIDEO
├─ P5 Shot Anchors
└─ P6 Canonical Dialogue / OCR
        ↓
P7 Whole-Episode Understanding + Story / Rhythm
        ↓
P8 Shot Breakdown
        ↓
P9 Character / Speaker / Scene / Prop Resolution
        ↓
P10 deterministic Source Snapshot publication
        ↓
原片剧本 / 分镜工作区
```

硬规则保持不变：

- 完整 Episode 永远是 Source Truth；
- P5 与 P6 都直接读取完整 Episode；
- P6 ASR 不能按 Shot 分段识别再拼接；
- P7 必须建立整集上下文；
- P8 不能每 Shot 独立猜整集故事；
- P9 必须做跨 Shot 全局归一；
- P10 不重新调用模型；
- GET / 页面刷新不启动任何重任务；
- 只有用户显式点击“解析原片”才允许创建 / 继续需要的分析任务；
- 每个已有 CURRENT 子结果都允许幂等复用，不能为了“看起来在执行”重复付费分析。

---

# 3. 普通用户界面

普通模式只显示：

```text
原片
[上传 / 追加]
[解析原片]

解析中：正在理解原片 63%

完成后：
[原片剧本] [分镜] [人物资产]
```

普通模式禁止把以下内容作为独立工作卡堆给用户：

```text
P5
P6
P7
P8
P9
P10
Artifact
ProviderJob
Fingerprint
Provenance
Frozen Inputs
SourceVideoSnapshot
```

这些只进入开发 / 诊断模式。

---

# 4. 原片剧本不是新一轮生成

“原片剧本”首先应是已有正式 Source Facts 的确定性可读视图，不额外让模型自由改写 Source Truth。

组合来源：

```text
P9 Scene Assignment
+ P9 Speaker Attribution / Character
+ P8 Shot visual_description / camera language
+ P6 canonical dialogue
```

按连续 Scene Assignment 自动形成场次：

```text
场 1 · 王桂香家客厅
动作描述……
王桂香：……

场 2 · 居民楼公共楼道
动作描述……
……
```

如果同一 Scene 后续再次出现，应形成新的场次段落，而不是把不连续的镜头强行并到同一段。

剧本视图必须保留到 Shot / utterance 的可追溯引用，但普通模式不展示内部 artifact id。

---

# 5. 分镜视图

每个场次下面直接关联原片正式 Shot：

```text
场 2 · 居民楼公共楼道
#002  00:03.20-00:04.60  中景  ……
#003  00:04.60-00:06.10  近景  ……
...
```

用户可直接进入“修改分镜”。

Source Truth 与用户改稿必须分层：

```text
原片分镜事实 = SOURCE_SHOT_FACTS，只读
用户修改版本 = 编辑草稿 / 后续 Target Draft
```

任何编辑都不得反写覆盖 P5/P6/P7/P8/P9/P10 Source Facts。

在正式 Target Storyboard 能力接入前，UI 可以先提供明确标识为“编辑草稿”的持久化工作副本，但不得伪装成正式 TARGET_STORYBOARD Artifact。

---

# 6. 一键编排要求

新增产品级“原片解析” orchestration：

1. 显式 POST 创建一个顶层原片解析任务；
2. 后台检查当前 Source Artifact 状态；
3. 只执行缺失 / STALE 的内部步骤；
4. P5/P6 按 Episode 运行；
5. P7 在 P6 CURRENT 后运行；
6. P8 在 P7 + P5 CURRENT 后运行；
7. P9 在 P8 CURRENT 后运行；
8. 最后确定性发布 P10 Snapshot；
9. 顶层任务统一汇总进度和失败原因；
10. 子任务继续保留原有 Task / ProviderJob / revision / fingerprint / provenance 审计；
11. 同一完整 Source chain 重复点击必须幂等复用；
12. 任何子任务失败时顶层任务 fail closed，不伪造“解析完成”。

---

# 7. 状态语义

普通模式只暴露四类状态：

```text
未解析
解析中
解析完成
结果有更新，需要重新解析
```

内部可继续使用：

```text
NOT_BUILT / CURRENT / STALE
Task queued / running / succeeded / failed
```

但不要求普通用户理解这些工程词汇。

---

# 8. 当前实施边界

本轮只做：

- 产品级一键原片解析编排；
- 普通模式隐藏 P5~P10 独立操作面板；
- 从现有 Source Facts 生成可读的场次剧本视图；
- 场次下直接展示正式 Shot 分镜；
- 为“直接改分镜”预留与 Source Truth 隔离的编辑草稿入口；
- 开发 / 诊断模式继续保留已有 P5~P10 验收面板。

本轮不进入：

- 本土化改写；
- Target Bible；
- 正式 Target Script；
- 正式 TARGET_STORYBOARD；
- 视频生成。

`SOURCE_SNAPSHOT` 在新的产品呈现完成真实人工验收前继续保持 `PLANNED`。
