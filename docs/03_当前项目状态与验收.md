# 3. 当前 Speaker 根因已经确认

当前 `breakdown_scene_timeline_assembler_v1.py`：

- canonical dialogue 只接受 ASR-origin DIALOGUE；
- Speaker 只读取 event participants 中已有的 `role=SPEAKER`；
- assembler 自己不做真正音视频 Speaker 识别。

当前 `source_dialogue_speaker_resolver_v1.py`：

- 使用 explicit speaker；
- Final Character 归属；
- 当前 Shot/Scene 唯一人物；
- performance people；
- 前后对白 continuity；

做纯规则自动推断。

因此当前主要问题不是“整个程序没有 Speaker 字段”，而是：

> **缺少真正的 audio-visual speaker attribution 证据层。**

新方案：

```text
D-ORCA
  ↓
speaker visual/audio evidence
  ↓
Character V10.1 identity normalization
  ↓
DialogueSpeakerBinding
  ↓
旧 rule resolver 仅 fallback
```

# 4. Source Screenplay V2 当前真实状态

当前已有：

`engine/app/source_screenplay_runtime_v2.py`

已经落实以下重要边界：

- SourceDramaSnapshot 保持不可变；
- Episode Understanding 会真正参与剧本动作组织；
- 相邻 Shot 的重复动作可合并成可读 ACTION；
- canonical source dialogue 正文不由 screenplay model 生成；
- 每条 canonical dialogue 恰好插入一次；
- Scene 顺序必须与当前 source facts 一致；
- GET 只读取 materialized artifact；
- compile 必须显式 POST / task。

这部分方向正确，**不需要因为改 Qwen3.8 + D-ORCA 推倒重写。**

下一步主要提升它的上游事实质量：

```text
更强 Qwen3.8 visual/story facts
+
更准 D-ORCA speaker attribution
↓
更可靠 SourceDramaSnapshot
↓
更可靠 Source Screenplay
```

## 新规则

后续要改成：

```text
低 confidence / 内容歧义
→ 自动选择当前最佳结果
→ 保存 resolution metadata
→ 继续
```

而不是：

```text
低 confidence
→ BLOCKED_REVIEW
→ 用户逐项点确认
```

现有 Review UI 暂时保留，用于：

- 用户主动纠错；
- 历史数据兼容；
- 高级诊断。

不应该再控制普通内容是否可消费。
