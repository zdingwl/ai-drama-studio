# 短剧重做系统开发总纲

> 这是当前项目最高层的业务说明。
>
> 这份文档只回答三个问题：**系统要做什么、每一步产出什么、下一步拿这些数据干什么。**
>
> 数据库、接口、任务状态、fingerprint、revision 等技术细节统一放到《02_工作流V2技术实现规范.md》。

## 1. 项目最终要做什么

给系统一部已经拍好的短剧，系统先看懂原短剧，然后按照项目选择的**目标语言、目标地区和场景策略**，重新生成一部适合目标地区的新短剧。

新短剧可以沿用原片的：

- 剧情走向；
- 人物动作；
- 表演意图；
- 镜头构图；
- 运镜；
- 剪辑节奏；
- 原镜头作为 Reference Video。

但目标版本需要重新处理：

- 人物：必须变成目标版本人物；
- 台词：翻译并本土化到目标语言；
- 声音：使用目标人物声音；
- 口型：对应目标语言最终音频；
- 场景：根据项目策略 KEEP / LOCALIZE；
- 时间：不能硬套原片时长，要根据目标语言真实说话时间调整；
- 最终视频：使用本地 MiniMax H3 重新生成，再经过质检、口型、音频、字幕和拼接形成整集。

## 2. 完整流程：只记住这 10 步

| 步骤 | 大白话说明 | 最终得到什么 | 后面拿来干什么 |
|---|---|---|---|
| 1. 创建项目 | 导入短剧，告诉系统要做成哪个国家、哪种语言 | 原片、剧集顺序、源语言、目标语言、目标地区、场景策略 | 决定后面翻译、人物风格、场景本土化方向 |
| 2. 拆分原片 | 读取视频并切成一个个镜头 | 视频信息、每个镜头起止时间、缩略图、Reference Clip | 后续识别、生成、字幕、剪辑都依赖这些时间和参考片段 |
| 3. 看懂原片 | 分析每个场景和镜头到底发生了什么 | 剧情、场景、人物、动作、表演、运镜、对白、画面文字、道具 | 作为后面重拍剧情、动作、镜头和表演依据 |
| 4. 整理原片人物和场景 | 把不同镜头里看到的同一个人、同一个场景统一起来 | Final Character、Final Scene、Final Prop、镜头人物绑定、说话人绑定 | 确定谁是谁、谁说哪句话、哪些内容需要替换 |
| 5. 固化原片事实 | 把确认后的原片资料保存成一份唯一可信版本 | SourceDramaSnapshot 和版本信息 | 后续本土化、翻译、H3 生成只能以这份正式数据为准 |
| 6. 设计目标版本 | 设计出海后的新人物、新场景和声音 | TargetCharacter、目标姓名/外貌/参考图、场景 KEEP/LOCALIZE、目标场景、VoiceProfile | H3 用它生成人物和场景，TTS 用它生成角色声音 |
| 7. 生成目标对白和声音 | 翻译、本土化并真正生成配音 | 最终目标台词、目标说话人、声音文件、真实说话时长、情绪信息 | 用于新时间轴、口型、字幕和最终音轨 |
| 8. 重排时间并准备生成 | 根据目标语言真实说话时长重新安排镜头 | RemakeTimeline、对白位置、GenerationSegment、H3 生成条件 | 告诉 H3 每次生成什么、生成多长、参考哪个原镜头 |
| 9. H3 重拍与质检 | 用 H3 重新生成镜头，自动检查，不合格就安全重试 | GenerationAttempt、QC 结果、GenerationSelection | 只有最终选中的镜头版本才能进入后期 |
| 10. 后期和成片 | 做口型、目标音轨、字幕、背景音、拼接并验收 | 最终 MP4、SRT、成片版本、验收结果 | 播放、下载和商业交付 |

## 3. 一句话看懂数据怎么流

```text
原短剧
  ↓
拆成镜头
  ↓
看懂每个镜头
  ↓
确认原片人物 / 场景 / 台词 / 说话人
  ↓
SourceDramaSnapshot（原片正式事实）
  ↓
设计海外版人物 / 场景 / 声音
  ↓
翻译台词 + 生成目标语音
  ↓
根据真实说话时长重排时间
  ↓
生成 H3 任务片段
  ↓
H3 重拍 + 自动质检 + 选版
  ↓
口型 + 目标音轨 + 字幕 + 安全背景音
  ↓
整集拼接 + 人工验收
  ↓
海外版完整短剧
```

## 4. 普通用户只需要 3 个页面

### Project（项目）

负责从“导入原片”一直准备到“可以开始 H3”。

普通用户在这里关心：

- 项目和 Episode；
- 原片是否已经看懂；
- 人物/场景是否确认；
- 目标人物/场景是否设计好；
- 目标对白/声音是否准备好；
- 时间轴和生成计划是否准备好。

ASR、OCR、VLM、Tracking、GenerationSegment 等内部技术结果默认不做顶层页面。

### Review Center（待确认）

只做一件事：**处理系统自己不敢安全决定的问题。**

例如：

- 这个女人到底是哪一个正式人物；
- 这句台词到底是谁说的；
- 这个场景应该保留还是本土化；
- 一句目标语言台词太长，应该延长镜头还是跨到反应镜；
- H3 连续生成失败，系统无法安全选择版本；
- 多人镜头无法确认应该给谁做口型。

同一个根问题只让用户确认一次，不能把一个人物问题扩散成几十条对白待办。

### Output（成片）

负责：

- 开始 H3 重拍；
- 查看 H3 生成进度；
- 自动质检和重试；
- 选择可用版本；
- 开始口型和后期；
- 播放最终成片；
- 下载 MP4 / SRT；
- 人工接受或驳回最终版本。

## 5. 最重要的业务规则

这些规则后续开发不能随意改变：

1. **先看懂原片，再设计目标版本，再生成。**
2. **SourceDramaSnapshot 是后续唯一的原片正式事实入口。**
3. **识别到一个人，不等于已经确认成正式人物。** LocalSubject / Track / Face 都不能直接当 Final Character。
4. **人物始终替换；场景按 KEEP / LOCALIZE / AUTO 决定。**
5. **目标对白先生成真实语音，再根据真实语音时长重排时间。**
6. **Shot 不等于 GenerationSegment。** 原片镜头是导演/剪辑单位，GenerationSegment 是 H3 实际生成单位。
7. **H3 生成成功不等于镜头可用。** 必须经过 QC，只有 GenerationSelection 可以进入后期。
8. **多人镜头做口型前必须先确认目标说话人。**
9. **原片原始音轨不能直接混入目标成片。** 可以安全复用的背景音必须先分离并再次抑制原语言对白。
10. **自动工作在后台执行，不要为每个算法单独做页面。**
11. **页面打开、刷新、切换页面只能读取状态，不能偷偷启动重任务。**
12. **模型离线是运行环境问题，不是假装成人工内容问题。**

## 6. 后续开发怎么使用这份总纲

开发任何功能前先回答：

1. 它属于上面的第几步？
2. 输入是什么？
3. 自动处理什么？
4. 什么情况下需要人工确认？
5. 最终输出什么正式数据？
6. 下一步具体读取这些数据做什么？
7. 什么条件下才算这个模块真的完成？

如果一个功能无法明确回答这些问题，先不要继续增加代码，先确认它是否真的属于当前产品主线。
