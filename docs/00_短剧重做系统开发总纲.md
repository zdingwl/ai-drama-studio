# 短剧重做系统开发总纲

> 当前最高优先级业务总纲。更新时间：2026-09-08。
>
> 核心目标：输入一部已经完成的短剧，先真正看懂原片，再按照目标语言、目标地区和场景策略，用 MiniMax H3 重做一部本土化版本。

---

## 1. 最重要的流程原则

从 2026-09-08 起，原片理解顺序正式改为：

```text
导入完整 Episode
  ↓
媒体检查 / 时间基准
  ↓
Shot Boundary / Reference Clip
（这里只建立时间锚点，不代表已经做逐镜语义拉片）
  ↓
ASR + OCR
（保留原对白文字、字幕和时间证据）
  ↓
Gemini 3.1 Pro Preview
【先做整集理解】
  ├─ 原片剧情 / 剧本结构
  ├─ Story Beats / 关键事件
  ├─ 角色候选
  ├─ 角色关系
  ├─ 场景候选
  ├─ 关键道具候选
  ├─ 世界背景
  └─ 时间范围
  ↓
Source Episode Intelligence / Source Bible
  ↓
Qwen3.8-27B
【再做逐镜拉片】
  ├─ 当前镜头出现的人物候选
  ├─ 当前场景 / 道具对应
  ├─ 动作 / 表情 / 姿态 / 视线 / 互动 / 站位
  ├─ 景别 / 机位 / 构图 / 运镜 / 光线
  ├─ 当前镜头剧情作用
  └─ 连续性
  ↓
D-ORCA + Character V10.1 + Scene/Prop normalization
  ↓
SourceDramaSnapshot
```

### 为什么 Shot Boundary 可以提前存在

Shot Boundary 只是视频时间锚点和 Reference Clip 的切分依据。它可以在整集理解之前建立，因为 Gemini、ASR/OCR 和后续逐镜分析都需要准确时间范围。

但是：

> **建立 Shot Boundary != 做逐镜拉片。**

禁止再采用下面的旧业务逻辑：

```text
先让模型逐 Shot 猜人物/场景/道具
→ 最后再把几十个 Shot 拼成剧情和剧本
```

正式业务顺序必须是：

```text
先看懂整集
→ 先知道这部戏讲什么、有哪些人、有哪些场景和关键道具
→ 再拿这些全局知识去逐镜分析导演怎么拍
```

## 2. 模型职责

### Gemini 3.1 Pro Preview：整片理解主模型

当前模型 ID：

```text
gemini-3.1-pro-preview
```

它负责完整 Episode 的第一遍全局理解：

- Episode Summary；
- Source World；
- Story Beats；
- 角色候选与角色关系；
- 场景候选；
- 关键道具候选；
- Script Scene 结构；
- Key Events；
- 跨镜、长程剧情关系。

Gemini 可以看完整视频和原音，同时接收 ASR/OCR 文字与时间证据。

**Gemini 不拥有 canonical source dialogue。**

它可以利用对白理解剧情，但不能改写、翻译、润色或凭空补写正式源对白。正式源对白正文和时间仍由 ASR/OCR evidence + reconcile 层拥有。

### Qwen3.8-27B：第二遍逐镜导演/视觉理解

Qwen3.8 不再负责从几十个孤立 Shot 中反推整集故事。

它必须在 Gemini Source Bible 已经 READY 后运行，并消费这份上游上下文，重点补充每个 Shot 的：

- 当前可见人物；
- 动作；
- 表情；
- 姿态；
- 视线；
- 互动；
- Blocking；
- 场景/道具可见事实；
- Shot Type；
- Camera Angle；
- Composition；
- Camera Motion；
- Lighting；
- Continuity；
- Narrative Function。

当前 Shot 看不到的事实不能因为 Source Bible 里存在就伪造成当前镜头可见事实。

### ASR / OCR

负责：

- 原始对白文字；
- 原始字幕/画面文字；
- 时间证据；
- SourceDialogueUtterance 候选。

原始 evidence 不就地改写。

### D-ORCA 8B

主要负责：

```text
WHEN：什么时候说
WHO：谁说
WHAT：作为校验证据，不覆盖 canonical text
```

### Character V10.1

负责跨镜身份归并。

Gemini 的 `character_key` 只是全局人物候选，不等于 Final Character ID；Qwen 当前镜头里的匿名人物也不等于 Final Character。Character V10.1 仍负责把视觉证据安全归一到正式 Source Character。

## 3. 原片必须得到两类正式结果

### Source Script

面向剧情和用户阅读：

- Scene Heading；
- 剧情动作；
- 人物关系；
- 完整 canonical dialogue；
- Speaker；
- 关键剧情道具；
- Story Beats；
- 剧情节奏。

### Source Directing Reference

面向后续复刻生成：

- Source Shot 起止时间；
- Reference Clip；
- 当前人物；
- 动作 / 表演；
- Blocking；
- 表情 / 姿态 / 视线 / 互动；
- 景别；
- 机位；
- 构图；
- 运镜；
- 光线；
- 场景；
- 道具；
- 连续性；
- 剪辑关系。

二者最终都必须能够从 current `SourceDramaSnapshot` 追溯，不允许后续模块直接绕过 Snapshot 拼 raw ASR、raw OCR、Gemini raw JSON、Track ID 或 Qwen raw response。

---

## 4. SourceDramaSnapshot 仍是硬边界

```text
原片 evidence
  ↓
Episode Intelligence
  +
逐镜 Directing Facts
  +
Dialogue / Speaker / Character / Scene / Prop normalization
  ↓
SourceDramaSnapshot
  ↓
Target / Timeline / H3 / Post
```

模块 6—10 只能消费 current + ready 的 SourceDramaSnapshot。

必须继续保持：

- Source != Target；
- Source Character != TargetCharacter；
- Source Scene != Target Scene；
- Source Prop != Target Prop；
- LocalSubject / Track / Face != Final Character；
- 一条完整 SourceDialogueUtterance 可以 1:N 投影到多个 Shot；
- 一条跨 Shot 对白不能因为切镜变成多条独立业务对白；
- 上游 revision/fingerprint 改变后，下游必须 STALE。

## 5. 完整产品流程

```text
1 创建项目
  ↓
2 导入 / 排序 Episode + 媒体预处理
  ↓
3 建立 Shot 时间锚点 / Reference Clip
  ↓
4 整片理解
  ASR/OCR → Gemini 3.1 Pro → Source Bible
  ↓
5 逐镜拉片 + 人物/场景/道具归一
  Qwen3.8 → D-ORCA → Character V10.1 → SourceDramaSnapshot
  ↓
6 目标世界 / 目标人物 / 目标场景 / 目标关键道具 / Voice
  ↓
7 目标对白 → Qwen3-TTS → 真实语音时长
  ↓
8 Replica Storyboard / RemakeTimeline / GenerationSegment
  ↓
9 MiniMax H3 → QC → Retry → Selection
  ↓
10 Lip Sync / 音轨 / 字幕 / 拼接 → EpisodeOutput
```

用户不需要理解内部模型名字。普通页面只展示真正有用的业务结果。

## 6. 出海本地化原则

后续目标版本不是简单翻译。

系统需要保留原片：

- 剧情冲突；
- 关键反转；
- 动作关系；
- 表演关系；
- 镜头语言；
- 节奏和导演意图。

然后根据目标语言/地区替换或调整：

- 人物身份；
- 人物外形；
- 服装；
- 场景；
- 关键道具；
- 社会制度/文化环境；
- 画面文字；
- 台词表达；
- Voice。

目标侧所有资产必须受统一 Target World 约束，避免人物、场景、道具各自本地化后不属于同一个世界。

---

## 7. 多语言时长规则

目标对白顺序固定：

```text
完整源对白
→ 翻译
→ 本地化
→ 最终目标台词
→ 目标 Speaker / Voice
→ TTS
→ 真实语音时长
→ RemakeTimeline
→ GenerationSegment
```

禁止先猜目标语言时长再排最终时间轴。

允许的逐镜时间策略包括：

```text
KEEP
TRIM
CARRY_OVER_REACTION
EXTEND
REWRITE_SHORTER
HUMAN_REVIEW
```

禁止用全局不自然语速或整体慢放视频硬解决语言时长差异。

Shot、Target Storyboard Shot、GenerationSegment 必须保持不同概念。

---

## 8. H3 与后期硬规则

```text
Shot != GenerationSegment
GenerationAttempt != 可用镜头
GenerationSelection = 当前正式可用版本指针
```

MiniMax H3 输入可使用 Source Reference Clip 作为动作、表演、构图和运镜参考，但源语言音轨必须移除。

H3 技术生成成功后仍需要：

```text
ffprobe
→ 完整 decode
→ 时长门禁
→ 语义 QC
→ PASS / RETRY / REVIEW
```

只有 GenerationSelection 可以进入后期。

raw source audio 永远不能直接混入目标成片。

---

## 9. 自动化与人工纠错

默认自动完成。

普通低置信度不应成为强制人工门禁；系统保存 confidence / provenance / method 后选择当前最佳结果继续。

真正阻塞主要来自：

- 文件损坏；
- 必需媒体缺失；
- Gemini / 本地模型 Runtime 不可用；
- 输出 schema 损坏；
- revision 已过期；
- 必需生成文件不可消费；
- H3 / Lip Sync 等结构性质量失败。

人工页面只负责容易出错、确实值得用户修改的结果，不给 ASR/OCR/VLM/Track/fingerprint 等内部证据单独做顶级页面。

---

## 10. API / Task 硬规则

页面打开、刷新、切 Tab/Route：

```text
只读
```

GET 不能：

- 写数据库；
- 建任务；
- 调 Gemini；
- 启动本地模型；
- 自动进入下一重阶段；
- 隐式重算。

重任务只能由用户明确动作启动。

Gemini 属于外部计费 Provider。远程请求前必须先持久化本地 provider-job 记录，并保存：

- capability/scope；
- provider/model；
- payload/input fingerprint；
- status；
- attempt；
- 更新时间；
- 非敏感错误类型。

API key 只从运行环境读取，禁止写入 DB、artifact、日志或 Git。

当前环境变量：

```text
GEMINI_API_KEY
# 或
GOOGLE_API_KEY
```

没有 key 时整片理解应明确进入未配置/运行依赖状态；**禁止偷偷降级到小模型并继续逐镜拉片。**

## 11. 当前模型组合

```text
完整 Episode 整片理解：Gemini 3.1 Pro Preview
原对白/时间：faster-whisper + OCR reconciliation
逐镜视觉/导演事实：Qwen3.8-27B
Speaker Attribution：D-ORCA 8B
跨镜人物身份：Character V10.1
目标语音：Qwen3-TTS
最终视频：MiniMax H3
口型：LatentSync
```

模型可以以后替换，但业务边界不能再倒回“先逐镜猜、后拼整集”。

---

## 12. 开发验收分层

任何“完成”必须分开记录：

1. 代码实现；
2. 自动测试 / CI；
3. Gemini 真实 API + 完整 Episode 验收；
4. 本地 Qwen/D-ORCA 等真实模型验收；
5. 真实项目端到端验收；
6. 用户看/听最终短剧验收。

其中任意一层通过，都不能冒充后面的层已经通过。
