# 短剧重做系统开发总纲

> 这是当前项目最高层、最高优先级的业务说明。
>
> 本文只回答：**系统最终要做什么、主流程怎么走、每一步保留什么正式结果、哪些事情可以自动完成。**
>
> 数据库、接口、任务、fingerprint、revision、Provider 契约统一看 `02_工作流V2技术实现规范.md`。
>
> **2026-09-07 起，本项目采用“默认全自动，人工只做可选纠错”的产品原则。历史文档里“低置信度/身份不确定/说话人不确定必须人工确认后才能继续”的描述全部废止。**

---

## 1. 项目最终要做什么

给系统一部已经拍好的短剧，系统先完整理解原片，再按照项目选择的**目标语言、目标地区和场景策略**，重新生成一部适合目标地区的新短剧。

目标不是只“翻译台词”，也不是只“还原剧本”。系统必须同时理解并保留两层原片信息：

```text
原视频
  ↓
完整视频理解
  ├─ Source Script（剧情层）
  │  场次 / 剧情 / 人物关系 / 完整对白 / 谁说话
  │
  └─ Source Directing Reference（导演层）
     人物动作 / 表情 / 站位 / 互动
     景别 / 机位 / 构图 / 运镜 / 光线
     场景 / 道具 / 镜头时长 / 剪辑关系
```

用户主要查看和修改的是**原剧剧本**；导演级镜头信息继续完整保存在后台，后续生成目标分镜和 H3 视频时使用，不能因为做了剧本还原就丢掉。

## 2. 原片理解主技术路线

当前目标主链固定为：

```text
原视频
  ↓
Shot / Reference Clip / 时间基准
  ↓
Qwen3.8-27B
  ├─ 人物与可见关系
  ├─ 动作 / 表情 / 互动 / 站位
  ├─ 场景 / 道具 / 画面事件
  ├─ 景别 / 机位 / 构图 / 运镜基础理解
  └─ 跨镜事件 / 整集剧情理解

D-ORCA 8B
  ├─ WHEN：什么时候说
  ├─ WHO：谁说
  └─ WHAT：说了什么 / 音视频对齐证据

ASR / OCR
  ├─ 保留源对白文字与源时间证据
  └─ 与 D-ORCA 做校验，不让大模型随意改写原对白

Character V10.1
  └─ 跨镜人物身份统一
  ↓
SourceDramaSnapshot
```

模型职责必须分开：

- **Qwen3.8-27B 是主视觉/剧情理解模型，不负责凭空猜音频内容。**
- **D-ORCA 是 Speaker Attribution 的主要音视频证据来源。**
- **ASR/OCR 继续保留原始文字和时间证据，完整源对白不能被剧本模型改写。**
- **Character V10.1 继续负责跨镜身份归并，不因为减少人工就降低身份合并阈值。**

后续如果增加 FilmOps / ACaM 等摄影专项模型，只作为 `Source Directing Reference` 的增强 Provider，不改变 SourceDramaSnapshot 的正式边界。

## 3. 默认全自动原则

### 3.1 什么不再阻塞

以下内容不再要求用户先确认才能继续：

- 人物身份置信度不高；
- 谁在说话置信度不高；
- ASR 与 OCR 存在轻微差异；
- 场景名称不够确定；
- 动作/表情存在多个合理描述；
- 场景 KEEP / LOCALIZE 存在偏好空间；
- 目标台词有多种自然说法；
- 目标语言时长需要在几种安全镜头策略中选择。

系统必须：

```text
收集证据
→ 自动选择当前最合理结果
→ 保存 provenance / confidence / resolution method
→ 继续下游
```

这些技术信息默认不展示给普通用户；用户发现结果不对时再修改。

### 3.2 什么才是真正阻塞

只有**无法形成可消费数据的技术/结构失败**才阻塞，例如：

- 视频文件损坏或无法解码；
- 需要音频分析但源文件不存在可用音轨；
- 模型 Runtime 启动失败且没有可用 fallback；
- 任务输出结构损坏、无法通过 schema/时间范围校验；
- 必需生成文件损坏；
- H3 输出无法解码或后期输入缺失。

内容“不够确定”不等于技术失败。

### 3.3 用户纠错

人工入口仍然保留，但定位变成：

> **可选纠错，不是流程门禁。**

用户可以修改：

- 人物归属；
- 说话人；
- 原剧剧本；
- 场景/道具；
- 动作/表演；
- 目标国家改编；
- 分镜和最终生成结果。

修改后按 revision/fingerprint 让受影响的下游结果失效并显式重算。

## 4. 完整流程：只记住这 10 步

| 步骤 | 大白话说明 | 正式产物 | 下游用途 |
|---|---|---|---|
| 1. 创建项目 | 导入短剧并选择源语言、目标语言、目标地区 | ProjectSpec、EpisodeSource、剧集顺序 | 决定后续语言和地区策略 |
| 2. 拆分原片 | 建立时间基准并切 Shot | Shot、Reference Clip、ShotRevision | 给理解、生成、字幕、剪辑统一时间锚点 |
| 3. 完整理解原片 | Qwen3.8 + D-ORCA + ASR/OCR 看懂画面、声音和对白 | Shot Facts、Scene Timeline、Dialogue、Speaker Evidence、Directing Facts | 形成原片真实内容底座 |
| 4. 自动统一人物/场景/道具 | Character V10.1 做跨镜人物身份，资产自动归并 | Final Character / Scene / Prop、Speaker Binding | 让不同镜头引用同一个正式对象 |
| 5. 固化原片事实 | 把当前最佳原片事实编译成唯一正式版本 | SourceDramaSnapshot | 后续所有目标版本只读它 |
| 6. 还原与改编剧本 | 先还原 Source Script，再按国家/语言产生 Target Script | Source Screenplay、Target Script | 成为目标分镜的剧情输入 |
| 7. 目标人物/场景/声音 | 设计本地化人物、场景和 Voice | TargetCharacter、TargetScene、VoiceProfile | 给 H3 / TTS 使用 |
| 8. 目标对白与分镜 | 先生成目标 TTS，再按真实时长拆场和生成目标分镜 | TargetDialogue、SpeechAsset、Storyboard、RemakeTimeline | 决定视频真正生成什么、多久 |
| 9. H3 重拍与自动质检 | 按目标分镜生成并自动 QC / 重试 / 选版 | GenerationSegment、Attempt、QC、Selection | 只有 Selection 进入后期 |
| 10. 后期与成片 | 口型、目标音轨、字幕、背景音、拼接 | MP4、SRT、EpisodeOutput | 直接交付；用户可选复查/驳回 |

## 6. Source Script 和 Source Directing Reference 必须分层

### Source Script

用户可读、可编辑：

- Scene Heading；
- 剧情动作；
- 人物关系；
- 完整对白；
- Speaker；
- 必要剧情道具；
- 故事节奏。

剧本不能退化成逐 Shot 技术字段堆砌。

### Source Directing Reference

主要给系统使用：

- 原 Shot 起止时间；
- Reference Clip；
- 景别；
- Camera Angle；
- Camera Motion；
- Composition；
- Blocking；
- Action；
- Expression；
- Gaze；
- Interaction；
- Lighting；
- Prop placement；
- Continuity；
- 剪辑关系。

**目标分镜可以参考这些导演信息，但不能机械 1:1 复制原 Shot。**

目标语言说话时长变化后，可以：

- 延长动作；
- 延长反应镜；
- 拆成更多 Target Shot；
- 合并不必要镜头；
- 安全裁剪空白；
- 调整镜头持续时间。

必须保证剧情意图、动作逻辑和导演风格仍能对应原片。

## 7. 用户界面原则

普通用户只需要看到真正有用的产品结果。

### Project

主要看：

- Episode；
- 原片理解是否完成；
- 原剧剧本；
- 目标国家剧本；
- 目标人物/场景；
- 分镜和生成准备状态。

ASR、OCR、VLM、Embedding、Track ID、confidence、fingerprint 等默认不做顶层页面。

### Review / Correction

保留现有 Review Center 兼容入口，但新产品语义是：

- 用户发现错误时修改；
- 查看高级诊断时展开；
- 不再因为低置信度强制用户清任务清单。

### Output

主要看：

- H3 生成进度；
- 当前选版；
- 最终 MP4；
- 字幕；
- 用户主动驳回/重生成入口。

## 8. 最重要的硬规则

1. **先理解原片，再改编目标版本，再生成。**
2. **SourceDramaSnapshot 是模块 6—10 唯一的原片正式事实入口。**
3. **剧本和导演参考分层保存，两者都不能丢。**
4. **Qwen3.8-27B 负责主视觉/剧情理解；D-ORCA 负责音视频 Speaker Attribution；ASR/OCR 保留源对白证据。**
5. **低置信度内容默认自动决策并继续，不创建强制人工门禁。**
6. **Character V10.1 不因追求全自动而降低“错误合并人物”的安全阈值；证据不足时宁可保持两个临时身份，也不要错误合并。**
7. **人物始终替换；场景按 KEEP / LOCALIZE / AUTO 决定。**
8. **目标对白先 TTS，再用真实语音时长设计 RemakeTimeline。**
9. **Shot 不等于 Target Shot，也不等于 GenerationSegment。**
10. **H3 技术成功不等于可用；只有通过 QC 的 GenerationSelection 进入后期。**
11. **多人镜头做口型前必须有一个机器可消费的目标 Speaker 决定，但不要求人工确认。**
12. **原片 raw audio 禁止直接混入目标成片。**
13. **自动算法在后台执行，不为每个模型单独做普通用户页面。**
14. **GET / 页面打开 / 刷新 / 切页只能读取，不能偷偷启动重推理。**
15. **模型离线、视频损坏、文件不可读属于 Runtime/技术失败，不是假人工内容问题。**
16. **用户修改正式事实后，依赖旧 fingerprint 的下游结果必须 STALE，不得继续冒充 current。**

## 9. 开发任何功能前必须回答

1. 它属于哪一个业务步骤？
2. 输入是什么当前正式数据？
3. 哪个 Provider / 规则自动处理？
4. 自动不确定时如何选择当前最佳答案？
5. 哪些真正的技术/结构失败才阻塞？
6. 输出是什么正式数据？
7. provenance / revision / fingerprint 怎么保存？
8. 用户如果发现错了从哪里修改？
9. 下游具体读取什么？
10. 什么条件下才算真实完成？

如果答不清这些问题，先不要增加页面和代码。
