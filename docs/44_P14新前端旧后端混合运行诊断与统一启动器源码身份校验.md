# P14 新前端 / 旧后端混合运行诊断与统一启动器源码身份校验

> 日期：2026-09-13  
> 状态：P14 本地运行与验收体验整改；补充 `docs/37`、`docs/38`、`docs/43`。  
> 本文只解决本地进程版本一致性，不改变 `TTS = PLANNED / TIMING = PLANNED / P14 PASS = NO`。

## 1. 现象

P14“技术验收就绪检查”页面已经出现，但点击：

```text
运行技术验收检查
```

返回：

```text
Not Found
```

如果仓库当前代码已经包含：

```text
GET /api/v3/projects/{project_id}/p14/acceptance-readiness
```

则这个 `Not Found` 不是技术验收 blocker，也不是正式 Artifact 缺失，而是当前 8000 端口上的 FastAPI 进程没有加载当前 checkout 的路由。

典型状态：

```text
Vite/frontend = 新代码
FastAPI/backend = 旧代码
```

## 2. 根因

旧统一启动器判断 backend 是否可复用时只检查：

```text
GET /api/v3/health -> 2xx
```

因此一个旧版本 backend 即使缺少后来新增的 API，只要 `/health` 正常，也会被错误复用。

“进程健康”和“进程属于当前源码版本”必须分开判断。

## 3. 新的 backend runtime identity

`GET /api/v3/health` 新增：

```text
runtime_fingerprint
```

该值在 backend 进程启动/import 时，对当前：

```text
backend/app/**/*.py
```

按稳定路径顺序做 SHA256。

关键规则：

- fingerprint 在进程启动时冻结；
- `git pull` 改变磁盘源码后，旧进程不会因为读取磁盘而假装变成新版本；
- 新 backend 重新启动后才获得新 fingerprint；
- fingerprint 只代表源码身份，不代表 P14 PASS。

## 4. 统一启动器 guard

正式入口继续是：

```text
Windows: start.cmd
Linux / WSL: ./start.sh
```

两个入口先运行 `scripts/start_studio_guard.py`。

Guard：

1. 计算当前 checkout 的 backend source fingerprint；
2. 读取 8000 `/api/v3/health`；
3. fingerprint 一致才允许后续启动器复用 backend；
4. backend 健康但 fingerprint 缺失或不一致时，视为 stale backend；
5. 只尝试终止命令行明确匹配 `app.main:app` 且监听约定 8000 的旧 Studio backend；
6. 如果 8000 仍被未知进程占用，则 fail closed，不杀未知服务；
7. stale backend 回收完成后再进入原 `start_studio.py`，由它执行 migration 并启动当前代码。

## 5. 前端错误口径

如果用户在更新代码后尚未重启 backend，P14 技术验收面板遇到路由级：

```text
HTTP 404 / Not Found
```

不得只显示裸错误。

产品提示必须明确说明：

```text
当前页面代码已更新，但 8000 后端仍是旧版本。
请退出旧的 Studio/backend 进程并重新运行 start.cmd（或 ./start.sh），然后刷新页面。
```

正式项目不存在等业务 404 仍按原业务错误展示，不应被误判成旧 backend。

## 6. 用户恢复流程

Windows：

```text
git pull
关闭旧 start.cmd / backend 窗口
start.cmd
```

Linux / WSL：

```bash
git pull
# 结束旧 launcher
./start.sh
```

重新启动后，`/api/v3/health` 应带有 `runtime_fingerprint`，再点击 P14 技术验收检查。

## 7. 阶段状态

本整改只保证前后端加载的是同一份 backend 源码。

即使：

```text
runtime fingerprint match
P14 technical_ready = true
```

仍不等于：

```text
P14 PASS
TTS = AVAILABLE
TIMING = AVAILABLE
```

仍需完成 `docs/43` 定义的真实音频、逐句人工听审、正式 TARGET_AUDIO、正式 TIMING_PLAN、无 overflow 和用户明确 P14 PASS。
