# P8 说话人候选绑定与分镜表可读性修正

> 日期：2026-09-09  
> 状态：P8 contract amendment，先设计后实现  
> 基线：`docs/08_P8逐镜精细拉片ProfessionalSkill与数据契约.md`  
> 原因：真实 P8 页面验收发现「对白 / 旁白」只有 delivery + canonical text，没有“谁说的”，无法作为专业逐镜拉片表完成用户审阅。

---

# 1. 问题定义

P8 1.0 的 `SOURCE_SHOT_FACTS.dialogue[]` 只有：

```text
canonical utterance
+ Shot overlap
+ delivery
```

因此页面只能显示：

```text
[对白] 一百二十八
[对白] 神经病你抢钱吧
[对白] 你 什么玩意儿
```

但无法显示：

```text
王桂香 · 对白 · 一百二十八
徐然   · 对白 · 神经病你抢钱吧
王桂香 · 对白 · 你 什么玩意儿
```

这不是 CSS 问题，而是 P8 typed contract 缺少逐句说话人候选绑定。

---

# 2. P8 与 P9 的新边界

P8 允许新增 **speaker candidate hint**，但仍不得进入 P9 最终身份归一。

P8 负责：

```text
CURRENT P6 canonical utterance
+
完整 Episode 的音画现场
+
CURRENT P7 SOURCE_BIBLE character candidates
↓
utterance → P7 character candidate（可空）
```

P8 只能从 CURRENT SOURCE_BIBLE 已存在的 `character_id` 中选择；不能创建新人物、不能写 `SourceSpeaker`、不能做声纹聚类或跨 Episode 最终身份归一。

P9 仍负责：

```text
Speaker / Character / Scene / Prop 最终归一
独立音视频证据
跨 Shot / 跨 Episode identity resolution
正式 SourceVideoSnapshot
```

因此 P8 的说话人字段是 **逐镜拉片中的 provisional candidate binding**，不是 P9 的最终 Speaker Truth。下游在 P9 完成前不得把它当成最终 speaker identity。

---

# 3. 权威边界保持不变

```text
完整 Episode                 = Source Truth
CURRENT P5 SHOT_ANCHORS      = Shot 时间权威
CURRENT P6 canonical Evidence = 对白正文权威
CURRENT P7 SOURCE_BIBLE      = 可选择的人物候选集合与全局语义上下文
```

P8 Provider 仍然：

- 不输出或修改对白正文；
- 不输出 Shot start/end/duration；
- 不创建 character ID；
- 不按单 Shot 独立猜整集故事；
- 直接读取完整 Episode；
- Reference Clip 只用于局部核对。

---

# 4. Professional Skill v1.1

版本升级：

```text
shot-breakdown@1.1.0
p8-shot-breakdown-v2
SOURCE_SHOT_FACTS schema 1.1
source-bible-shot-facts-v2
```

Provider semantic 新增 Episode 级：

```text
EpisodeShotBreakdownSemantic
├─ shots[]
└─ dialogue_speakers[]
   ├─ utterance_number
   └─ speaker_character_id: string | null
```

为什么是 Episode 级而不是 Shot 级：

> 同一条 P6 canonical utterance 可能跨多个 Shot。说话人属于 canonical utterance，不应因切镜而在不同 Shot 中产生不同身份猜测。

`dialogue_speakers` 必须对当前 Episode 的每一条 canonical utterance 恰好输出一次；无法可靠判断时 `speaker_character_id = null`。

---

# 5. SOURCE_SHOT_FACTS schema 1.1

`CanonicalDialogueBinding` 新增：

```text
speaker: BoundSubjectRef | null
```

其中：

```text
BoundSubjectRef
├─ id      ← CURRENT SOURCE_BIBLE character_id
└─ label   ← 服务端从 CURRENT SOURCE_BIBLE 注入 name
```

Provider 只返回 `speaker_character_id`，没有写 label 的权限。服务端负责：

1. 校验 utterance 集合完整且无重复；
2. 校验非空 `speaker_character_id` 属于 CURRENT SOURCE_BIBLE；
3. 把 candidate ID 映射为 `id + label`；
4. 把同一个 canonical utterance 的同一 speaker binding 注入其所有 Shot overlap；
5. 正文继续逐字复制 CURRENT P6。

任何未知 candidate ID、漏 utterance、增 utterance、重复 utterance 都 fail closed。

---

# 6. UI 契约

P8 主界面的对白块必须显示：

```text
说话人候选 + delivery + canonical text
```

示例：

```text
徐然     [对白]
神经病你抢钱吧

王桂香   [画外对白]
你去报警抓我吧
```

如果 P8 无法可靠绑定：

```text
未确认说话人 [对白]
正文……
```

UI 不得仅依据“当前 Shot 里出现了谁”自行猜 speaker，也不得拿 `bindings.characters[0]` 当说话人。

---

# 7. Revision / STALE

这是正式 schema / Professional Skill / Prompt / Source Truth contract 变化。

迁移后：

```text
旧 SOURCE_SHOT_FACTS 继续保留历史
validity = STALE
is_current = false
```

P5 / P6 / P7 不因本次 P8 contract amendment 失效。

必须显式重新运行 P8 才能生成带 speaker candidate 的新 `SOURCE_SHOT_FACTS` revision；GET 不得自动重算。

---

# 8. 验收

自动测试至少覆盖：

- Provider schema 禁止 speaker candidate 之外的 speaker identity 字段；
- speaker candidate 只能引用 CURRENT SOURCE_BIBLE character ID；
- 未知 ID fail closed；
- 每条 canonical utterance 恰好一条 Episode 级 speaker annotation；
- 跨 Shot utterance 在所有 Shot 中得到同一个 speaker；
- `speaker=null` 合法且 UI 显示“未确认说话人”；
- dialogue text 仍逐字等于 P6 canonical；
- P5 时间仍完全不变；
- schema/profile/skill version 变化使旧 P8 STALE；
- GET 仍只读、POST 才执行真实 Provider。

真实短剧最终验收仍必须人工逐镜确认“谁说的 + delivery + 正文 + 声音”后，才允许 `SHOT_BREAKDOWN = AVAILABLE`。

本修正只属于 P8；不得进入 P9。
