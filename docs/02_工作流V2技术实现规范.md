# 工作流 V2 技术实现规范

> 本文是技术层规范。
>
> 业务流程先看：
>
> 1. `docs/00_短剧重做系统开发总纲.md`
> 2. `docs/01_十个模块详细设计.md`
>
> 本文负责约束：**数据边界、状态、版本、任务、接口、人工审核、H3、后期、安全和页面交互。**

---

## 1. 技术目标

Workflow V2 不增加更多用户页面，而是解决当前工作流容易出现的几类结构性问题：

- “任务执行成功”被误认为“业务阶段完成”；
- 页面打开、刷新、任务完成后可能意外启动新任务；
- GET/read 接口产生写入副作用；
- 上游一个人物问题扩散成大量下游人工问题；
- 完整对白跨多个 Shot 后，被错误拆成多条独立业务对白；
- 上游变化后，旧结果仍被当成当前结果使用；
- 模型离线、业务不确定、技术失败、数据过期混成同一种状态；
- Project、Review Center、Output 各自推断状态，出现同一项目显示不同结论。

技术层必须保证：

```text
一个正式源事实入口
一个正式工作流状态入口
显式命令启动重任务
版本变化可追踪
下游过期可判断
人工只处理真正需要判断的根问题
重任务可幂等、可重试、可恢复
```

## 2. 权威数据边界

### 2.1 原片事实唯一入口

```text
ASR / OCR / VLM / Tracking / Character / Scene / Prop / Fusion
                         ↓
                SourceDramaSnapshot
                         ↓
               所有目标版本和生成流程
```

`SourceDramaSnapshot` 是模块 6—10 唯一允许依赖的原片事实接口。

下游不得绕过 Snapshot 直接拼接零散的：

- ASR 临时结果；
- OCR 临时结果；
- Fusion 临时结果；
- Tracking ID；
- LocalSubject；
- 未定稿的人物/场景候选。

### 2.2 原片和目标版本必须分开

```text
Source Character  -> TargetCharacter
Source Scene      -> SceneLocalizationMapping / Target Scene
Source Dialogue   -> TargetDialogue
```

禁止通过“修改源人物记录”的方式实现目标人物。

### 2.3 人物层级不能混用

至少区分：

```text
Detection / Face
Track
Scene-local Person / LocalSubject
Character Candidate / Identity Evidence
Final Character
TargetCharacter
```

`Track`、`Face`、`LocalSubject` 都不是正式人物。

### 2.4 场景对象不能都叫 Scene

至少区分：

- Source Semantic Scene：原片叙事/时间线语义场景；
- Final Scene Asset：可正式引用的源场景资产；
- SceneLocalizationMapping：源场景到 KEEP / LOCALIZE 的目标映射；
- Target Scene Reference：目标场景描述或参考资产。

## 3. 完整对白与 Shot 投影数据契约

### 3.1 核心原则

完整对白是业务对象，Shot 中出现的对白部分只是投影。

```text
SourceDialogueUtterance
      ↓ 1:N
ShotDialogueProjection
```

一条完整对白跨 3 个 Shot：

- 完整文本只保存一次；
- 完整开始/结束时间只保存一次；
- 每个 Shot 保存自己覆盖的那一段时间；
- 所有投影共享同一个 `dialogue_group_id / utterance_id`。

### 3.2 SourceDialogueUtterance 至少需要

- utterance_id；
- episode_id；
- scene_id（如可确定）；
- source_text；
- source_start_us；
- source_end_us；
- speaker_binding / speaker_key；
- source revision；
- provenance；
- fingerprint。

### 3.3 ShotDialogueProjection 至少需要

- projection_id；
- utterance_id / dialogue_group_id；
- shot_id；
- projection_index；
- projection_count；
- shot_local_start_us；
- shot_local_end_us；
- utterance_offset_start_us；
- utterance_offset_end_us；
- continues_from_previous；
- continues_to_next。

### 3.4 TargetDialogue

每个完整 `dialogue_group_id` 只允许一个当前 TargetDialogue revision。

TargetDialogue 继承 Shot 投影关系，但不能复制成“每个 Shot 一条完整目标对白”。

## 4. SourceDramaSnapshot 规范

Snapshot 至少包含可下游消费的：

- Project / Episode 基本范围；
- Scene；
- Shot；
- Reference Clip；
- 源 Shot 时间；
- 完整 SourceDialogueUtterance；
- ShotDialogueProjection；
- Final Character；
- Final Scene；
- Final Prop；
- Shot Asset Binding；
- Dialogue Speaker Binding；
- 动作；
- 表演；
- 构图；
- 运镜；
- OCR / 画面文字；
- 数据来源；
- source revision；
- source fingerprint。

Snapshot 禁止包含目标人物、目标对白、目标音频等 Target-side 数据。

源 ASR、OCR、Shot 时间等原始事实进入后续流程后保持只读；如果需要纠错，应形成新的上游 revision，再重新编译 Snapshot，而不是在目标模块里偷偷改源事实。

## 5. 三维状态模型

任何业务阶段都不能只用一个 `status` 表示所有情况。

### 5.1 数据有效性 Validity

| 状态 | 用户含义 |
|---|---|
| NOT_BUILT | 尚未生成过结果 |
| CURRENT | 当前结果基于最新上游数据 |
| STALE | 有旧结果，但上游已经变化，需要重算 |

### 5.2 业务就绪度 Readiness

| 状态 | 用户含义 |
|---|---|
| READY | 当前结果满足下游要求 |
| BLOCKED_REVIEW | 需要人工决定 |
| BLOCKED_DEPENDENCY | 被上游阻塞 |
| WAITING_RUNTIME | 等待本地模型/Worker/运行环境 |

### 5.3 执行状态 Execution

| 状态 | 用户含义 |
|---|---|
| IDLE | 空闲 |
| QUEUED | 等待执行 |
| PROCESSING | 执行中 |
| SUCCEEDED | 本次任务执行完成 |
| FAILED | 本次任务失败 |
| INTERRUPTED | 任务中断，可从检查点恢复 |

### 5.4 可消费条件

阶段结果只有同时满足：

```text
Validity = CURRENT
Readiness = READY
```

才允许流入下游。

`Execution = SUCCEEDED` 只表示本次程序运行结束，不代表业务数据一定完整、当前或可交付。

例如：

```text
任务成功运行
→ 检测到人物身份冲突
→ Execution = SUCCEEDED
→ Readiness = BLOCKED_REVIEW
→ 不能进入下一阶段
```

## 6. Revision 与 Fingerprint

### 6.1 大白话定义

- revision：业务对象第几版；
- fingerprint：这份结果当时依赖的输入到底是哪一版数据。

### 6.2 上游变化处理

上游 fingerprint 改变时：

1. 保留旧结果作为历史；
2. 将旧结果标记 `STALE` 或 `SUPERSEDED`；
3. 清除 current pointer；
4. 计算影响范围；
5. 页面展示“哪些内容需要重算”；
6. 等用户明确点击后才启动重算。

禁止保存项目设置后自动消耗 GPU 重跑整个流程。

### 6.3 最低失效矩阵

| 上游变化 | 下游至少失效 |
|---|---|
| 替换原视频 | 模块 2—10 |
| 修改 Shot / 原片理解 | 模块 4—10 |
| 修改人物、场景、说话人绑定 | 模块 5—10 |
| SourceDramaSnapshot 更新 | 模块 6—10 |
| 修改目标地区/场景策略 | 模块 6—10 |
| 修改 TargetCharacter / Voice / Target Scene | 模块 7—10 |
| 修改 TargetDialogue / TTS | 模块 8—10 |
| 修改 RemakeTimeline / GenerationSegment | 模块 9—10 |
| 修改 GenerationSelection | 模块 10 |
| 修改 PostProductionSegment | EpisodeOutput |

旧版本不应物理删除，除非明确做历史清理。

## 7. Validator 规范

每个业务模块应有只读 Validator。

Validator 负责返回：

- 输入是否当前；
- 必需输入是否齐全；
- 输出是否存在；
- 输出是否完整；
- blocking errors；
- review candidates；
- runtime requirements；
- metrics；
- warnings；
- next action 建议。

Validator **不得**：

- 创建任务；
- 自动修改业务对象；
- 自动关闭 Review Case；
- 在 GET 时悄悄同步数据；
- 自动启动下一阶段。

---

## 8. Review Case 规范

### 8.1 定义

Review Case 表示：**用户真正需要做的一次业务决定。**

Evidence / Issue 表示支持这个决定的证据，不应和 Case 混为一张“待办行”。

### 8.2 根因去重

如果一个人物身份问题影响：

```text
18 个 Shot
63 个对白投影
```

系统只创建：

```text
1 个 CHARACTER_IDENTITY Case
```

下游对应数据只显示：

```text
被上游人物问题阻塞
```

不能再生成 63 个 LOCALIZATION / SPEAKER 重复 Case。

### 8.3 Case 至少包含

- case_id；
- project_id；
- case_type；
- subject_type / subject_id；
- cause_fingerprint；
- reason；
- severity；
- status：OPEN / RESOLVING / RESOLVED / SUPERSEDED；
- blocking_stages；
- candidate_actions；
- affected_shot_count；
- affected_dialogue_projection_count；
- revision。

建议唯一性：

```text
project + case_type + subject + cause_fingerprint
```

### 8.4 Case 同步时机

只允许在：

1. 阶段任务写入新结果后；
2. 用户保存正式决定后；
3. 上游 revision 改变后。

页面 GET 时不得同步 Review Case。

### 8.5 Case 关闭规则

禁止“通用标记已处理”。

正确顺序：

```text
用户提交正式决定
→ 写正式业务对象
→ Validator 再检查
→ 阻塞条件消失
→ Case = RESOLVED
```

### 8.6 基础 Case 类型

当前至少保留：

- SHOT_BOUNDARY；
- CHARACTER_IDENTITY；
- ASSET_BINDING；
- SPEAKER；
- TARGET_CHARACTER；
- SCENE_LOCALIZATION；
- LOCALIZATION；
- DIALOGUE_TIMING；
- H3_QC；
- LIP_SYNC_QC。

H3/TTS/Qwen/LatentSync/Audio Separator 离线不是人工内容问题，不创建假的 Review Case。

Project、Review Center、Output 不得各自拼状态。

```text
generated_at
overall_status
next_action
can_continue
active_command
review_summary
runtime_summary
episodes[]
stages[]
```

每个 stage 至少包含：

```text
stage_key

readiness
execution
consumable
reason_code
reason
current_input_fingerprint

metrics
open_review_cases
```

## 10. API 读写边界

### 10.1 GET 必须纯读取

推荐：

```text
GET /api/projects/{project_id}/flow-state
GET /api/projects/{project_id}/review-cases
GET /api/projects/{project_id}/runtime-status
GET /api/projects/{project_id}/outputs
```

GET 必须满足：

- 不写业务数据；
- 不创建 Task；
- 不启动模型；
- 不关闭 Review Case；
- 不隐式生成缺失数据；
- STALE 以结构化业务状态返回，不用异常状态码假装技术错误。

### 10.2 重任务必须显式命令

可以升级为：

```text
POST /api/projects/{project_id}/commands/prepare-remake
POST /api/projects/{project_id}/commands/h3-generate-ready
POST /api/projects/{project_id}/commands/postproduction
```

也可以兼容现有 `/tasks/...` URL，但语义必须相同：**只有明确用户动作才能创建。**

每个命令至少携带：

- Idempotency-Key；
- expected workflow revision；
- input fingerprint；
- Episode / 处理范围；
- action source。

服务端必须做幂等，不得只靠前端按钮 disabled 防止重复任务。

## 11. Task Receipt 与后台任务

每个重任务应持久化：

- task_id；
- task_type；
- input fingerprint；
- execution status；
- checkpoint；
- current / total（能准确计算时）；
- heartbeat；
- retry_count / max_retries；
- cancellable；
- target_surface；
- last_error；
- started_at；
- updated_at；
- finished_at；
- 时间字段带时区。

### 11.1 任务规则

- 页面 mount 不创建任务；
- refresh 不创建任务；
- route change 不创建任务；
- task finished 不自动创建下一项重任务；
- 已成功且 fingerprint 当前的检查点要复用；
- 同一个输入和命令要有幂等保护；
- 中断后尽量从 checkpoint 恢复；
- 模型临时失败有限自动重试；
- 用户需要重新跑时必须显式点击。

### 11.2 运行环境状态

统一使用：

```text
Readiness = WAITING_RUNTIME
reason_code = MODEL_OFFLINE / TTS_OFFLINE / H3_OFFLINE / LIPSYNC_OFFLINE / ...
```

旧 `WAITING_MODEL` 可以兼容映射，不要再把基础设施离线变成人工内容问题。

## 12. 前端交互硬规则

| 用户事件 | 允许 | 禁止 |
|---|---|---|
| 打开 Project/Review/Output | GET Snapshot | POST、重算、关闭 Case |
| 切换页面 | 路由 + GET | 启动任务 |
| 点击刷新 | GET 最新状态 | 写业务数据 |
| 创建任务 | POST 显式命令 | 自动跳页后再创建第二次 |
| 任务完成 | 刷新 Snapshot、通知 | 自动开始下一重任务 |
| 保存人工决定 | 写正式业务对象 | 只关闭提醒 |
| 最后一项人工确认完成 | 显示可继续 | 自动跑 GPU |
| 点击“验证并继续” | POST continuation | 重做已通过上游 |
| Runtime 恢复 | 显示“可以重试” | 自动重跑 |
| 上游变化 | 下游 STALE | 用旧结果继续 |
| 浏览器重新打开 | 恢复当前 Snapshot | 再创建 AUTO task |

### 12.1 Loading

- 初次加载使用 skeleton；
- 后续刷新保留最近成功 Snapshot；
- 只让用户刚点击的按钮进入 pending；
- 不要整页闪空。

### 12.2 GET 失败

继续显示最近一次成功状态，并提示：

```text
状态刷新失败，当前展示最近一次结果。
[重新刷新]
```

不能因为 GET 失败把阶段改成“等待生成”。

### 12.3 并发编辑

写操作携带 expected revision。

如果用户审核期间上游数据变化：

- 保存失败并返回 revision conflict；
- 提示证据已更新，需要重新查看；
- 保留前端尚未提交的编辑内容；
- 禁止覆盖新版本数据。

## 13. 页面职责

### 13.1 Project

负责模块 1—8 的业务准备。

顶层建议只保留：

- 当前下一步；
- 项目与本土化规则；
- Episode 管理；
- 原片理解摘要；
- 目标人物与场景摘要；
- 对白与生成准备摘要；
- 高级诊断（默认折叠）。

主页面不要直接展示 ASR、OCR、VLM、LocalSubject、Embedding 等内部技术名。

### 13.2 Review Center

只显示当前真正需要用户决定的根 Case。

推荐工作区：

```text
左：Case 队列
中：证据 / 前后镜头 / 影响范围
右：正式业务决定编辑器
```

“已处理历史”和技术 ID 默认折叠。

### 13.3 Output

负责模块 9—10。

优先展示最终 Episode 结果；没有成片时，再展示当前唯一下一步。

H3 Context、Attempt、QC、PostProductionSegment、模型日志属于高级诊断，不做普通用户主流程。

## 14. H3 Provider 边界

业务层不能直接强耦合本地 SGLang/H3 调用。

```text
Remake Business
→ VideoGenerationProvider
→ MiniMaxH3Provider
→ H3RuntimeManager
→ Local SGLang / MiniMax H3
```

统一 Provider 至少负责：

- generate；
- runtime/status；
- cancellation（若支持）；
- 统一异常；
- 统一结果对象。

以后更换或增加生成供应商时，不重写目标版本和时间轴业务层。

---

## 15. GenerationSegment 与 H3 输入

### 15.1 Shot != GenerationSegment

Shot 是原片导演和剪辑单位。

GenerationSegment 是 H3 实际执行单位。

当前 H3 约束：

```text
4..15 秒
<4 秒目标内容：H3 至少生成 4 秒，再精确裁切
>15 秒目标内容：拆成多个 GenerationSegment
```

### 15.2 H3 Context 必须可复现

每次生成至少记录：

- generation_segment_id；
- source Reference Clip / visual-only derivative；
- TargetCharacter references；
- LOCALIZE 场景参考/描述；
- 目标语音条件；
- 动作；
- 表演；
- 构图/运镜约束；
- 目标时长；
- seed；
- provider/model profile；
- prompt / correction prompt；
- input fingerprint。

Ref2VA 使用源 Reference Video 时必须去掉源语言音轨，目标 TTS 作为独立音频条件。

## 16. H3 Attempt、QC、Retry、Selection

必须保持：

```text
GenerationSegment
  ├─ GenerationAttempt 1
  ├─ GenerationAttempt 2
  └─ GenerationAttempt 3
        ↓
GenerationQualityCheck
        ↓
GenerationSelection
```

### 16.1 GenerationAttempt

不可变执行历史。

`SUCCEEDED` 只说明 Provider 返回了技术文件，不代表业务可用。

### 16.2 结构硬门禁

至少：

- ffprobe；
- 完整 ffmpeg decode；
- 目标时长容差；
- 文件可读取。

结构失败不能被人工“忽略后通过”。

### 16.3 语义 QC

使用 Qwen3-VL 等检查：

- 视觉完整性；
- 是否泄漏源演员；
- 目标人物身份；
- 场景；
- 动作；
- 表演；
- 构图/运镜；
- 与前后 Selected Output 的连续性。

### 16.4 自动重试

安全情况下：

- 更换 seed；
- 把具体失败原因写入 correction prompt；
- 默认有限次数，不允许无限循环。

重复或存在歧义的内容失败才进入 H3_QC Review Case。

### 16.5 GenerationSelection

这是一个 GenerationSegment 当前可用版本的正式指针。

后期只能读取 `GenerationSelection / Selected Output`。

连续性参考也使用“前一个 Selected Output”，不能随便使用最近一次 SUCCEEDED Attempt。

---

## 17. 目标对白、TTS 与时间轴

正确顺序固定为：

```text
完整源对白
→ 翻译
→ 本土化
→ 最终目标台词
→ Target Speaker / Voice
→ TTS
→ 读取真实语音时长
→ RemakeTimeline
→ GenerationSegment
```

禁止：

```text
先按文字猜一个时长
→ 先排时间轴
→ 最后 TTS
```

也禁止全局把语音不自然加速或把整段视频统一慢放来解决目标语言时长差异。

跨 GenerationSegment 对白必须保存正确 audio offset，后一个 Segment 不能从句首重新播放。

---

## 18. PostProduction 安全规范

### 18.1 唯一视频输入

```text
GenerationSelection
→ PostProductionSegment
→ EpisodeOutput
```

### 18.2 Lip Sync

```text
画外对白
→ 保留目标音频，跳过口型

单一可见目标说话人
→ LatentSync full segment

多张可见人脸
→ 先做目标身份定位
→ 再对目标人物 ROI 做 LatentSync
```

多人情况下不能让口型模型自己任意挑一张脸。

身份不确定进入 `LIP_SYNC_QC`；模型离线进入 `WAITING_RUNTIME`。

### 18.3 原音频安全

硬规则：

```text
raw source audio 永远不能直接混入目标成片
```

安全背景复用流程：

```text
源 Shot 音频
→ 独立 Worker 分离 Instrumental / 非对白背景
→ 根据 SourceDramaSnapshot 的源对白窗口再次硬抑制
→ 对应映射到目标时间
→ 时长适配
→ 保守背景增益
→ 目标对白期间 duck
→ limiter
→ 最终混音
```

背景音 Worker 不可用或处理失败：

```text
TARGET_DIALOGUE_ONLY_FALLBACK
```

已有目标对白-only输出仍可继续组装，不创建人工 Review Case。

### 18.4 字幕

- UTF-8；
- 使用目标 RemakeTimeline；
- 一条完整对白跨多个 GenerationSegment 时只输出一条业务字幕，不能重复句首。

## 19. EpisodeOutput

EpisodeOutput 必须：

- 只组装当前有效且成功的 PostProductionSegment；
- 按目标 RemakeTimeline 排序；
- 标准化分段媒体后再 concat；
- 输出 MP4；
- 输出 UTF-8 SRT；
- 执行 ffprobe；
- 完整解码检查；
- 音轨检查；
- 时长检查；
- 保存 checksum；
- 保存不可变版本号；
- 保存人工验收记录。

机器完成后最高只能到：

```text
READY_FOR_MANUAL_ACCEPTANCE
```

最终“交付通过”必须由用户真实观看和试听后确认。

驳回必须路由到真正的责任模块：

| 问题 | 返回 |
|---|---|
| 台词内容 | 模块 7 |
| 语速/停顿/节奏 | 模块 8 |
| 人物/场景/动作/镜头 | 模块 9 |
| 口型/音轨/字幕 | 模块 10 后期 |

## 21. 技术验收最低标准

- [ ] 打开/刷新/切换页面没有隐式 POST；
- [ ] 一次用户点击至多创建一个相同重任务；
- [ ] task finished / 组件重挂载不会创建下一轮任务；
- [ ] GET 不产生业务写入；
- [ ] 完整对白和 Shot 投影保持 1:N 契约；
- [ ] 一个上游人物根问题不会扩散成大量下游人工任务；
- [ ] LocalSubject / Track 不被直接当 Final Character；
- [ ] Character V10.1 身份门槛不因减少 Review 而降低；
- [ ] 0 个 Review Case 不自动等于“可以生成成片”；
- [ ] STALE 数据不计入当前完成率；
- [ ] Runtime 离线不创建假人工内容问题；
- [ ] Header / Project / Review / Output 消费同一 Workflow revision；
- [ ] TargetDialogue 使用完整 dialogue group，而不是 Shot 复制行；
- [ ] TTS 真实时长驱动 RemakeTimeline；
- [ ] Shot 与 GenerationSegment 分离；
- [ ] 只有 GenerationSelection 进入后期；
- [ ] H3 硬解码失败不能人工绕过；
- [ ] 多脸口型先确认目标身份；
- [ ] 原片 raw audio 不直接进入目标成片；
- [ ] 背景音失败可以安全降级且不阻塞 Episode；
- [ ] Task 中断可从检查点继续；
- [ ] 最终真实跑通 H3 → QC → Selection → PostProduction → EpisodeOutput；
- [ ] 用户完成真实观看、试听和最终验收。
