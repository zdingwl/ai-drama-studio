# 当前最重要的架构校正

2026-09-08 根据 Seko 3.0 可复核产品实测，对视频类项目做了编排校正。

外部可观察的 Seko 产品行为是：

```text
完整短剧视频
+
用户创作意图
↓
Agent
↓
多模态分析
↓
素材基线 / 整体分析 / 时间化剧本 / 角色 / 场景 / 道具

```

该实测只证明**产品层行为**，不证明 Seko 内部具体是否使用 Shot Detection、ASR、OCR 或其调用顺序。详细证据等级与边界见：

```text
docs/03_Seko3.0_Skill架构逆向分析.md
```

V3 据此正式区分：

```text

!=

```

以后不再把“P5 镜头边界 → P6 ASR/OCR → P7 整集理解”直接做成用户必须依次操作的页面阶段。

# 视频 Source Truth 与内部编排

完整 Episode 始终是权威原片：

```text
SOURCE_VIDEO / 完整 Episode
= Source Truth
```

当前正式内部方向：

```text
完整 Episode
        │
        ↓
Media Preflight
        │
        ├────────────────┬────────────────┐
        ↓                ↓                ↓
Shot Anchors         ASR Evidence      OCR Evidence
        │                │                │
        └────────────┬───┴────────────────┘
                     ↓
              Source Evidence
                     +
               完整 Episode
                     ↓
          整集多模态原片理解
                     ↓
             Source Episode Bible
                     ↓
           Story / Rhythm Skeleton
                     ↓
      带全局知识 + Shot Anchors 做逐镜精细拉片
```

硬规则已经写入 Root Skill manifests：

- `SHOT_BOUNDARY` 直接读取 `SOURCE_VIDEO`；
- `SOURCE_DIALOGUE_EVIDENCE` 也直接读取 `SOURCE_VIDEO`；
- P6 对白证据不再依赖 `SHOT_ANCHORS` 才能开始；
- Shot Anchors 与连续 ASR 在资源允许时可以并行；
- ASR 不按每个 Reference Clip 分开识别；
- 整集理解不依赖“先把视频切碎”；
- 逐镜精细拉片仍必须在整集知识建立后再结合 Shot Anchors 执行。

当前已新增自动测试锁定上述依赖关系。

# Source Evidence 与 Source Understanding 分离

Seko 实测中出现了原片某句台词触发平台文本审核、导致文本节点创建失败的情况。这进一步说明语义模型输出不能等同原始素材事实。

V3 正式边界：

```text
Source Evidence
= ASR / OCR / subtitle reconciliation
= 原片实际说了什么、写了什么
= canonical + provenance

Source Understanding
= 剧情、人物、关系、场景、事件、节奏等语义理解
```

多模态模型 / Agent 无权静默覆盖 canonical Source Evidence。
