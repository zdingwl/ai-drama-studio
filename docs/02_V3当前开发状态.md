# 3. 当前 Source → Target 正式链路

完整 Episode 仍然是 Source Truth。当前正式链路：

```text
SOURCE_VIDEO / 完整 Episode
        │
        ↓
P5 Shot Anchors
        +
P6 ASR / OCR Canonical Evidence
        +
P7 Episode Understanding / Source Bible / Story / Rhythm
        +
P8 Source Shot Facts
        +
P9 Character / Speaker / Scene / Prop Resolution
        │
        ↓
P10 CURRENT SOURCE_VIDEO_SNAPSHOT
        │
        ↓
P11 ADAPTATION_PLAN + TARGET_BIBLE
        │
        ├──────────────────────────────┐
        ↓                              ↓
P12 TARGET_SCRIPT                P13 TARGET_ASSETS
（AVAILABLE）                   （PLANNED / 真实复验中）
```

硬边界继续保持：

- P5~P10 Source Facts 不允许被 Target / Production 阶段反向改写；
- P10 `SOURCE_VIDEO_SNAPSHOT` 是后续 Target 世界读取 Source Facts 的唯一当前版本锚点；
- P11 `TARGET_BIBLE` 定义正式 Target Character / Scene / Prop identity 与本土化语义；
- P12 只负责到 Final Target Dialogue，不负责资产、TTS、Timing、Storyboard 或 Generation；
- P13 唯一硬输入只有 CURRENT `TARGET_BIBLE`，只负责 Target Character / Scene / Prop 的视觉身份实现；
- `TARGET_SCRIPT` 不是 P13 输入，Target Script revision 变化不得无依据地使 TARGET_ASSETS STALE；
- P13 不负责 Target Voice、TTS、Timing、Storyboard、Generation、QC、Lip Sync 或 Post。

# 6. 本轮真实 P13 验收结果

真实 REPLICA 项目已经完成：

```text
CURRENT TARGET_BIBLE
→ real ProviderJob
→ NEEDS_REVIEW candidate
→ USER EXPLICIT ACCEPT
→ CURRENT TARGET_ASSETS
```

说明以下路径已经真实运行：

- P13 真实 Provider 调用；
- candidate staging；
- 人工 review gate；
- formal TARGET_ASSETS publication；
- Character / Scene / Prop 实际内容展示。

但人工核对旧 `replica-target-visual-identity-v1` formal revision 后发现三个阻断问题：

### 6.1 全局叙事 continuity 被注入 asset packet

旧服务端 `_compose()` 在 Provider 中文语言门禁之后，把：

```text
TARGET_BIBLE.continuity_rules
entity.continuity_rules
```

合并进每个人物 / 场景 / 道具的 `continuity_constraints`。

真实页面因此出现大量重复英文：Story Beat、shot order、beat timing、cliffhanger、人物关系、剧情价格与转场规则等。这些规则属于 Target Bible / preservation locks，不是单个视觉 asset 的 continuity，也绕过了 P13 中文审核门禁。

v2 已改为：

```text
Target Bible = 上游 semantic truth / lineage
Target*Asset.continuity_constraints = asset-local visual continuity only
```

服务端不得再机械复制全局叙事锁。

### 6.2 Character wardrobe 越过 P13 baseline

真实结果出现“楼道穿 A / 新房闪回穿 B / 卧室早餐穿 C”的逐场景换装表。

P13 当前规则：

```text
wardrobe_baseline = 基础服装身份 / 风格边界
```

除非 CURRENT TARGET_BIBLE 已明确给出已确认 variation，否则不得在 P13 自行创建逐 Scene / Shot wardrobe plan。

### 6.3 Scene time-of-day 发明剧情时间

真实结果把连续剧情解释为“深夜 → 次日上午”。P13 唯一硬输入 Target Bible 并未给出这一故事时间变化，因此属于无依据补全。

当前规则：

```text
time_of_day_baseline = 场景视觉基线
!= 剧情时间轴
```

若 Target Bible 没明确时段，具体昼夜 / 临时灯光变化留给未来 Storyboard / Shot context，不得在 P13 猜。

因此本轮结论是：

```text
real Provider path = PASS（路径真实可执行）
real content quality = FAIL / BLOCKED
P13 PASS = NO
```

# 7. v3 / visual-identity-v2 整改

整改包含：

1. `P13_PROMPT_VERSION` 升级为 `p13-replica-target-assets-v3`；
2. `P13_TARGET_ASSET_CONTRACT` 升级为 `replica-target-visual-identity-v2`；
3. Professional Skill 升级为 `replica-target-assets@1.1.0`；
4. Provider prompt 明确 asset-local visual scope；
5. Provider 禁止复制 Story Beat / shot order / dialogue / rhythm / cliffhanger 等叙事 preservation locks；
6. Provider 禁止自行生成逐 Scene / Shot wardrobe schedule；
7. Provider 禁止从 Scene 顺序 / 闪回 / 情绪推断剧情时间跳变；
8. 服务端 `_compose()` 不再把 Target Bible global/entity continuity rules 注入 review-facing asset continuity；
9. stable asset ID binding contract 不变；
10. migration 只把 pre-v3 `NEEDS_REVIEW` candidate → `SUPERSEDED`；
11. 已 ACCEPTED 正式资产不由 migration 静默改写，历史仍可追溯；
12. 前端识别旧 `target_asset_contract` 并提示用户显式“重新生成候选”。

旧 formal revision 即使仍是 CURRENT，也只是历史上一次显式接受的业务结果；它已被真实人工验收判定不满足最终 P13 质量合同，不能据此宣布 `P13 PASS`。
