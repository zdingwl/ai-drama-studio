# 当前最重要的产品架构

完整 Episode 永远是 Source Truth：

```text
SOURCE_VIDEO / 完整 Episode
= Source Truth
```

视频类项目内部编排：

```text
完整 Episode
        │
        ↓
Media Preflight
        │
        ├────────────────┬────────────────┐
        ↓                ↓                ↓
Shot Anchors         ASR Evidence      OCR Evidence
        │                │                │
        └────────────┬───┴────────────────┘
                     ↓
              Source Evidence
                     +
               完整 Episode
                     ↓
          整集多模态原片理解 / P7
                     ↓
      SOURCE_BIBLE《源作概览分析》
                     ↓
           Story / Rhythm Skeleton
                     ↓
      带全局知识 + Shot Anchors 做逐镜精细拉片 / P8
```

硬规则：

- Shot Boundary 读取完整 `SOURCE_VIDEO`；
- P6 ASR 读取完整连续音轨，不能按 Shot / Reference Clip 分开识别；
- P6 OCR 扫描完整视频时间轴，Shot Anchors 只能辅助抽帧 / 去重；
- P6 Source Evidence 与 P7 Source Understanding 严格分离；
- P7 必须读取完整 Episode，不允许把每个 Shot 独立丢给模型猜剧情后再拼接；
- P7 对白 / OCR 的文字事实必须引用 CURRENT P6 Evidence；模型不得覆盖 canonical Source Evidence；
- P8 必须在 CURRENT SOURCE_BIBLE 已建立并人工验收后再开始。

工程实现切片 P5/P6/P7/P8 不等于普通用户必须逐项点击的业务流程。普通用户产品流程仍应表现为：

```text
上传完整原片
→ 原片理解
→ 可读、可编辑的《源作概览分析》
→ 后续目标版本创作
```

# SOURCE_BIBLE 的正式语义

`ArtifactType.SOURCE_BIBLE` 正式定义为：

> **《源作概览分析》：整集原片理解生成的用户可读、可编辑、可版本化 Source Understanding Artifact。**

第一版正式内容包括：

```text
SOURCE_BIBLE
├─ 素材基线
├─ 整体分析
├─ 时间化原作剧情
├─ 人物与人物关系
├─ 场景
├─ 关键道具
├─ Story / 关键事件
├─ 情绪时间线
├─ Story Skeleton
├─ Rhythm Skeleton
└─ Source Evidence provenance refs
```

它不等于：

```text
ASR raw output
OCR raw output
SHOT_ANCHORS
Provider 原始 response
聊天消息
```

Seko 产品实测观察到完整短剧经多模态分析后可形成画布文本节点《源作概览分析》，包含素材基线、整体分析、完整时间化原剧本、角色关系、场景和关键道具。V3 吸收该产品体验，但数据库正式真相仍由 Artifact Graph / SourceBibleRevision 管理。

# P7 已实现的工程范围

## 1. 输入门禁

P7 只对：

```text
REPLICA
REDRAW
```

开放，不对 `TRANSLATION` 执行 SOURCE_BIBLE。

创建 P7 Task 前必须满足：

```text
CURRENT SOURCE_VIDEO
+
CURRENT SOURCE_DIALOGUE / Source Evidence
+
Source Evidence complete = true
+
Evidence Episode 集合与完整 Source Truth 一致
+
可选 CURRENT SHOT_ANCHORS（必须与当前 SOURCE_VIDEO 对应）
```

Shot Anchors 缺失不阻塞 P7。

每个 Episode 调用 Provider 时传入 immutable `source.mp4` 的完整路径，不传 Shot Reference Clip。

## 2. Professional Skill / Grounding v2

正式 Skill：

```text
skills/professional/episode-understanding/SKILL.md
skills/professional/episode-understanding/manifest.json
source-video-understanding@1.1.0
```

当前 Grounding Contract：

```text
grounded-source-truth-v2
```

正式三档：

```text
FACT
INFERENCE
UNKNOWN
```

发布语义：

```text
FACT / INFERENCE
→ 必须有 CURRENT Evidence ID 或完整 Episode video_time_ranges

UNKNOWN
→ 不得携带 Evidence / video_time_ranges
→ 只能对应省略 / null 的未确认 claim
→ 不能与确定性事实正文同时发布
```

正式 Source Facts 当前强制 FACT-grounded：

- story background；
- character identity；
- relationship；
- scene；
- story event；
- prop appearance；
- 每一条 world rule。

道具 `story_function` 可以是有支持的 INFERENCE；无法确认时必须 `null + UNKNOWN`。

`world_rules` 只允许本作品内部已确认规则，不允许社会泛化、法律结论、道德训诫；没有内部规则时必须允许空数组。

## 3. SOURCE_BIBLE schema / server validation

当前 SOURCE_BIBLE schema 为 `1.1`，强类型 Pydantic schema 覆盖：

- Material Baseline；
- Overall Analysis；
- timed story segments；
- characters / states；
- relationships；
- scenes；
- props；
- story events；
- emotion beats；
- Story Skeleton / Story Beats；
- Rhythm Skeleton / Rhythm Phases；
- claim grounding / provenance。

服务端负责固定媒体事实（Episode ID / order、原始文件名、duration、宽高、aspect ratio、fps、codec、has_audio），模型不能改写这些 Source Truth。

模型输出必须先通过 Provider grounding validation，再在 Service 发布边界重复验证：

- 所有时间范围必须在 Episode 内；
- Evidence ID 必须真实属于当前 Episode 的 CURRENT Evidence；
- FACT / INFERENCE 必须有依据；
- UNKNOWN 不能承载确定性 Source Fact；
- world rules 必须 1:1 FACT-grounded；
- prop appearance / story function 的事实与推断边界合法；
- character / relationship 引用必须一致；
- 非法结构 / 幻觉 Evidence ID fail closed，不发布 SOURCE_BIBLE。

## 4. revision / fingerprint / provenance

P7 Task fingerprint 当前包含：

```text
P7 prompt/profile/schema version
Professional Skill id/version
Grounding Contract
SOURCE_VIDEO artifact id + fingerprint
SOURCE_DIALOGUE artifact id + fingerprint
可选 SHOT_ANCHORS id + fingerprint
Episode immutable asset SHA / duration
SourceEvidenceSet id + fingerprint
可选 ShotBoundarySet id
实际 Provider profile / model selection
```

因此切换模型、Professional Skill、Grounding Contract 或有效 Provider profile 不会复用旧业务 Task。

新的 SOURCE_BIBLE provenance 直接记录：

- exact upstream Artifact ID / fingerprint；
- Episode Evidence Set ID / fingerprint；
- ProviderJob ID；
- provider / model；
- remote response/job ID（存在时）；
- prompt / schema version；
- `professional_skill_id`；
- `professional_skill_version`；
- `grounding_contract`；
- generated task ID。

API Key 不写入 Project、DB、Artifact、ProviderJob、provenance 或日志。

## 5. Artifact Graph / 编辑行为

模型成功并通过校验后发布：

```text
SOURCE_VIDEO ─DERIVED_FROM→ SOURCE_BIBLE
SOURCE_DIALOGUE ─DERIVED_FROM→ SOURCE_BIBLE
SHOT_ANCHORS ─USES→ SOURCE_BIBLE       （可选）
SOURCE_BIBLE ─CONTAINS→ STORY_SKELETON
SOURCE_BIBLE ─CONTAINS→ RHYTHM_SKELETON
```

完整 SOURCE_BIBLE 正文存储在 `SourceBibleRevision`，Artifact metadata 只保存摘要 / 指针。

用户编辑 CURRENT SOURCE_BIBLE 时：

```text
SOURCE_BIBLE rev1
↓ 编辑
SOURCE_BIBLE rev2
```

- rev1 保留并变 STALE；
- rev2 成为 CURRENT；
- 旧 Story / Rhythm 跟随 STALE；
- 新 Story / Rhythm 从 rev2 重新物化；
- canonical P6 dialogue / OCR 不发生写入或改写；
- `SUPERSEDES` 关系保留 revision 链。

# P7 Provider 调用契约

## Doubao Seed 2.1 Pro

```text
完整 Episode
→ Volcengine Ark Files API
→ 等待文件可用
→ Responses API input_video + p7-source-bible-v2 / CURRENT Evidence
→ JSON output
→ Pydantic + grounding v2
→ Service publication 再校验
→ SOURCE_BIBLE
→ best-effort 删除远端临时文件
```

ProviderJob 必须在远端调用前 commit。

## 本地 Qwen

```text
完整 Episode 本地 file:// URI
+
P7 prompt / CURRENT Evidence
→ vLLM OpenAI-compatible /chat/completions
→ video_url
→ JSON output
→ Pydantic + grounding v2
→ Service publication 再校验
→ SOURCE_BIBLE
```

两个本地模型默认使用独立 vLLM endpoint（8000 / 8001）；也允许指向同一个多模型网关。

本地 vLLM 必须能够访问 backend 的完整 Episode Artifact 路径并允许 local media file URL。模型权重、量化、GPU tensor parallel、max-model-len 由部署环境决定，不塞进 FastAPI 进程。

Thinking runtime 若暴露 `<think>...</think>`，服务端只提取最终 JSON，不将 reasoning 文本写入 SOURCE_BIBLE。

# Grounding v1 → v2 的 STALE 迁移

Alembic `0010_p7_grounding_contract_v2` 用于使已经按 v1 生成的理解链失效：

```text
v1 SOURCE_BIBLE       → STALE
其 Story Skeleton      → STALE
其 Rhythm Skeleton     → STALE
P6 Source Evidence     → CURRENT，不修改
```

这样部署 v2 后不会把旧的“UNKNOWN + 确定性正文”结果继续显示为 CURRENT。
