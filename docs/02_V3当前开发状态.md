# SOURCE_BIBLE 的正式产品语义

当前代码已经存在：

```text
ArtifactType.SOURCE_BIBLE
```

本次实测后，正式定义为：

> **SOURCE_BIBLE = 《源作概览分析》：整集原片理解生成的用户可读、可编辑、可版本化 Source Understanding Artifact。**

它至少应表达：

```text
SOURCE_BIBLE
├─ 素材基线
├─ 整体分析
├─ 时间化原剧本 / 剧情时间线
├─ 人物候选与人物关系
├─ 场景
├─ 关键道具
├─ Story / 关键事件
└─ Source Evidence provenance refs
```

它不等于：

```text
ASR raw output
OCR raw output
SHOT_ANCHORS
模型原始 response
聊天消息
```

Replica / Redraw Root Skill 已经把整集理解步骤校正为：

```text
完整 SOURCE_VIDEO
+
SOURCE_DIALOGUE / Source Evidence
↓
《源作概览分析》 / SOURCE_BIBLE
↓
带整集知识 + SHOT_ANCHORS 做逐镜拉片
```

并新增自动测试锁定该依赖契约。

# 合规微调与 Source Evidence 的边界

Seko 实测中的“合规微调”作用于画布文本节点，因此 V3 必须坚持：

```text
SOURCE_DIALOGUE / OCR Evidence
= 原片实际说了什么 / 写了什么
= canonical + provenance

SOURCE_BIBLE / 源作概览分析
= 对原片事实的业务理解与用户可读表达
= 可以修改并产生新 revision
```

禁止：

```text
合规微调 SOURCE_BIBLE
→ 覆盖 canonical SOURCE_DIALOGUE 原文
```

第一版安全策略：

```text
SOURCE_BIBLE rev1
↓ 用户修改 / 合规微调
SOURCE_BIBLE rev2
↓
保留 rev1
↓
依赖旧 SOURCE_BIBLE 的逐镜拉片 / Snapshot / Target 下游 STALE
```

以后可以通过结构化 diff / semantic fingerprint 减少仅措辞变化造成的无意义重算，但在正式实现前优先 fail-safe。

# Canvas 与 Artifact Graph 的关系

Seko 产品实测显示了：

```text
生成业务结果
→ 写入画布节点
→ 用户查看 / 修改
→ Agent 读取节点详情
→ 继续创作
```

V3 吸收该体验，但数据库真相仍是 Artifact Graph：

```text
SOURCE_BIBLE Artifact
= revision / provenance / CURRENT / STALE / 正式业务真相

Canvas Text Node
= SOURCE_BIBLE 的可视化与编辑入口
```

未来 Canvas 节点必须引用正式 Artifact ID / revision，不能让脱离 Artifact Graph 的 Markdown 节点成为唯一真相。

# 视频 Source Truth 与内部编排

完整 Episode 始终是权威原片：

```text
SOURCE_VIDEO / 完整 Episode
= Source Truth
```

当前正式内部方向：

```text
完整 Episode
        │
        ↓
Media Preflight
        │
        ├────────────────┬────────────────┐
        ↓                ↓                ↓
Shot Anchors         ASR Evidence      OCR Evidence
        │                │                │
        └────────────┬───┴────────────────┘
                     ↓
              Source Evidence
                     +
               完整 Episode
                     ↓
          整集多模态原片理解
                     ↓
      SOURCE_BIBLE《源作概览分析》
                     ↓
           Story / Rhythm Skeleton
                     ↓
      带全局知识 + Shot Anchors 做逐镜精细拉片
                     ↓
              SourceVideoSnapshot
```

硬规则：

- `SHOT_BOUNDARY` 直接读取 `SOURCE_VIDEO`；
- `SOURCE_DIALOGUE_EVIDENCE` 也直接读取 `SOURCE_VIDEO`；
- P6 对白证据不依赖 `SHOT_ANCHORS` 才能开始；
- Shot Anchors 与连续 ASR 在资源允许时可以并行；
- ASR 不按每个 Reference Clip 分开识别；
- OCR 可以使用 Shot Anchors 做抽帧 / 去冗余提示，但完整时间轴仍是 Source Truth；
- 整集理解必须读取完整 Episode；
- 先建立 SOURCE_BIBLE 整集知识，再回到 Shot 做逐镜精细拉片；
- 禁止“每个 Shot 各自猜故事 → 最后拼成整集剧情”。
