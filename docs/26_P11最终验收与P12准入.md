# 1. 最终结论

用户已于 2026-09-11 对 P11 Replica Target Bible 明确给出：

```text
P11 PASS
```

因此正式更新能力状态与阶段准入：

```text
LOCALIZATION = AVAILABLE

P11 Replica Target Bible = 最终真实人工验收通过

```

这次状态更新**不等于 P12 已验收**。当前仍必须保持：

```text

```

只有 P12 后续完成工程门禁、真实 Provider、真实项目端到端与人工质量验收，并由用户明确确认 `P12 PASS` 后，才能另行评估把 `TARGET_SCRIPT` 升为 `AVAILABLE`。

# 2. P11 最终契约保持不变

P11 正式基线继续是：

```text
replica-target-bible@1.0.0
p11-replica-target-bible-v1
P11 Target schema 1.0
replica-target-bible-v1
replica-story-rhythm-locks-v1
```

P11 正式输入继续只锚定：

```text
CURRENT SOURCE_VIDEO_SNAPSHOT
```

正式输出继续只允许：

```text
ADAPTATION_PLAN
TARGET_BIBLE
```

P11 PASS 不改变以下边界：

- Source Snapshot 仍是唯一当前 Source 世界版本锚点；
- P11 preservation locks 仍由服务端确定性生成；
- P11 不得反写 P5~P10 Source Facts；
- P11 不得重新识别或改写 P6 canonical dialogue；
- Target Character / Scene / Prop 继续保持独立 Target identity 与 source_*_id lineage；
- P11 不生成正式 TARGET_SCRIPT；
- P11 不生成 Target Storyboard / Target Voice / TTS / Timing / Generation / QC / Selection / Post。

# 3. P12 正式准入范围

下一工程切片正式进入：

```text
P12 Target Script / Localization
```

“正式准入”表示现在可以：

- 提交 P12 Professional Skill、typed schema、revision storage、provider/service、API、Artifact Graph、测试与 UI；
- 解除“P11 尚未 PASS”的 P12 service admission block；
- 在普通 REPLICA 产品流程中由用户显式启动真实 P12 Provider 任务；
- 使用真实项目执行 P12 端到端与人工验收。

但准入不代表能力已经 AVAILABLE。P12 真实人工 PASS 前：

```text
TARGET_SCRIPT = PLANNED
```

Task 技术 succeeded、Provider 返回成功、TARGET_SCRIPT Artifact CURRENT、自动测试通过或 CI 全绿，均不能替代 P12 真实人工验收。

---

# 4. P12 三个硬输入

P12 正式执行必须同时读取且只接受：

```text
CURRENT SOURCE_VIDEO_SNAPSHOT
CURRENT ADAPTATION_PLAN
CURRENT TARGET_BIBLE
```

三者必须满足：

1. 都属于当前 REPLICA 项目；
2. 都是唯一 CURRENT Artifact；
3. ADAPTATION_PLAN 与 TARGET_BIBLE 都绑定当前 SOURCE_VIDEO_SNAPSHOT；
4. target_language / target_region 与当前 Project 配置一致；
5. 任一输入缺失、STALE 或 lineage 不一致都必须 fail closed。

P12 不允许退回散落 P5~P9 Artifact 自行拼“当前 Source 世界”，也不允许丢掉 ADAPTATION_PLAN 只读取 TARGET_BIBLE。

---

# 5. canonical Source Dialogue 是原始对白事实

P12 原始对白只允许读取：

```text
CURRENT SOURCE_VIDEO_SNAPSHOT
  .episodes[*]
  .canonical_dialogue[*]
```

这些字段由 P10 从已验收 P6 canonical Source Dialogue 冻结：

```text
episode_id
utterance_id
utterance_number
start_us
end_us
text
language
```

其中 `text` 是原始 Source Dialogue 正文。P12 Provider 无权：

- 重新 ASR；
- 重新 OCR；
- 重新听写；
- 看口型猜台词；
- 按剧情补台词；
- 静默“纠错”或润色 Source text；
- 修改 Source timing；
- 创建、删除、合并、拆分 canonical utterance。

若 Source Dialogue 需要纠错，必须回到 P6 canonical adjudication / human edit 链路形成新 Source revision，并让 Snapshot 与 Target downstream 正确 STALE。

---

# 6. P12 对白链

正式链路固定为：

```text
Source Dialogue
→ Translation
→ Localization
→ Final Target Dialogue
→ Target Speaker/Voice
→ TTS
→ Actual Speech Duration
→ Timing Plan
```

P12 只负责前三个目标侧文本层：

```text
translation_text
localization_text
final_target_dialogue
```

不得在 P12：

- 创建 Target Voice；
- 生成 TTS；
- 估算或伪造 Actual Speech Duration；
- 为了预计时长硬塞/静默压缩对白；
- 生成 Timing Plan；
- 生成 Target Storyboard；
- 生成视频或进入 QC / Selection / Post。

真实时长只允许由后续 TTS 得到；镜头时间适配只属于后续 Timing Plan。

# 7. P12 正式工程基线

Professional Skill：

```text
target-script-localization@1.0.0
```

运行契约：

```text
P12_SCHEMA_VERSION = 1.0
P12_PROMPT_VERSION = p12-target-script-localization-v1
P12_TARGET_CONTRACT = replica-target-script-localization-v1
P12_SOURCE_DIALOGUE_CONTRACT = p6-canonical-dialogue-frozen-in-p10-v1
```

Root Replica Skill 的 `target_script` step 正式硬输入必须收紧为：

```text
SOURCE_VIDEO_SNAPSHOT
ADAPTATION_PLAN
TARGET_BIBLE
```

正式输出：

```text
TARGET_SCRIPT
```

P12 publication 至少建立：

```text
SOURCE_VIDEO_SNAPSHOT -> TARGET_SCRIPT : DERIVED_FROM
ADAPTATION_PLAN       -> TARGET_SCRIPT : USES
TARGET_BIBLE          -> TARGET_SCRIPT : USES
new TARGET_SCRIPT     -> old TARGET_SCRIPT : SUPERSEDES
```

任一三个硬输入形成新 CURRENT revision 时，旧 TARGET_SCRIPT 必须通过 Artifact Graph 递归 STALE。

# 10. P12 下一步验收

P12 工程提交与 CI 全绿后，下一步只执行 P12 真实验收，至少确认：

1. 真实 REPLICA 项目的三个硬输入均为 CURRENT 且 lineage 一致；
2. P12 只能由显式操作启动，页面刷新无 POST 副作用；
3. ProviderJob 在外部 Provider 请求前持久化；
4. Provider 输出 canonical utterance 1:1 完整覆盖，顺序一致；
5. Source `utterance_id / text / start_us / end_us` 原样保留；
6. `Translation → Localization → Final Target Dialogue` 三层语义可读、可审计；
7. 目标语言自然表达符合 P11 Target Bible / Adaptation Plan；
8. 可证明 Speaker→Character→Target Character 时正确绑定，否则保持空；
9. 不生成 Voice / TTS / Duration / Timing / Storyboard / Generation Artifact；
10. 新 P11 / Source input revision 能正确使旧 TARGET_SCRIPT STALE；
11. TARGET_SCRIPT revision / fingerprint / provenance / Artifact Graph / history 完整；
12. 用户最终人工确认目标对白质量。

只有用户明确给出：

```text
P12 PASS
```

之后，才允许把：

```text
TARGET_SCRIPT = AVAILABLE
```

并评估下一正式工程切片。
