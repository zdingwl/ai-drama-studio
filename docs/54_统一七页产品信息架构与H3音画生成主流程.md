# 统一七页产品信息架构与 H3 音画生成主流程

> 日期：2026-09-13  
> 状态：正式产品信息架构合同。本文优先于旧文档中把 P5～P17 工程阶段直接映射为普通用户页面的描述；不撤销既有 Artifact、Source Truth、lineage、fail-closed 与人工验收合同。

## 1. 核心原则

项目类型只决定“保留什么、修改什么”，不要求用户学习不同的软件。系统内部可以继续增加 Engineering Stage，普通用户一级页面固定为：

```text
项目 → 原作 → 剧本 → 资产 → 分镜 → 生成 → 成片
```

其中“项目”是首页；项目内固定六个制作工作区。不适用的工作区自动隐藏或跳过。普通模式只操作业务结果，P5～P17、Artifact、ProviderJob、revision、fingerprint、schema 等只允许出现在 `?debug=1`。

## 2. 七个一级页面

1. **项目**：新建项目、继续已有项目。创建时只要求项目类型、目标地区、目标语言和必要素材；技术策略进入高级设置。
2. **原作**：视频项目上传完整视频并显式“解析原片”；小说/剧本项目上传文件或粘贴正文。后台技术链不作为用户步骤。
3. **剧本**：统一展示故事、剧集、对白、改编设置。用户编辑最终要拍摄或交付的内容，不编辑中间 Artifact。
4. **资产**：统一管理人物、场景、道具，默认只显示名称、参考、最终形象与状态；优先展示待确认和有问题项目。
5. **分镜**：把最终剧本、最终资产和适用的原作镜头事实编译为目标分镜与生成计划。
6. **生成**：默认按集执行 H3 原生音画联合生成，只把异常镜头交给用户处理。指定声线、独立配音、保留原音属于高级声音策略。
7. **成片**：自动完成镜头组合、声音、字幕、转场与质量检查，用户处理剩余问题后生成和导出最终成片。

## 3. 六种项目流程

```text
REPLICA:             原作 → 剧本 → 资产 → 分镜 → 生成 → 成片
REDRAW:              原作 → 剧本 → 资产 → 分镜 → 生成 → 成片
TRANSLATION:         原作 → 剧本 → 资产 → 分镜 → 生成 → 成片
NOVEL_TO_DRAMA:      原作 → 剧本 → 资产 → 分镜 → 生成 → 成片
SCRIPT_TO_DRAMA:     原作 → 剧本 → 资产 → 分镜 → 生成 → 成片
SCRIPT_LOCALIZATION: 原作 → 剧本
```

剧本本土化完成后可以显式“用这个剧本创建短剧”，创建新的视频制作项目并从资产工作区继续，不复制第二套视频工作流。

## 4. 项目类型差异

- 复刻：保持故事和节奏，允许人物、地区、文化、语言与部分镜头表达本土化。
- 重绘：内容和表演结构尽量不变，重点替换视觉表现。
- 翻译：故事、人物行为、构图与节奏最大程度保持；对白和所有画面内源语言文字必须目标语言化，因此仍走重新生成画面主路径。
- 小说生成短剧：把小说改编为分集短剧后全新设计资产与镜头。
- 剧本生成短剧：从已有剧本进入导演化整理、资产和镜头设计。
- 剧本本土化：默认只交付目标剧本。

## 5. H3 音画联合生成

普通模式默认链路调整为：

```text
Generation Shot Contract
+ 最终对白
+ 表演要求
+ 人物 / 场景 / 道具
+ 可选声线参考
→ H3 音画联合生成
→ 音画联合 QC
→ 人工只处理异常项
→ 正式选片
```

“配音”不再是固定一级阶段。IndexTTS、独立 WAV、Timing 与独立 Lip Sync 保留为高级声音策略或 fallback，不要求所有项目经过。

P16 执行层默认使用 Windows 原生 `ComfyUI + MiniMax-H3` Runtime；Studio 通过 `/prompt → /history/{prompt_id} → /view` 提交官方原生 H3 音画 workflow、等待完成并读取最终 MP4。Linux / 私有 GPU 主机可显式选择 `LOCAL_SGLANG`；MiniMax Cloud 只作为用户/部署环境显式选择的 fallback，本地失败不得自动转付费云端。当前 P13 尚无真实 reference media，因此本地第一版以 FL2VA `t2va` 为默认；Ref2VA 等真实参考图/视频/音频具备后再接入。

普通用户点击生成之前，Studio 必须先以只读方式检查 H3 Runtime readiness。ComfyUI 模式检查 `/system_stats + /object_info`，并验证所需原生 H3 节点以及配置的 FL2VA / Qwen3VL / video VAE / audio VAE 文件均可见；SGLang 模式继续检查 `/health + /v1/models`。Runtime 未启动、warmup、接口不兼容或模型不匹配时，页面直接显示原因并禁用生成按钮；不得用一次真实生成失败来探测服务是否存在。

音画联合 QC 至少检查：对白完整准确、声线稳定、嘴型同步、音频清晰、环境音合理、人物与资产一致、动作和构图正确、源语言文字无残留。

## 6. 自动化与人工边界

- 默认按集生成，不要求逐镜启动。
- 页面首先显示完成、生成中、需要处理的数量。
- “生成”页必须以持久化 Task 的真实 `queued / running / failed / interrupted / succeeded` 状态和 Selection candidate 为准；`POST 202` 只表示命令已接收，禁止据此显示“已生成”或与真实 Task 冲突的成功提示。页面刷新后必须从项目 Task 恢复正在执行的 P16 状态。
- P16 失败且仍可 retry、或 interrupted 且可 resume 时，普通用户按钮必须调用正式 Task retry/resume；通用调度器必须重新派发 P16 runner，不能只把 Task 改回 queued 后无人执行。若显式 retry 时发现正式 Artifact lineage 或 H3 Runtime/profile 已变化（例如 P15 发布了新的 CURRENT Generation Segments，或 `LOCAL_SGLANG → LOCAL_COMFYUI`），不得复活旧 fingerprint Task，而应由该 retry Command 基于当前正式输入创建并调度 replacement P16 Task，同时保留被替代失败 Task id 作为 checkpoint provenance；当前正式输入缺失或 STALE 时仍 fail closed。
- 用户默认只进入异常项。
- GET 保持只读；付费生成仍由显式 Command 启动，并在远端调用前持久化 ProviderJob。
- 自动检查通过不能替代需要用户观看和听审的最终质量判断。
- 本文不自动把 P14～P17 标记 PASS，也不自动升级尚未真实验收的 capability。
