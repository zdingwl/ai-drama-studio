```text

↓
```

# 3. 一键解析内部硬链

一次显式：

```text
POST /api/v3/projects/{project_id}/commands/source-analysis
```

内部必须遵守：

```text
完整 SOURCE_VIDEO / Episode
├─ P5 Shot Anchors
└─ P6 canonical Dialogue / OCR
        ↓
P7 Whole-Episode Understanding + Story / Rhythm
        ↓
P8 Shot Breakdown
        ↓
P9 Character / Speaker / Scene / Prop Resolution
        ↓
P10 deterministic Source Snapshot publication
        ↓
READY
```

硬规则：

- 完整 Episode 永远是 Source Truth；
- P5/P6 直接读取完整 Episode；
- ASR 不按 Shot / Reference Clip 分段识别后拼接；
- P7 必须建立整集上下文；
- P8 不能每 Shot 独立猜整集故事；
- P9 做跨 Shot 全局归一；
- P10 不调用模型，不创建 ProviderJob；
- 已有 CURRENT 子结果必须幂等复用，只补缺失 / STALE；
- 任一子任务失败，顶层任务 fail closed；
- 页面 GET / 刷新不得启动重任务；
- 只有显式“解析原片 / 重新解析原片”可以创建或恢复所需任务。

# 6. 最终真实人工验收步骤

## A. 普通模式入口与只读

打开：

```text

```

不要加 `?debug=1`。

验收：

- [ ] 页面没有独立 P5 / P6 / P7 / P8 / P9 / P10 操作面板；
- [ ] 页面没有 `SourceVideoSnapshot / Frozen Inputs / fingerprint / provenance / ProviderJob` 技术术语；
- [ ] 普通用户只看到原片输入、一次“解析原片”入口和最终业务结果；
- [ ] 连续刷新页面不会自动启动分析任务或付费 Provider。

## B. 一次“解析原片”

当结果不是 READY 时，显式点击一次：

```text
解析原片
```

验收：

- [ ] 只需要一次用户操作；
- [ ] 状态只使用“未解析 / 解析中 / 解析完成 / 有更新需重新解析 / 解析失败”等产品词汇；
- [ ] 进度可以理解，不要求用户逐项操作内部阶段；
- [ ] 已 CURRENT 的内部结果被复用，不为了表现“正在工作”重复调用 Provider；
- [ ] 若发生失败，可以显式重新解析；不会永久卡在“解析中”。

## C. 解析完成后的原片剧本

进入“原片剧本”。

验收：

- [ ] 场次符合真实 Episode 连续 Scene Assignment；
- [ ] Episode 边界不会静默合并场次；
- [ ] 台词正文保持 P6 canonical 原文；
- [ ] 同一 canonical utterance 即使跨 Shot，也只在剧本出现一次；
- [ ] Speaker / Character 对应符合已验收 P9 Source Truth；
- [ ] 动作描述没有被 working draft 覆盖；
- [ ] 用户主观确认剧本可以正确表达原片发生了什么。

## D. 分镜与音画核对

进入“分镜”。

验收：

- [ ] 共 28 Shot；
- [ ] Shot 顺序、start/end/duration 与 P5 CURRENT 保持一致；
- [ ] 缩略图可见；
- [ ] Reference Clip 可播放；
- [ ] visual description / 景别 / 角度 / 运镜 / 构图可读；
- [ ] Shot 下的对白与原片音频、P6 canonical 对齐；
- [ ] 用户主观确认逐镜内容足以作为后续目标版本设计依据。

## E. 人物 / 场景 / 道具结果

进入“人物 / 场景 / 道具”。

验收：

- [ ] Character = 3；
- [ ] Scene = 3；

## G. Working Draft 与 Source 隔离

验收：

- [ ] 页面明确说明这是“分镜编辑草稿”；
- [ ] 原片剧本 / 原片 Source Facts 不改变；
- [ ] 修改后的 Shot 显示“已修改”；

## H. STALE / 恢复链

在 `?debug=1` 对 P9 Speaker 做一次**语义不变的显式 CONFIRM**，生成新的 Source revision，不人为制造错误 Source Truth。

验收：

- [ ] 旧 Snapshot 变 STALE；
- [ ] 基于旧 Snapshot 的 working draft 变 STALE / 归档；
- [ ] 普通模式显示“结果有更新，需要重新解析”；
- [ ] 用户显式点击“重新解析原片”后，只补跑失效链；
- [ ] 新 Snapshot revision 变 CURRENT；
- [ ] 旧 Snapshot revision 永久保留；
- [ ] 旧 draft 不自动套用到新 Source；
- [ ] 在新 Source 第一次编辑时，从当前原片分镜重新开始。
