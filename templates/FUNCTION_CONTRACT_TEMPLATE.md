# Function Contract — <function_name>

> 每个非纯展示、非显而易见的业务函数在开发前必须能回答本模板。
> 只有函数名和一句“单一职责”不够。

## 1. 基础信息

```text
Function ID:
Function Name:
Feature:
Layer: Controller | Service | Repository | Validation | Path | Manifest | Frontend API | Store | UI
File:
Status: PLANNED | IN_PROGRESS | TESTED
```

## 2. 业务作用

用非技术语言说明：

> 这个函数替用户/系统解决什么真实问题？

不得只写“获取项目”“创建项目”这种名称翻译。

## 3. 为什么要独立成函数

说明为什么不能合并进上层或下层函数，以及它隔离了什么职责。
